# 02：场景中的对象与空间关系

本文行数：88行，预期阅读时长：5分钟

**模型不仅决定机器人长什么样，还决定关节如何运动、状态如何解释，以及受力后怎样变化。**

## 开发者理解：把结构、形状和测量点分开

想让一根杆绕固定轴转动，需要一个 body 表示刚体、一个 joint 允许转动、一个 geom 描述杆的形状。想知道杆尖在哪里，可以在杆尖放一个 site。给 site 取名后，程序就有一个明确的任务点可以读取。

body 是携带坐标系和惯性信息的结构单元；它可以包含多个 geom。geom 可以承担外观、碰撞和惯性推算等职责，具体由配置决定。site 是参考点或参考坐标系，可用于传感器等定义，本身不生成碰撞或承载质量。

## 速记

| 内容 | 含义 | 改变后的主要影响 |
| --- | --- | --- |
| URDF 的 link / MJCF 的 body | 刚体及其局部坐标系 | 结构与坐标层级 |
| joint | 刚体之间允许的相对运动 | 自由度、转轴、零位与限位 |
| visual / geom | 显示形状；MJCF geom 也可参与碰撞与惯性推算 | 外观或物理行为，取决于配置 |
| collision / 接触 geom | 碰撞检测使用的几何 | 能否穿过障碍、在哪里接触 |
| inertial | 质量、质心和惯量 | 重力、加速和转动响应 |
| 工具坐标系 / site | 用来读取或定义任务位置的参考系 | 末端目标与误差的含义 |

URDF 通过 joint 自己的 parent / child 关系来连接 link；而 MJCF 通过嵌套 body 表达层级，joint 是放在放在自己的运动 body 内的。没有 joint 的子 body 可以固定在父 body 上。URDF 本身不是 MuJoCo 原生支持的格式，虽然能够导入 MuJoCo，但“能导入机械臂模型”和“已经配置好完整仿真”是两件事，MuJoCo 的执行器、传感器、接触参数等通常还需要另外配置。

## 父子结构怎样决定空间关系

两关节机械臂的结构可读为：

```text
world
└── upper_arm：关节原点在 (0,0,0.3) m，shoulder 绕 +z
    ├── 上臂 geom：从局部原点延伸到 (0.4,0,0) m
    └── forearm：原点在上臂局部 (0.4,0,0) m，elbow 绕 +z
        ├── 前臂 geom：从局部原点延伸到 (0.3,0,0) m
        └── tip site：前臂局部 (0.3,0,0) m
```

肩关节转动时，上臂、前臂和 tip 一起随之转动；肘关节转动时，只改变前臂相对上臂的姿态。`forearm pos="0.4 0 0"` 表示相对父 body 的偏移，不是固定在世界坐标 x=0.4 m。

本模型零位时，tip 世界坐标为 `(0.7,0,0.3) m`。关节为 `[0.5,-0.8] rad` 时，tip 约为 `(0.637634,0.103114,0.3) m`；坐标已经把两级转动与偏移合在一起，不能直接把某个 body 的 `pos` 当作结果。该值经解析 FK 与 MuJoCo 核对，见[综合例子](../12_arm_walkthrough/README.md)。

## 关节允许哪种运动

| 类型 | 允许的相对运动 | 常见用途 |
| --- | --- | --- |
| hinge | 绕指定局部轴转动，1 个自由度 | 机械臂转动关节 |
| slide | 沿指定局部轴平移，1 个自由度 | 滑台、夹爪手指 |
| ball | 三维转动，3 个自由度 | 球关节 |
| free | 三维平移与转动，6 个自由度 | 可拿起的物体、浮动基座 |

joint 的 `pos` 指定轴经过的位置，`axis` 指定运动方向，这里的方向均按其 body 的局部坐标系。

例如，一个放在空中的 body 若没有 joint，会固定在父 body 上；增加 freejoint 后才会在重力作用下自由下落。

## 例子：关节位置不等于工具尖端位置

**条件：** 本章使用[自带单摆模型](../mujoco/models/pendulum.xml)。世界系 z 轴朝上；杆的关节原点在世界坐标 `(0, 0, 1) m`，绕局部 `+y` 轴按右手规则转动。零位时，杆沿局部 `-z` 方向伸出 `0.5 m`，尖端 site 为 `(0, 0, -0.5) m`。

**几何推导结果：** 关节角 `q` 单位 rad，尖端的世界坐标为：

```text
x = -0.5 sin(q)
y = 0
z = 1 - 0.5 cos(q)
q = 0       → tip = (0, 0, 0.5) m
q = 0.5 rad → tip ≈ (-0.239713, 0, 0.561209) m
```

**解释：** body 原点一直在关节处，site 才是杆末端。控制“末端到某点”前，要先确定读取的是法兰、夹爪中心还是工具尖端（TCP）。仅名称叫 `end_effector` 并不能保证偏移正确。

## 例子：质量翻倍，位置会不会变

**条件：** 保持几何与关节角不变，仅把杆的 geom 质量从 `1 kg` 改为 `2 kg`，惯性由同一几何自动推算。

**结果与解释：** 同一 `q` 下尖端坐标不变，质量和惯量翻倍；动力学方程中的惯性与重力项变化。不能据此断言角加速度总会减半，因为重力矩也变了。若改的是杆长，尖端坐标与惯性通常都会改变。[验证记录](../mujoco/verification.md)核对了几何不变和惯量翻倍。

## 容易混淆的地方

- 长度使用 m、质量使用 kg、惯量使用 kg·m²；渲染的网格缩放不能代替整套物理参数的单位核对。
- joint 的轴在指定局部系中解释，不能直接当成世界轴。MJCF XML 的角度单位由 `compiler angle` 指定，本例明确为 radian；运行时 hinge 的 `qpos` 使用 rad。
- 关节限位约束允许的运动范围；碰撞模型约束接触，两者不能互相替代。仿真限位通常是求解器约束，不是简单把位置数组裁剪到边界。
