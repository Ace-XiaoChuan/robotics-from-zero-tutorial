# 11：从异常现象定位问题

本文行数：73行，预期阅读时长：5分钟

## 开发者理解：先找出结果从哪一层开始偏离

“机械臂不动”可能表示没有推进时间、命令没有作用到关节、执行器力太小，也可能是画面没有更新。先把这些情况区分开，再改对应环节，通常比同时调步长、增益和摩擦更容易看清原因。

最小检查信息是：加载了哪个模型，当前时间、目标、实际角度与速度、实际执行器力，以及是否有接触或限位。读数必须来自同一份 data，并明确采样阶段。

## 从加载到显示逐层缩小

1. **确认模型。** 输出实际解析后的 XML 路径与 MuJoCo 版本。核对模型名称、关节名称、nq/nv/nu，避免实际上加载了另一份同名文件。
2. **检查静态几何。** 初始化后调用 forward，核对零位、转轴与工具点。此时可设置 qpos 做几何对照，先排除坐标解释错误。
3. **检查无窗口步进。** 固定初态与短输入，观察 time、qpos、qvel 是否正常变化。把显示问题与物理问题分开定位。
4. **检查命令到实际力。** 读 ctrl、actuator_force 和 qfrc_actuator，结合传动与输出范围解释；再检查外力与约束。
5. **检查观测与显示。** 确认派生量已更新、图像采样时刻正确，最后看相机、同步和窗口环境。

无需每次执行全部步骤。已有证据指向哪层，就从那里继续。例如无窗口运动和坐标都正确，但窗口黑屏，应先处理显示环境。

## 例子：目标已经收到，仍然到不了

两关节机械臂从 `[0,0] rad` 开始，目标在 1 秒内过渡到 `[0.5,-0.8] rad`，保持至 3 秒。除下列执行器力矩范围外，其余模型、输入和时间设置相同：

| MuJoCo 3.13.0 实际结果 | 正常范围 ±8 N·m | 很弱的范围 ±0.01 N·m |
| --- | --- | --- |
| 最终命令 / rad | `[0.5,-0.8]` | `[0.5,-0.8]` |
| 最终实际角度 / rad | `[0.499999,-0.799995]` | `[0.167958,-0.301852]` |
| 目标减实际 / rad | `[0.00000128,-0.00000483]` | `[0.332042,-0.498148]` |

弱执行器组已推进 3 秒、命令也正确；实际运动受驱动力限制。重新赋值同一个目标不会增加可用力矩。下一步应检查任务时长、所需驱动力和执行器能力，再决定是否改变模型或目标轨迹。

这里给出了明确的参数对照，因此可以定位到力矩限制。面对未知模型时，不能看到误差就直接推断原因；还应查重力、限位、接触、控制增益和目标可达性。

## 例子：物体看起来在地上，却没有被支撑

[方块对照](../08_contact_constraints/README.md)关闭了两侧碰撞掩码。1 秒时 `ncon=0`，物体中心 z 约为 `-4.85481 m`。恢复碰撞后，中心接近 `0.05 m`，四个接触点的法向力总和接近 `1.962 N`。

这种问题优先检查碰撞设置，而不是调位置执行器增益。若 ncon 非零但支撑不足，还需要继续确认接触是否激活、接触力、几何方向、软硬参数和求解状态。

## 把一个大场景缩成可解释的小问题

先固定初态和输入，只保留与现象有关的物体与关节。一次只改一组参数，并保存少量对应读数。例如研究方块滑动时，保持重力和质量不变，明确无摩擦与有摩擦的接触配置。

若必须关掉重力、摩擦或某些接触来排查，应把它记录为对照条件。简化后正常可以帮助定位原因，但还要回到任务原条件核对，不能只保留容易成功的配置。

数值异常时也要查看 MuJoCo 的 warning 与非有限数值。部分异常会触发自动重置，表现为时间突然回到零；程序还在循环，并不说明仿真状态一直有效。

## 给 AI 或同伴描述问题时带什么

一个有效描述可以是：“使用这份自包含 XML，MuJoCo 3.13.0，步长 0.002 s；初态为零，两个 position 目标为 `[0.5,-0.8] rad`，按仿真时间运行 3 秒。ctrl 正确但角度只有某值，实际输出已达到某个限幅。”

这比只给一张机械臂没动的截图多出了输入、状态、时间和约束信息。附上最小模型与短程序，就能更容易复现和解释现象。
