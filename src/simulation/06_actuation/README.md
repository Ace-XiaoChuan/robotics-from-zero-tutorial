# 06：输入怎样通过执行器变成运动

本文行数：88行，预期阅读时长：5分钟

**`ctrl` 是执行器的命令数组；至于其中的每一项具体是代表力矩、位置目标还是其他量，要看 actuator 的定义与传动。**

## 开发者理解：从命令到实际关节力

“让关节到 0.5 rad”可以交给位置伺服执行器(position servo actuator)，也可以由自己的控制器先计算力矩，再交给 motor。前者输入目标位置，后者输入驱动命令；最终运动都由产生的力与系统动力学决定。

这里的 **控制器（controller）** 指“根据目标和当前状态计算控制命令”的算法或程序，不一定是一块硬件控制板。它可以只是你写的几行 Python，例如 PD 控制。

读程序时要把命令和 XML 一起看。biu如 `ctrl[0] = 0.5` 只给出了一个数值，但是没有执行器类型、传动和单位时，就缺少可解释性。

## 速记

| 接口或模型配置 | 含义 |
| --- | --- |
| `motor` | 直接驱动，输出还要经过 gear 等传动映射 |
| `position` | 位置伺服目标，内部由误差产生力，并非直接改位置 |
| `velocity` | 速度伺服目标，内部由速度误差产生力 |
| `data.qfrc_applied` | 外加广义力，长度 nv；绕开 actuator 的输入与传动路径 |
| `data.actuator_force` | 执行器空间的力 |
| `data.qfrc_actuator` | 执行器映射到自由度上的广义力 |

## 例子：一个可解释的电机输入

自带模型使用：

```xml
<motor name="hinge_motor" joint="hinge" gear="1"
       ctrllimited="true" ctrlrange="-2 2"/>
```

**条件与推导：** 这是直接驱动 hinge 的 motor，gear 为 1，无额外激活动力学；`ctrl=0.2` 对应施加 `0.2 N·m` 的关节力矩。正方向与 joint 的 `+y` 转轴一致。

**结果：** `ctrl=3` 超出范围时，正常启用控制限幅的计算使用 2，得到 `2 N·m`；但 `data.ctrl[0]` 本身仍可显示 3，不能只看输入数组判断实际输出。[检查脚本](../mujoco/check_basics.py)验证了这一点。

**解释：** 简单 hinge 的 gear 若改为 2，同一 motor 输入产生的关节力矩也变为两倍。对于 position actuator，简单 hinge 传动下目标对应的是 `gear × q`；只有 gear=1 等条件满足时，才能直接把输入读作关节目标角度。

## 例子：给目标位置，不会瞬间到位

教学配置 `<position joint="hinge" kp="20" gear="1"/>` 在不含其他执行器偏置和限幅影响时，产生类似 `tau = 20 × (ctrl - q)` 的弹簧力矩。若目标 `0.5 rad`、当前位置 `0.2 rad`，这一项为 `6 N·m`。

这只是某时刻的执行器力矩推导，实际加速度还受惯性、重力、阻尼与接触影响，目标也不保证达到。增益、稳态误差和跟踪曲线属于 S5。

## 命令、执行器力与关节力的路径

```text
ctrl：命令
  → 输入限幅与执行器内部动态（取决于类型）
  → actuator_force：执行器空间的力
  → 传动映射
  → qfrc_actuator：作用到各自由度的广义力
  → 与重力、被动力、外力、约束共同决定运动
```

本教程采用无激活动态、单位传动比的一对一关节驱动。有滤波、激活动态、肌腱或其他传动时，中间关系会更复杂；不要默认所有执行器都对应一个独立关节。

| 配置 | 限制什么 | 能直接保证什么 |
| --- | --- | --- |
| `ctrlrange`，启用控制限幅 | 输入命令 | 参与计算的命令受限 |
| `forcerange`，启用力限幅 | 执行器输出力 | 单个执行器的输出受限 |
| joint `range`，启用限位 | 关节允许的运动范围 | 求解器会施加限位约束，仍受软约束与数值误差影响 |

限制目标位置，并不同时限制瞬时力矩；限制执行器力，也不等于把关节角硬裁剪在某区间。多执行器作用于同一关节时，还要看合力及模型中配置的关节总执行器力限制。

## 例子：目标正确，力矩却不够

[两关节模型](../mujoco/models/planar_arm.xml)为每个位置执行器配置 `kp=40、kv=8、gear=1`，输出限幅为 `[-8,8] N·m`。在肩关节 q=0、速度为零时突然给 `0.5 rad`，未限幅的伺服项为 `40×0.5=20 N·m`，实际执行器输出为 `8 N·m`。这是一次当前状态计算，经检查脚本核对。

在[综合运动](../12_arm_walkthrough/README.md)中，目标通过 1 秒曲线逐渐变化，再保持 2 秒。把两个执行器的输出范围改成 `[-0.01,0.01] N·m` 后，3 秒时实际角度只有约 `[0.167958,-0.301852] rad`，目标仍是 `[0.5,-0.8] rad`。

这个结果说明命令已经收到，但执行能力与动力学限制了实际运动。排查时应一起读目标、实际状态和实际输出；不能只检查 ctrl 已经等于目标。

## 外加力与执行器输入怎样选择

`qfrc_applied` 在自由度空间施加广义力，适合明确的扰动力或自定义驱动力；其长度为 nv，转动项单位 N·m、平移项单位 N。`xfrc_applied` 则按 body 施加世界系下的力与力矩，每行依次是 `[Fx,Fy,Fz,Tx,Ty,Tz]`，作用点为该 body 质心。

这两种外力字段会保留到被程序修改或重置；一个“推一下”的扰动需要在结束后清零。它们不经过 actuator 的输入、传动与输出限幅，若模型同时启用执行器，力会共同作用。选择接口时先说明你想模拟电机命令，还是额外施加的扰动。

## 旧脚本应怎样理解

旧 Panda 脚本通过 `qfrc_applied` 加力，与通过 `ctrl` 控制不是同一条路径。若模型自身的 actuator 同时产生力，两者会共同影响运动，必须一起核对。不能把“外加关节力运行了”写成“执行器控制已验证”。
