# S0 · 单元 06：配置与实验复现

本文行数：85行，预期阅读时长：4分钟

**一句话回忆：一次实验的结果属于“代码版本 + 配置 + 输入数据 + 环境 + 随机性”的组合；只保存最后一个数字，下一次就无法解释差异。**

## 速记

- 把会变化的参数放进 YAML、JSON 或命令行，而不是散落在源码常量中；同时记录参数文件的路径和版本。
- 配置有来源和优先级：默认值、配置文件、命令行参数和环境变量覆盖关系必须写清楚。
- 记录代码提交、依赖版本、模型文件、输入数据、随机种子、时间和运行命令。
- 固定随机种子只能减少一类差异；线程调度、GPU 算子、传感器时序和外部服务仍可能带来非确定性。
- 输出应包含原始配置和少量关键指标，构建产物与大型日志按仓库规则处理。
- 复现的目标是能解释差异，不是保证所有硬件和并发程序逐位相同。

## 例子：同一程序的两组配置

`controller.yaml`：

```yaml
controller:
  kp: 20.0
  kd: 0.5
  max_velocity: 1.0  # rad/s
  random_seed: 42
```

启动时明确指定：

```bash
ros2 run arm_demo controller_node \
  --ros-args --params-file config/controller.yaml
```

**结果：** 节点使用 `kp=20.0`、`kd=0.5`、速度上限 `1.0 rad/s` 和随机种子 `42`。如果命令行再次传入同名参数，最终值由节点和 ROS 2 参数覆盖规则决定，应在运行记录中写出实际生效值。

**解释：** 配置文件让“改参数”和“改程序”分开；注释中的单位属于配置契约的一部分。只写 `max_velocity: 1.0` 而不写单位，几周后很容易把 rad/s 当成 deg/s。

结果依据：配置和命令是教学示意；未声称当前仓库存在名为 `arm_demo` 的可执行程序。

## 例子：最小复现实验记录

一条有用的记录至少包含：

```text
代码：git commit abc1234
环境：Ubuntu 22.04，ROS 2 Humble，Python 3.10
命令：python3 scripts/run_demo.py --config configs/demo.yaml
输入：data/episode_0001.npz，shape=(100, 7)，关节单位 rad
随机性：seed=42
结果：末端位置误差 0.010 m，运行 12.4 s
```

**结果与解释：** 另一个人可以先检查提交、配置、输入形状和单位，再判断差异来自代码还是环境。`0.010 m` 是指标，不等于“控制已经正确”；还需要知道目标、坐标系和误差计算方式。

## 推荐的配置边界

| 内容 | 适合放在哪里 | 需要记录什么 |
| --- | --- | --- |
| 机器人模型、关节名和限位 | 版本化的模型/config 文件 | 文件版本、单位、坐标系 |
| 控制增益、阈值、话题名 | YAML 或命令行 | 实际生效值和覆盖来源 |
| 大型传感器数据 | 仓库外或数据目录 | 文件校验和、采集时间、格式 |
| 随机种子 | 配置和运行记录 | 每次实验使用的 seed |
| 依赖和工具链 | `package.xml`、`requirements`、环境记录 | 版本和安装来源 |
| 输出指标与日志 | 小型摘要进入版本记录 | 输入、指标定义、失败原因 |

## 遇到问题时查

| 现象 | 原因或检查方向 |
| --- | --- |
| 同样命令结果不同 | 比较提交、配置、输入文件、随机种子和环境；不要只比较命令文本 |
| 参数文件似乎没有生效 | 打印或查询实际参数值，检查路径、键名、命名空间和覆盖顺序 |
| 本机能运行，换机失败 | 记录 OS、编译器、ROS 发行版、Python/库版本和模型路径 |
| 固定 seed 仍有差异 | 检查并发、GPU、时间步长、传感器噪声和外部服务；说明可接受误差 |
| 结果文件太大无法提交 | 保存配置、版本、校验和与关键摘要；按 `.gitignore` 规则放置原始产物 |
| 清理 build 后行为变化 | 检查是否依赖了旧 install、环境变量或未记录的生成文件 |
