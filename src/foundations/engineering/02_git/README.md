# S0 · 单元 02：Git 与 agent 协作

本文行数：51行，预期阅读时长：2分钟

**快速回忆：改文件、提交、推送是三个不同状态。** 日常操作继续交给 agent，阅读下面的例子就能复习。

## 记住这四点

| 概念 | 含义 |
| --- | --- |
| 工作区 | 磁盘上正在修改的文件，保存文件不等于进入 Git 历史 |
| 差异（diff） | 两个状态之间具体改了哪些内容 |
| 提交（commit） | 本地历史检查点，有编号和说明；不证明代码已验证正确 |
| 推送（push） | 把提交发送到远程仓库，本地提交不会自动出现在 GitHub 上 |

定义可按需查 [Git commit](https://git-scm.com/docs/git-commit) 与 [Git push](https://git-scm.com/docs/git-push) 官方说明。

## 例子 1：看懂 agent 的改动摘要

假设 agent 把模型路径从固定字符串改为命令行参数，下面是简化的差异示意，并非当前仓库的实际改动：

```diff
- model_path = "/home/me/models/robot.xml"
+ model_path = args.model
```

**含义：** 现在由调用者指定模型文件。你主要判断这个变化是否符合需求，以及新运行命令有没有说明。

如果状态列表出现 `M README.md`，表示文件有修改；`?? notes.md` 表示新文件尚未跟踪。普通 `git diff` 不包含未跟踪文件和已暂存改动，因此“diff 为空”不一定表示没有修改。需要时让 agent 汇总完整范围，见 [速查](notes.md#diff)。

## 例子 2：“完成了”到底完成到哪一步

| agent 的报告示例 | 已经完成 | 还不能据此认定 |
| --- | --- | --- |
| “文件已修改，验证通过” | 改动已在工作区，做过所述验证 | 已保存为提交 |
| “已创建本地提交，编号为……” | 改动进入本地历史，可用编号定位 | 已同步到 GitHub |
| “已推送到远程某分支” | 相应提交已同步到该远程分支 | 已合并到主分支 |

**结论：** 看清改动范围、验证结果、提交编号和推送目标，就足以进行日常协作。

## 文件管理只记一条

保留有助于理解与复现的材料：代码、笔记、配置和小型示例通常进入版本记录；构建产物、缓存和大型数据按项目规则处理。具体操作由 agent 完成，本仓库规则见 [.gitignore](../../../../.gitignore)。

需要保存阶段成果时，可以对 agent 说：

> 请检查本次任务的改动，完成必要验证后保存为本地提交，告诉我提交编号，以及还有哪些改动未包含。

分支、冲突和恢复方式遇到时再查 [协作速查](notes.md)。本页是解释性例子，不代表实际执行了提交或推送。
