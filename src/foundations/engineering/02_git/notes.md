# Git 协作速查

本文行数：51行，预期阅读时长：2分钟

只在遇到相应问题时查阅；正常操作交给 agent 即可。

<a id="diff"></a>

## 1. agent 说改了，为什么 diff 没内容

| 情况 | 怎样查看 |
| --- | --- |
| 已跟踪文件的修改还没暂存 | `git diff` |
| 已暂存，准备写入下一次提交 | `git diff --cached` |
| 新文件还没跟踪 | `git status --short` 找到文件，再直接打开 |
| 已经提交 | `git show --stat HEAD` 看最近提交的文件摘要 |

“暂存”可理解为选出下一次提交要记录的内容，不需要自己记操作流程。diff 的比较范围见 [官方说明](https://git-scm.com/docs/git-diff)。

当前仓库整理目录时，可能同时出现旧路径删除和新路径未跟踪。让 agent 结合内容判断是否属于搬迁，不能只看一个 `D` 就判断文件丢失，也不能据此认定所有删除都正确。

<a id="checkpoint"></a>

## 2. 已提交，为什么 GitHub 没变化

提交保存在本地；推送后相应提交才同步到远程。让 agent 报告“提交编号、当前分支、是否推送及目标分支”即可。工作区干净也不代表已经同步远程。

## 3. 改完不好用了，怎样描述恢复需求

说明想恢复的功能和最后正常的版本，例如：

> 上一个可运行版本中，相机图像能正常显示。请比较最近相关改动，恢复这项功能，保留后来补充的笔记，并验证结果。

agent 再选择局部修复或版本恢复方式。Git 能提供已记录内容的历史；未提交的新文件和修改不一定有可恢复记录。

<a id="files"></a>

## 4. 哪些文件应该留在仓库

- **通常保留**：源码、学习笔记、模型来源说明、运行配置、小型输入与必要指标。
- **通常忽略或单独存放**：`build/`、`install/`、`log/`、缓存、虚拟环境和大型数据。

`.gitignore` 主要影响未跟踪文件；已经跟踪的文件，不会因为后来加了忽略规则就自动从版本记录中消失。需要时让 agent 检查跟踪状态。

## 5. 一句通用协作要求

> 完成后告诉我：改了什么、怎样验证、是否提交、是否推送，以及还有什么未完成。

无需为了使用 agent 先学完整套 Git。把注意力放在任务范围与结果是否正确。
