# 05：旋转表示与约定

本文行数：76行，预期阅读时长：4分钟

**旋转矩阵、欧拉角、轴角和四元数都能描述朝向，但数字的排列、旋转顺序和参考坐标系必须一起说明。**

## 速记要点

- 本章使用右手系、列向量；计算角度用 rad，示意角度同时标出 °。正转按右手定则。
- `R_A_B` 是 B 系相对 A 系的朝向，也是把同一几何向量的 B 系坐标换成 A 系坐标的矩阵：`v_A = R_A_B @ v_B`。
- 旋转矩阵是无量纲的 `3 × 3` 矩阵，满足 `R.T @ R = I`、`det(R) = +1`。反向转换为 `R_B_A = R_A_B.T`。
- 姿态有 3 个自由度；矩阵的 9 个数和单位四元数的 4 个数含有约束，并不是更多自由度。

## 例子：B 系相对 A 系绕 +z 转了 90°

两个原点重合，z 轴重合，B 的 x 轴朝 A 的 +y，B 的 y 轴朝 A 的 -x。从 A 的 +z 端朝原点看是逆时针。

$$
R_{A\_B}=R_z(\pi/2)=
\begin{bmatrix}0&-1&0\\1&0&0\\0&0&1\end{bmatrix}
$$

矩阵的三列依次是 B 的 x、y、z 单位轴在 A 中的坐标。因此，B 系位移 `v_B = [1, 0, 0] m` 在 A 中是：

```python
import numpy as np

R_A_B = np.array([[0., -1., 0.], [1., 0., 0.], [0., 0., 1.]])
v_B = np.array([1., 0., 0.])
v_A = R_A_B @ v_B       # [0, 1, 0] m
v_B_again = R_A_B.T @ v_A  # [1, 0, 0] m
```

**结果与解释：** 几何箭头没有移动，只是换了一套坐标描述；长度仍是 1 m。同一个数值矩阵也可以表示“在固定 A 系内，把箭头主动转动 90°”，但那时输入和输出都在 A 系，物理含义不同。必须根据符号和上下文区分，不能仅凭矩阵数字判断。

## 同一个朝向的四种写法

以下均表示刚才绕 +z 的 90° 朝向，轴方向在 A 中表达。

| 表示 | 本例数值 | 必须说明的约定 |
| --- | --- | --- |
| 旋转矩阵 | 上面的 `R_z(pi/2)` | 从哪个系转到哪个系 |
| 欧拉角 | `[roll, pitch, yaw] = [0, 0, pi/2] rad` | 本章定义 `R = Rz(yaw) @ Ry(pitch) @ Rx(roll)` |
| 轴角 | 单位轴 `[0, 0, 1]`，角 `pi/2 rad` | 轴在哪个系表达；旋转向量为轴乘角度 |
| 单位四元数 | 按 `[w,x,y,z]` 为 `[sqrt(2)/2, 0, 0, sqrt(2)/2]` | 分量顺序、旋转方向及单位长度 |

单位四元数的轴角写法为：

$$
q=[\cos(\theta/2),\ u_x\sin(\theta/2),\ u_y\sin(\theta/2),\ u_z\sin(\theta/2)]
$$

这里 `u` 是无量纲单位轴。`q` 与 `-q` 表示相同旋转，所以不能直接用四元数分量相减来衡量姿态误差。若接口按 `[x,y,z,w]` 排列，本例应写成 `[0, 0, sqrt(2)/2, sqrt(2)/2]`。

## 例子：为什么旋转顺序不能省略

在固定 A 系主动旋转位移 `v = [0,1,0] m`，比较两种顺序：

| 操作 | 列向量写法 | 结果 / m |
| --- | --- | --- |
| 先绕固定 x 轴 90°，再绕固定 z 轴 90° | `Rz @ Rx @ v` | `[0,0,1]` |
| 先绕固定 z 轴 90°，再绕固定 x 轴 90° | `Rx @ Rz @ v` | `[-1,0,0]` |

**结果与解释：** 两个结果不同。欧拉角的三个数字只有连同轴顺序、固定轴或随动轴约定才有意义。上面的 RPY 定义可按固定轴先 x、再 y、最后 z 理解。

## 易错点与适用边界

- 欧拉角直观，但本章 RPY 在 `pitch = ±pi/2` 附近有表示奇异性；这不等于机械臂本体处于运动学奇异位形。
- 轴角在零转角时轴不唯一，在 180° 处也有符号与分支问题；姿态差应由成熟旋转库处理边界。
- 四元数要归一化，零四元数无效；插值需处理 `q` 与 `-q`，不能直接线性插值后当作角速度恒定的运动。
- 一个 `3 × 3` 数组不一定是旋转矩阵。例如 `diag(1,1,-1)` 虽然正交，但行列式为 -1，是反射。
- 浮点计算只要求在合适容差内正交。不要在每次中间计算时过早舍入，显示时再格式化。
