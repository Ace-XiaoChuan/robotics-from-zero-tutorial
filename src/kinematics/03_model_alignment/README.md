# 03：关节映射、基座与工具对齐

本文行数：74行，预期阅读时长：4分钟

**比较两个 FK 结果之前，要确认它们使用同一关节构型、同一基座、同一物理工具点和同一时刻。两个数组长度相同，不代表它们描述同一个状态。**

## 速记要点

| 必须对齐的量 | 要说明什么 |
| --- | --- |
| 关节映射 | 名称、排列、轴正方向、零位、单位 |
| 基座 | FK 相对 world、base 还是其他坐标系 |
| 末端 | 查询的是 link、法兰、夹爪中心还是 TCP |
| 模型几何 | 连杆尺寸、固定关节、工具安装变换 |
| 数据时刻 | 状态来自哪个时间戳，派生位姿是否已更新 |

本章沿用 2R：长度 `[0.4,0.3] m`、基座 B、关节顺序 `[joint1,joint2]`。所有计算为教学静态数据。

## 例子 1：同样两个数，顺序不同结果就不同

接收的消息为 `names=[joint2,joint1]`，`positions=[pi/2,0] rad`。运动学模型需要 `[joint1,joint2]`：

```python
import numpy as np

names = ["joint2", "joint1"]
positions = [np.pi / 2, 0.]
by_name = dict(zip(names, positions))
q = np.array([by_name[name] for name in ["joint1", "joint2"]])
```

**结果：** 正确 q 为 `[0,pi/2]`，末端 `[0.4,0.3] m`。若直接复制消息数组，则 q 变成 `[pi/2,0]`，得到 `[0,0.7] m`。

这里假定名称唯一、数量匹配且必要关节齐全；实际接收端需要验证这些条件。qpos 中还可能包含浮动基座和夹爪，关节 ID 也不一定等于数组地址，不能默认前 n 项总是机械臂关节。

若设备关节读数有符号和零位差异，可明确写 `q_model = s * (q_device - q_zero)`，s 为 +1 或 -1。例如设备读数 `0.1 rad`、零位偏置 `0.1 rad`、s=+1，模型角为 0。该映射参数必须来自模型或标定，不能为了对齐某一帧随意调整。

## 例子 2：法兰与 TCP 为什么差 10 cm

将 2R 的连杆末端视为法兰 F。`q=[0,pi/2]` 时，`p_B_F=[0.4,0.3,0] m`，法兰绕 z 朝向 90°。TCP 相对法兰沿法兰 +x 伸出 `0.1 m`，朝向不变：

$$
T_{B\_TCP}=T_{B\_F}T_{F\_TCP}
$$

**结果：** 法兰 +x 在基座中朝 +y，因此 TCP 位置为 `[0.4,0.4,0] m`，不是 `[0.5,0.3,0] m`。

若一套库查询法兰、另一套查询 TCP，位置差会随工具朝向改变，不能当成固定世界系误差扣除。

## 例子 3：两个库的 world 不同

设 B 相对世界 W 绕 z 转 90°，B 原点在 W 中为 `[1,2,0] m`。将刚才 TCP 的基座坐标 `[0.4,0.4,0] m` 换到 W：

$$
T_{W\_TCP}=T_{W\_B}T_{B\_F}T_{F\_TCP}
$$

**结果：** 世界系 TCP 位置为 `[0.6,2.4,0] m`，朝向为绕 z 的 180°。这个位置与基座系结果不同，但两者可以同时正确。

## 对齐结果应怎样报告

对于同一物理 TCP，统一到同一参考系后，分别报告 `||p1-p2||`（m）与相对旋转角（rad）。不能把位置和姿态的原始分量混成一个无单位的“误差”。

至少使用多组非零关节状态；一个姿态对齐不能证明关节顺序、轴方向和工具变换都正确。运动中的模型比较还应检查时间差，例如沿某轴以 `0.1 m/s` 运动时，`20 ms` 的状态时间差就对应约 `2 mm` 的位置差。
