# 06：多传感器时间对齐与任务状态

本文行数：77行，预期阅读时长：4分钟

**把正确的坐标变换用在错误时刻，也会得到错误位置。图像、关节状态和估计必须同时说明“相对于谁”与“描述什么时候”。**

## 速记要点

- 采样时间、接收时间、处理完成时间不同；采样时间需由设备或采集链路定义。
- 多设备时间戳需要可比较的时钟域，配对算法无法自动修复时钟偏差。
- 眼在手上的图像应配曝光时刻的机器人位姿。
- 旧测量可以保留用于追踪来源，但不能每次发布时改成“刚测到”。

## 例子：200 ms 错位造成 2 cm 偏差

假设相机随末端沿基座 x 正方向以 `0.10 m/s` 匀速运动，朝向固定，目标在基座系静止：

| 事件 | 时间 | 应如何解释 |
| --- | --- | --- |
| 图像曝光参考时刻 | `1.00 s` | 本帧描述的几何关系 |
| 图像到达处理节点 | `1.15 s` | 已有 `0.15 s` 传输与缓存延迟 |
| 检测计算结束 | `1.20 s` | 处理完成，并没有重新曝光 |

若拿 `1.20 s` 的末端位姿乘 `1.00 s` 的相机系目标位姿，会额外带入 `0.10×0.20=0.02 m` 的基座 x 偏移。

**结果与解释：** 正确做法是用 `T_B_EE(1.00)` 计算 `T_B_Tag(1.00)`。若任务需要 `1.20 s` 的移动目标状态，再用明确的运动模型从 1.00 s 预测到 1.20 s，保留估计时间和上次测量时间两个字段。

即使相机固定，移动目标的旧位姿仍会过期；只是固定相机外参本身没有随时间变化。

## 例子：插值需要左右两侧样本

同一时钟下，有末端基座系 x 位置 `p(1.00)=0.40 m`、`p(1.10)=0.42 m`。在匀速近似成立时：

$$
\lambda=\frac{1.04-1.00}{1.10-1.00}=0.4,\qquad
p(1.04)=(1-\lambda)0.40+\lambda0.42=0.408\ \mathrm m.
$$

**解释：** 查询 1.04 s 可插值，查询 1.20 s 已属于外推；不能因为同一个公式还能算就宣称有对应观测。间隔过长、速度变化剧烈时，插值误差也需考虑。

位置线性插值、四元数的球面插值和关节角插值有不同语义。连续旋转关节跨越 ±π 时先处理角度连续性；多关节机械臂对关节插值后做 FK，与对两个末端位姿插值一般不相同，应明确采用的近似。

## 时钟、缓存和同步方法

| 情况 | 需要明确的处理 |
| --- | --- |
| 相机与编码器各有硬件时钟 | 校准偏移与漂移，记录时间映射及误差 |
| 同时使用仿真时间和系统时间 | 显式区分，不能直接相减判断年龄 |
| 图像帧率低于关节状态频率 | 缓存关节状态，按图像时刻查询或插值 |
| 近似时间配对 | 限定最大差值，承认剩余时间误差 |
| 数据迟到或乱序 | 使用历史更新与重传播，或显式丢弃并计数 |
| 仿真 reset 或回放时间倒退 | 清空相关缓存、重新初始化估计，避免跨 episode 配对 |

时间配对只解决“选哪两条消息”；它不保证两个传感器物理上同时采样。曝光是一个时间区间，需说明时间戳代表开始、中间还是结束；快速运动或滚动快门还可能使单一位姿近似失效。

ROS TF 与时间的已有解释复用 [ROS 2 笔记](../../ros2/README.md)。读取当前最新变换与查询图像时间的变换是不同意图，超出缓存范围时应报告失败原因。

## 给规划器的目标记录

下面是教学字段建议，非本仓库现有消息类型；坐标链已完成，使用基座系表达位置，姿态若用四元数则明确排列 `[x,y,z,w]`。

| 字段 | 语义 |
| --- | --- |
| `pose_base`, `frame_id` | 目标原点在基座系的位姿；指定目标是 Tag、物体还是抓取点 |
| `estimate_stamp` | 这个估计描述的状态时刻 |
| `measurement_stamp` | 最近参与更新的观测采样时刻 |
| `source`, `target_id` | 传感器或算法来源、目标身份 |
| `position_covariance` | 基座系 3×3，单位 m²；未估计时明确未知 |
| `valid`, `reason` | 是否满足当前任务的使用条件及失效原因 |

例如当前 `1.20 s`、测量时间 `1.00 s`，若本任务示意规定最大测量年龄为 `0.10 s`，则年龄 `0.20 s` 应判过期；这个阈值不是通用机器人标准。预测到当前时刻也不能删除“已连续 0.20 s 没有新观测”这一信息。

发现无效状态时，由任务层依据场景决定等待、重新观测或结束当前动作；记录保留原因。后续保存图像、状态和动作时，还要明确动作在观测前还是后下发，见[数据采集](../../data_collection/README.md)。

本章插值与延迟数值为教学例子，见[核对记录](../verification.md)；未进行多硬件时钟同步或 ROS TF 实时集成验证。
