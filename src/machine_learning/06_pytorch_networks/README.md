### 验证集怎样使用？

本周采用固定验证集：每个 epoch 训练结束后，用同一份 10,000 张验证图片检查 loss 和 accuracy。验证时不反向传播、不更新模型参数；使用评估模式并关闭梯度记录。观察训练与验证曲线，帮助判断模型是否学会、是否开始过拟合，并选择训练轮数和设置。模型及设置确定后，才使用官方测试集报告最终效果。

验证集不必每轮重新划分；固定试卷才能方便比较不同轮次和配置。

### 1. 模型：从图片到十个分数

```text
64 张灰度图片     [64, 1, 28, 28]
    ↓ Flatten：每张图铺平成一行，不混合不同图片
784 个像素       [64, 784]
    ↓ Linear(784, 128)：加权求和并加上偏置
128 个中间结果   [64, 128]
    ↓ ReLU：负数变成 0，非负数保留
128 个中间结果   [64, 128]
    ↓ Linear(128, 10)：为数字 0～9 打分
10 个类别分数    [64, 10]
```

网络共有 101,770 个可学习参数，包括两层 Linear 的权重和偏置；Flatten 和 ReLU 没有可学习参数。`128` 是我们选择的隐藏层大小，权重和偏置的具体数值则由训练来调整。

这十个分数叫 logits，还不是概率。`argmax(dim=1)` 为每张图片找分数最高的类别。例如最高分在下标 3，就预测数字 3。刚建立模型时参数尚未学习，这时输出只用于确认形状和计算流程正确。

### 2. 训练：一批图片怎样改变参数？

`engine.py` 的 `train_one_epoch()` 展示一次学习的核心：

```python
optimizer.zero_grad()          # 清掉上一次计算留下的梯度
logits = model(images)         # 前向传播：当前模型为每张图打分
loss = loss_fn(logits, labels) # 交叉熵：对照正确标签，衡量错误程度
loss.backward()               # 反向传播：计算各参数的梯度
optimizer.step()              # Adam：依据梯度真正调整参数
```

交叉熵损失接收原始分数和整数标签，不需要提前把输出转成概率，也不需要把标签改成十个数。准确率回答“猜对了多少”，损失则提供适合计算梯度的学习信号。

反向传播只计算梯度，优化器才更新参数。Adam 会结合当前梯度及历史梯度信息调整更新，学习率 `0.001` 控制调整的整体尺度，并不是每个参数每次固定加减 `0.001`。

### 3. 一轮训练后，用固定验证集检查

训练一轮就是遍历全部 50,000 张训练图，分成 782 批逐批更新参数。随后用 10,000 张验证图检查损失和准确率。验证使用 `model.eval()` 和 `torch.no_grad()`，不反向传播，不修改权重。

本次运行 5 轮，按最高验证准确率保存最佳一轮的权重；准确率相同时保留较早的一轮。训练指标是在一轮中边更新参数边累计的，验证指标是在轮末参数固定后计算的，因此第一轮验证准确率高于训练准确率也可能是正常现象。

每批损失先乘以该批图片数，再汇总除以总图片数。这样最后只有 16 张的小批次不会被误当成与 64 张的大批次权重相同。

## 概念复习：从传统机器学习过渡到 PyTorch

### 开始前先看全貌：神经网络、前向传播与反向传播

在接触 `Tensor`、`Dataset` 和 `DataLoader` 这些 PyTorch 概念之前，先建立一张完整的思维地图。

#### 什么是神经网络？

神经网络可以先理解为一个**带有大量可学习参数的函数**：它接收输入，经过若干层计算，最后给出输出。

以 MNIST 手写数字识别为例：

```text
28×28 灰度图像
    ↓
神经网络逐层处理图像中的信息
    ↓
输出 10 个分数，分别对应数字 0～9
    ↓
分数最高的类别作为预测结果
```

网络中的一层通常会对上一层的结果做一次变换，再把结果交给下一层。随着数据依次通过各层，原始像素会被逐步转换成更适合分类的内部表示。

神经网络中有两类内容需要区分：

- **网络结构**：有多少层、每层有多少神经元、使用什么激活函数等，通常由开发者设计。
- **模型参数**：主要是权重（weight）和偏置（bias），由训练过程根据数据自动学习。

刚创建的神经网络，其参数通常接近随机值，因此还不会识别数字。所谓“训练”，就是不断调整这些参数，使网络的预测越来越接近正确答案。

> “神经网络”这个名称受到生物神经系统的启发，但在本项目中，把它看成一个由多层数学运算组成、能够通过数据调整参数的模型就足够了。

#### 什么是前向传播？

**前向传播（forward propagation）**是指：输入数据按照网络的层次，从前向后依次完成计算，最终得到预测结果。

```text
输入图像 → 第 1 层 → 第 2 层 → …… → 输出分数
```

训练时，还会把输出分数与真实标签进行比较，计算出一个损失值（loss）。损失用来衡量当前预测“错得有多严重”。

前向传播只使用网络的**当前参数**完成计算，它本身不会修改参数。训练完成后的实际预测阶段也需要前向传播，但通常不再计算损失，也不需要反向传播。

#### 什么是反向传播？

**反向传播（backpropagation）**发生在得到损失以后。它从损失出发，沿着刚才的计算路径反向追溯，计算每个参数对损失产生了多大影响。

这种影响用**梯度（gradient）**表示。可以暂时把梯度理解为一份参数调整建议：

- 某个参数应该向哪个方向调整；
- 这个参数对当前错误的影响有多大。

反向传播的核心数学依据是链式法则，但本周不需要手工推导公式。更重要的是理解：**反向传播负责计算梯度，并不直接修改参数**。真正根据梯度更新参数的是优化器（optimizer）。

#### 一次学习过程的完整关系

```text
输入一批图像
    ↓  前向传播：当前模型预测什么？
预测分数
    ↓  与真实标签比较：预测错了多少？
损失 loss
    ↓  反向传播：每个参数应向哪里调整？
参数梯度
    ↓  优化器：按照梯度和学习率真正修改参数
更新后的神经网络
    ↺ 继续处理下一批数据
```

因此，可以用下面四句话记住训练神经网络的主线：

1. **前向传播**得到预测。
2. **损失函数**衡量预测误差。
3. **反向传播**计算参数的梯度。
4. **优化器**根据梯度更新参数。

后面的概念都是在为这条主线服务：`Tensor` 是数据和参数的表示方式，`Dataset` 与 `DataLoader` 负责提供一批批数据，模型负责前向传播，PyTorch 的自动求导机制负责反向传播，优化器负责更新参数。

### 1. 神经网络在这个任务中做什么？

这里的目标仍然是前几周熟悉的**监督分类**：给定一张图像 `x`，预测真实标签 `y ∈ {0, 1, ..., 9}`。

```text
28 × 28 手写数字图像
        ↓ 神经网络
10 个类别分数
        ↓ 取分数最高的类别
预测数字
```

神经网络不是预先写好“什么形状是 5”的规则。它包含许多可调整的参数（权重和偏置），训练过程通过已标注样本逐步改变这些参数，使正确类别的分数更合理。

与前几周的 scikit-learn 对比：

| scikit-learn 中常见的体验 | PyTorch 中的体验 |
| --- | --- |
| 调用 `model.fit(X, y)`，训练细节大多隐藏在库内 | 自己显式写出取 batch、前向、损失、反向和更新 |
| `X` 常是二维表格 `[samples, features]` | 图像常保留为四维张量 `[batch, channel, height, width]` |
| 算法对象内部管理参数优化 | 模型、损失函数和优化器是三个明确对象 |
| 通常一次 `fit` 完成训练 | 通常按多个 epoch、多个 batch 逐步更新 |

因此，本周的新知识不只是“换一个模型”，而是打开 `.fit()` 这个黑盒，看见训练内部发生的事。

### 2. Tensor（张量）是什么？

可以把 Tensor 理解为**能被 PyTorch 追踪计算、并可放到 CPU 或 GPU 上的多维数组**。

| 张量例子 | shape | 含义 |
| --- | --- | --- |
| 一个数 | `[]` | 标量，例如一个 loss |
| 一组标签 | `[64]` | 64 个样本的类别 |
| 一张 MNIST 图 | `[1, 28, 28]` | 1 个通道、28 行、28 列 |
| 一个 MNIST batch | `[64, 1, 28, 28]` | 64 张单通道图像 |
| 一个 batch 的模型输出 | `[64, 10]` | 每张图对 10 个数字类别的分数 |

阅读张量时优先问三件事：

1. `shape`：每一维分别表示什么？
2. `dtype`：是浮点像素、整数标签，还是布尔掩码？
3. `device`：数据现在在 CPU 还是 GPU？

图像常用 `[N, C, H, W]` 表示：

- `N`（number/batch）：一次处理多少张图；
- `C`（channel）：灰度图为 1，RGB 彩色图通常为 3；
- `H`（height）：高度；
- `W`（width）：宽度。

张量的 shape 是本周最重要的调试线索。很多神经网络错误并不是数学错误，而是某一层收到了不符合预期的 shape。

### 3. Sample、Dataset、DataLoader 和 Batch

这四个词可以用“仓库取货”来理解：

| 概念 | 直觉理解 | 在 MNIST 中是什么 |
| --- | --- | --- |
| sample | 一件货物 | 一张图和它的一个标签 |
| Dataset | 知道所有货物在哪、怎么取的仓库 | 支持用索引取出 `(image, label)` |
| batch | 一次装车的一批货 | 例如 64 张图和 64 个标签 |
| DataLoader | 按规则分批、打乱并送货的调度器 | 从 Dataset 中不断产生 batch |

`Dataset` 回答“第 `i` 个样本是什么”，`DataLoader` 回答“怎样把整份数据送给模型”。它们不是模型，也不负责学习参数。

对一个 Dataset 使用索引：

```text
dataset[0]
  → image: `[1, 28, 28]`
  → label: 一个 0～9 的整数
```

对一个 DataLoader 取一批：

```text
next(iter(loader))
  → images: `[64, 1, 28, 28]`
  → labels: `[64]`
```

DataLoader 中常见的三个参数：

- `batch_size`：一批有多少个样本；
- `shuffle`：每个 epoch 前是否重新打乱样本顺序；
- `num_workers`：用多少个子进程并行准备数据。本周 CPU 小数据集可从 `0` 开始。

通常训练 DataLoader 使用 `shuffle=True`，避免模型持续按固定类别或文件顺序学习；验证和测试不需要打乱，便于结果对齐与排查错误样本。

### 4. Batch、Iteration 和 Epoch 有什么区别？

- **batch(批次)**：一次送入模型的一小批样本。
- **iteration(迭代)/step**：用一个 batch 完成一次前向、反向和参数更新。
- **epoch(纪元)**：模型已经把整个训练集看过一遍。

假设以后有 50,000 个训练样本，batch size 为 64：

```text
每个 epoch 的 iteration 数 = ceil(50000 / 64) = 782
前 781 个 batch 各有 64 个样本
最后一个 batch 有 16 个样本（不丢弃尾 batch 时）
```

为什么不每次只用一个样本？这样梯度波动很大，而且无法高效利用矩阵运算。为什么不一次放入全部数据？这会需要更多内存，并且每个 epoch 只更新一次参数。mini-batch 是运算效率、内存和更新稳定性之间的折中。

### 5. 全连接神经网络如何处理一张图？

先暂时忘掉术语，只看一张手写数字图片在网络里经历了什么。

一张 MNIST 图片由 `28 × 28 = 784` 个小格子组成。每个格子里都有一个数，表示这个位置的亮度，也就是笔迹在这里有多明显。全连接神经网络要做的事情可以概括成三步：

1. 把 784 个小格子排成一行；
2. 根据这些像素算出 128 个中间结果；
3. 再根据中间结果，为数字 0～9 各打一个分。

把一批图片同时送进网络时，形状会这样变化：

```text
一批原始图片              [B, 1, 28, 28]
    ↓ 把每张图片铺平成一行
每张图片的 784 个像素     [B, 784]
    ↓ 第一层：从像素中整理出 128 个中间结果
每张图片的中间表示         [B, 128]
    ↓ 第二层：给 0～9 分别打分
每张图片的 10 个类别分数   [B, 10]
```

#### `[B, 1, 28, 28]` 这样的中括号表示什么？

这里的中括号不是图片里的具体数字，而是数据的**摆放规格**，PyTorch 称它为 shape（形状）。

`[B, 1, 28, 28]` 可以这样读：

- `B`：这一批有多少张图片；
- `1`：每张都是灰度图，只有一个颜色通道；
- 第一个 `28`：图片有 28 行；
- 第二个 `28`：图片有 28 列。

`B` 是 batch size（每批图片数量）的占位符。如果一次拿 64 张图片，`B` 就是 64：

```text
[64, 1, 28, 28]
  ↑   ↑  └──┴── 每张图片高 28、宽 28
  │   └──────── 灰度图只有 1 个通道
  └──────────── 这一批共有 64 张图片
```

网络处理这一批图片后，最左边的 64 一直不变：

```text
[64, 1, 28, 28] → [64, 784] → [64, 128] → [64, 10]
```

这是因为图片没有变多或变少，变化的只是**每张图片的表示方法**。最后的 `[64, 10]` 表示“64 张图片，每张各有 10 个分数”，不是 64 张图片共用一组分数。

#### Flatten

Flatten 的意思是“铺平”。可以想象把一张 `28 × 28` 的方格纸逐行剪开，再首尾相接成一条长纸带：

```text
28 行 × 28 列  →  一行 784 个数
```

Flatten 不会修改像素的数值，也没有需要学习的参数，它只改变像素的排列方式。铺平以后，“哪个像素在上面、哪个像素和谁相邻”就不再明显，这也是以后要学习 CNN 的原因之一。

#### 补充：池化（Pooling），与 Flatten 有什么不同？

**池化就是把一个区域里的多个数，按规则汇总成一个数。** 它常见于下一周的卷积神经网络。本周实际的 DigitMLP 使用 `Flatten → Linear → ReLU → Linear`，没有池化层；这里补充概念，方便对照阅读。

例如，将下面一张 `2 × 2` 数字表作为一个池化窗口：

```text
1  3
2  4
```

| 操作 | 结果 | 做了什么 |
| --- | --- | --- |
| Flatten | `[1, 3, 2, 4]` | 展开成一排，四个数都保留 |
| 最大池化 | `4` | 取窗口内最大的数 |
| 平均池化 | `2.5` | 计算 `(1+3+2+4)/4` |

所以 Flatten 只是改变排列形状，池化则计算一个汇总值，会丢失部分细节。假设对 `28 × 28` 图片使用 `2 × 2` 窗口、步幅 2、不填充，每个通道会变成 `14 × 14`；批次维和通道维保持不变。**这是假设的尺寸例子，本周代码并未加入这个操作。**

常见最大池化、平均池化都没有需要训练的权重和偏置；窗口大小、步幅由我们设置。但梯度仍能通过池化传到前面的层。全局平均池化则把每个通道整张特征图取平均，每个通道留下一个数。

完整的 `4 × 4 → 2 × 2` 手算过程、通道形状和 ResNet18 中的用法见 [第七周：池化是什么](../07_transfer_learning/concepts.md#池化是什么先手算一张特征图)。

#### Linear（线性层/全连接层）

Linear 可以先理解成很多个“打分员”。每个打分员都会查看全部输入，只是关注程度不同。

例如，有的输入位置对判断数字很重要，它对应的权重可能较大；有的位置不重要，权重可能较小。每个打分员会把输入乘上各自的权重，加起来，再加一个偏置：

```text
一个输出 = 所有输入的加权总和 + 偏置
```

这里的**权重和偏置就是模型要学习的内容**。刚开始它们接近随机值，所以模型只会乱猜；训练会一点点调整它们。

`Linear(784, 128)` 的意思是：

- 每张图片送进来 784 个像素；
- 这一层安排 128 个打分员；
- 每个打分员都查看全部 784 个像素；
- 最后得到 128 个中间结果。

因此它被称为“全连接层”：每个输出都和上一层的所有输入相连。

基线网络的参数量：

```text
第一层：784 × 128 个权重 + 128 个偏置 = 100,480
第二层：128 × 10 个权重 + 10 个偏置 = 1,290
总计：101,770 个可训练参数
```

如果看到“神经元”这个词，可以先把它理解为上面的一个打分员，不必把它和真正的人脑细胞一一对应。

#### ReLU（激活函数）

第一层得到 128 个结果后，ReLU 会逐个检查它们：

```text
负数 → 变成 0
正数 → 原样保留
```

它很像一道只允许正数通过的门。为什么需要这道门？如果没有它，不管连续叠多少个 Linear，整个网络能做的事情仍然很单一。加入 ReLU 后，网络才能组合出弯曲、分段的判断规则，处理“同一个数字可以有多种写法”这类更复杂的情况。

零基础阶段只需要记住：**Linear 负责计算，ReLU 让多层网络真的比单层更有表达能力。**

#### 隐藏层

输入是我们能看到的像素，输出是我们能看懂的 10 个数字类别，中间的 128 个数就是“隐藏层”。“隐藏”只表示它们是网络内部的中间结果，并不神秘。

可以粗略地把这些中间结果理解为模型整理出的线索，例如哪里较亮、笔画怎样组合。但这些线索是训练出来的，不是我们提前规定“第 1 个必须找圆圈、第 2 个必须找竖线”，也不保证每个数都有一句简单的人类解释。

### 6. Logits、Softmax、预测和交叉熵

经过最后一层后，每张图片会得到 10 个原始分数，分别对应数字 0～9。这些原始分数的正式名称是 **logits**。

例如，模型看完一张图片后可能给出：

```text
数字：   0     1     2     3    ...
分数： -1.2   0.4   3.8   0.1   ...
```

这些分数可以是负数，也不要求加起来等于 1。它们不是概率，只表示模型更偏向哪个答案。这里数字 2 的分数最高，所以模型预测为 2。程序中“找到最大值所在位置”的操作叫 `argmax`。

如果要把结果展示给人看，可以用 **Softmax** 把这些原始分数换算成一组总和为 100% 的概率。Softmax 更像“翻译器”，方便阅读，不负责决定模型是否答对。

训练时不要自己先做 Softmax。PyTorch 的 `CrossEntropyLoss`（交叉熵损失）希望直接收到 logits，它内部会用更稳妥的方式完成所需计算。

交叉熵可以理解为老师给答案计算的“错误分”：

- 正确答案得分越高，错误分通常越小；
- 如果答错了，而且对错误答案特别自信，错误分会很大；
- 它不只说“对”或“错”，还告诉模型错得有多严重。

这个“错误分”就是 loss。模型训练的目标，就是让许多图片的平均 loss 越来越小。

把数据交给交叉熵时，形状必须是：

```text
logits: [B, 10]  每张图片的 10 个原始分数
labels: [B]      每张图片的正确答案，例如 [7, 2, 1, ...]
loss:   []       整批图片合成的一个错误分
```

### 7. 一次训练 Iteration 中发生什么？

可以把一次训练 iteration（迭代）想成学生完成一小组练习并订正一次：

```text
拿一批图片和正确答案
        ↓
清空上一次留下的修改建议
        ↓
模型做题：为每张图片给出 10 个分数
        ↓
对照正确答案，计算这批题错得多严重
        ↓
分析每个权重对错误造成了什么影响
        ↓
按照分析结果，小幅修改权重和偏置
        ↓
记录错误分和答对数量，再做下一批题
```

这里有两个容易混淆的词：

- **前向传播**：图片从输入层一路走到输出层，模型给出答案；
- **反向传播**：从 loss 往回检查，计算每个参数应该怎样调整。

反向传播只生成“修改建议”，并不会亲自修改参数。真正执行修改的是优化器的 `step()`。

### 8. 梯度、反向传播、优化器与学习率

模型有 101,770 个可调整的参数，可以把它想成一台有十万多个旋钮的机器。预测不准时，我们不可能靠手逐个试旋钮，PyTorch 会帮助完成下面的工作：

- **梯度（gradient）**：给每个旋钮一条建议——往哪边转，以及这个旋钮对当前错误的影响有多明显；
- **反向传播（backward）**：一次算出所有旋钮的梯度；
- **优化器（optimizer）**：读取这些建议并真正转动旋钮；
- **学习率（learning rate）**：限制每次转动的幅度。

学习率太大，就像每次猛转旋钮，可能反复越过合适位置，loss 上下乱跳；学习率太小，则每次只动一点点，可能很久都学不好。本周先用 Adam 优化器和 `1e-3` 学习率建立基线，不需要先研究 Adam 内部的数学细节。

PyTorch 默认会把新梯度加到旧梯度上，所以每批训练开始前要调用 `optimizer.zero_grad()`。这只是擦掉上一次的“修改建议”，**不会擦掉模型已经学到的权重**。

### 9. 训练模式、评估模式与关闭梯度

训练像平时练习：做完题以后要分析错误、修改参数。验证、测试和单张预测像考试或实际使用：只需要答题和统计结果，不能边考试边修改答案。

| 阶段 | 模型要做什么 | 是否计算梯度 | 是否修改参数 |
| --- | --- | --- | --- |
| 训练 | 预测、检查错误并学习 | 是 | 是 |
| 验证 | 检查当前学习效果 | 否 | 否 |
| 测试 | 报告最终成绩 | 否 | 否 |
| 单张推理 | 给一张新图片答案 | 否 | 否 |

代码中通常同时做好两件事：

- 训练前调用 `model.train()`；验证或预测前调用 `model.eval()`；
- 验证或预测时使用 `torch.no_grad()`，告诉 PyTorch 不必准备反向传播所需的记录。

#### Dropout 是什么？

Dropout 是一种用来缓解过拟合的方法，通常放在隐藏层之后。训练时，它会随机把一部分隐藏层输出暂时变成 `0`。例如：

```text
某次训练原有的隐藏层输出：[0.8, 0.0, 1.2, 0.5, 0.9]
这一次随机停用一部分后：[0.8, 0.0, 0.0, 0.5, 0.0]
```

如果写成 `nn.Dropout(p=0.2)`，`p=0.2` 表示训练过程中每个元素有 20% 的概率在本次前向传播中被置为 `0`。下一批数据经过网络时，会重新随机选择被停用的元素。Dropout 不会删除神经元或参数，也不会把对应权重永久改成 `0`；它只影响当前这一次前向传播。

这样做会让网络不能总是依赖某几个隐藏层结果，促使它从多种信息组合中作出判断。它可以看作给训练过程增加了一种随机限制，有时能减小训练集和验证集之间的差距。但 Dropout 并不保证一定提高验证效果，是否需要以及 `p` 取多大，都应该根据验证结果判断。

训练和使用模型时，Dropout 的行为不同：

| 模式 | Dropout 的行为 | 同一输入重复计算 |
| --- | --- | --- |
| `model.train()` | 按概率随机置零，并对保留值作相应缩放 | 输出可能不同 |
| `model.eval()` | 不再随机置零，所有隐藏层结果都参与计算 | 参数与输入相同时输出相同 |

PyTorch 在训练时对保留下来的值进行缩放，使其整体数值尺度与评估时大致一致。因此评估时不需要手动乘以保留比例。`model.train()` 和 `model.eval()` 正是告诉 Dropout 当前应采用哪种行为。

如果要在当前模型中加入 Dropout，结构可以写成：

```python
nn.Flatten(),
nn.Linear(784, 128),
nn.ReLU(),
nn.Dropout(p=0.2),
nn.Linear(128, 10),
```

Dropout 本身没有可学习参数；梯度仍会经过本次没有被置零的部分完成反向传播。它通常只用于训练阶段，在验证、测试和单张推理时关闭。

本周当前的 `DigitMLP` 基线没有加入 Dropout，所以 `train()` 与 `eval()` 暂时不会改变网络的输出。这里先理解它，是为了说明为什么规范的训练和验证代码仍然必须切换模式。`no_grad()` 是另一件事：它控制 PyTorch 是否记录梯度计算，而不是控制 Dropout 是否随机置零。

### 10. Loss 和 Accuracy 为什么都要看？

Accuracy（准确率）很好懂：100 张图答对 92 张，accuracy 就是 92%。但它只统计对错，不关心模型是“勉强答对”还是“非常确定地答对”。

Loss 会看得更细。假设正确答案是 7：

- 模型给 7 和 1 的分数几乎一样，虽然最后猜对 7，但还不够稳；
- 模型给 1 极高的分数、给 7 极低的分数，说明它错得很自信，问题更严重。

Accuracy 可能把第一种情况记作“对”、第二种记作“错”，只有两个结果；loss 则能反映程度。训练时优化器根据 loss 学习，阅读结果时则把 loss 和 accuracy 放在一起看。

每个 epoch 至少并排查看：

```text
train loss       train accuracy
validation loss  validation accuracy
```

常见解读：

| 现象 | 可能含义 |
| --- | --- |
| train/validation loss 都下降，accuracy 都上升 | 正常学习 |
| 训练和验证表现一直都差 | 还没学会：可能训练不足、模型太简单或代码有问题 |
| 训练越来越好，验证反而变差 | 可能只记住了训练题，也就是过拟合 |
| loss 忽高忽低、突然暴涨或出现 `NaN` | 学习率可能太大，也可能存在数据或代码问题 |

### 11. 训练集、验证集和测试集在本周的职责

可以把三份数据分别看成平时练习、模拟考试和期末考试：

```text
官方训练部分（60,000）
├── 训练集（50,000）：平时练习，模型根据答案修改参数
└── 验证集（10,000）：模拟考试，用来选择学习率、结构和训练轮数

官方测试部分（10,000）
└── 期末考试，所有选择完成后只评估一次
```

三份数据其实都有正确标签，区别在于我们怎样使用它们：

- 训练集可以直接影响权重；
- 验证集不修改权重，但可以帮助我们选择训练方案；
- 测试集只在方案完全确定以后报告最终成绩。

如果看完测试成绩又回去改学习率，再次测试，就相当于根据期末试卷备考。这样得到的分数不能真实代表模型面对新数据的能力。

### 12. Device（CPU/GPU）与随机性

Device 表示“计算在哪里做”。常见选择是 CPU 和 GPU。模型与输入数据必须在同一个设备上，就像计算器和要按的数字必须在同一张桌子上；模型在 GPU、图片在 CPU 时，PyTorch 会直接报错。

当前安装的是 CPU 版 PyTorch，对这个小型 MNIST 项目已经足够。以后换成 GPU，训练的主要步骤不会改变，只需要把模型和数据一起移动到 GPU。

训练中还有一些看似相同、实际每次可能略有变化的环节：

- 训练/验证划分；
- 模型最开始的随机权重；
- 每轮训练时图片的打乱顺序；
- 部分计算实现。

随机种子（random seed）像是告诉程序“使用第 42 套随机结果”。固定它以后，两次实验更容易使用相同的数据划分、初始权重和打乱顺序，比较学习率等变量时会更公平。固定随机种子不是提高准确率的技巧，也不保证不同电脑上的结果每一位小数都完全相同。

### 13. 数据到模型的完整心智图

```text
磁盘中的 MNIST 图片和标签
  ↓ Dataset：知道怎样取出第 i 张图片和它的答案
单张图片 `[1, 28, 28]` + 一个正确答案
  ↓ DataLoader：把多张图片装成一批
一批图片 `[B, 1, 28, 28]` + 一批答案 `[B]`
  ↓ Flatten：每张图片从方格铺成 784 个数
一批像素 `[B, 784]`
  ↓ Linear → ReLU → Linear
每张图片对 0～9 的原始分数 `[B, 10]`
  ├── 取最高分 → 模型答案 `[B]` → 与正确答案比较，计算 accuracy
  └── 全部分数 + 正确答案 → 交叉熵 → 一个 loss
                                      ↓ 反向传播：生成参数修改建议
                                    梯度
                                      ↓ 优化器：执行小幅修改
                                  更新后的模型
```

训练时，这条路线会一批一批重复。预测新图片时，只走到“取最高分”就结束，不再计算梯度，也不更新模型。

### 14. 快速复习卡

| 词语 | 一句话复习 |
| --- | --- |
| Tensor | PyTorch 用来保存数字的多维容器；图片、标签和模型输出都是 Tensor |
| shape | Tensor 的摆放规格，例如 `[64, 1, 28, 28]` 表示 64 张灰度图 |
| Dataset | 负责按编号取出一张图片和它的正确答案 |
| DataLoader | 负责打乱数据，并把许多样本分成一批一批 |
| Batch | 模型一次处理的一小批样本 |
| Iteration | 用一个 batch 做题、检查错误并更新一次参数 |
| Epoch | 把整个训练集都学习一遍 |
| Flatten | 把二维像素方格铺成一行，数值不变 |
| Linear | 让多个“打分员”对所有输入做不同的加权计算 |
| ReLU | 让负数不能通过、正数原样通过的一道门 |
| Hidden layer | 输入和最终答案之间的中间计算结果 |
| Logits | 模型给各个类别的原始分数，还不是概率 |
| Softmax | 把原始分数换算成总和为 100% 的概率，方便展示 |
| Loss | 模型这次错得多严重，是训练真正要降低的数值 |
| Gradient | 给每个参数的调整方向和影响大小 |
| Backpropagation | 根据 loss 为所有参数计算梯度 |
| Optimizer | 读取梯度并真正修改参数的工具 |
| Learning rate | 控制优化器每次修改参数的幅度 |
| Dropout | 训练时随机停用一部分隐藏层输出，用于缓解过拟合；评估时关闭 |
| train/eval mode | 告诉模型现在是在练习，还是只进行考试或预测 |

## 默认基线规格

| 项目 | 预定规格 | 原因 |
| --- | --- | --- |
| 数据 | MNIST，0～9 共 10 类 | 任务清晰，适合专注训练闭环 |
| 划分 | 官方训练部分再固定划分为训练/验证；官方测试部分最后只评估一次 | 避免用测试结果选参数 |
| 输入 | 单通道 `28 × 28` 图像，转为浮点张量并展平为 784 维 | 与全连接网络匹配 |
| 模型 | `784 → 128 → 10`，隐藏层使用 ReLU | 足够小，便于画出完整数据流 |
| 输出 | 10 个未归一化 logits | 与多分类交叉熵损失配合 |
| 损失 | 多分类交叉熵 | 标签是 0～9 的单一整数类别 |
| 优化器 | Adam | 先建立稳定基线，不把优化器比较混入本周范围 |
| 起始超参数 | 学习率 `1e-3`，batch size `64`，最多 `5` epochs，随机种子 `42` | 作为所有受控对比的默认基线 |
| 选择指标 | 验证集 accuracy，同时查看 loss | 分数与优化过程都需要解释 |

不在模型末尾手动加 softmax 后再交给交叉熵损失。如需展示概率，只在评估或推理结果上转换，不改变训练时的输出约定。

## 实施时的数据与训练流

```text
MNIST 官方训练部分
  → 用固定种子拆分训练集 / 验证集
  → DataLoader 按 batch 读取
  → 检查一个 batch 的 shape、dtype、数值范围和标签
  → 建立小型全连接网络
  → 逐 batch 执行前向、损失、反向和更新
  → 每个 epoch 记录 train/validation loss 与 accuracy
  → 只用验证结果做受控对比并选择配置
  → 保存 state_dict + 模型配置 + 类别映射
  → 新建模型、加载权重，验证同一输入的 logits/类别一致
  → 锁定配置后，官方测试部分只评估一次
```

开发阶段可先用很小的训练子集和 1 个 epoch 做烟雾测试，只确认流程能跑通，不把这个结果与正式实验比较。

## 停止规则与问题定位

- loss 出现 `NaN`/`inf`：停止正式实验，检查数值范围、学习率、损失输入与标签 dtype。
- 准确率长期接近随机猜测：先用一个小 batch 尝试过拟合，再检查参数是否加入优化器、梯度是否生成、标签是否对齐。
- 训练指标改善而验证指标恶化：记录从哪个 epoch 开始，作为过拟合证据，不用测试集帮助选 epoch。
- 加载失败：先对照模型结构配置和权重键名，不通过忽略不匹配键来掩盖问题。
- 结果不可复现：核对随机种子、数据划分、软件版本和设备；接受不同硬件上可能存在小幅数值差异。
