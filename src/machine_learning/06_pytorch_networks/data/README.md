# MNIST 数据说明

本文行数：132行，预期阅读时长：6分钟

## 默认数据集

默认使用 MNIST 手写数字数据集：单通道 `28 × 28` 灰度图像，标签为整数 `0～9`。数据集的官方训练部分含 60,000 张图像，官方测试部分含 10,000 张图像。

MNIST 原始数据由四个 IDX 文件组成，运行时放在本章的 `data/MNIST/raw/`。本章脚本使用 `download=False`，要求先准备本地数据；若另用 torchvision 下载，应使用同一个本章 `data/` 目录作为数据根目录。

- 来源：`https://ossci-datasets.s3.amazonaws.com/mnist/`
- 本地位置：`data/MNIST/raw/`
- 保留形式：同时保留原始 `.gz` 和解压后的 IDX 文件，后者可供 torchvision 直接读取。

## 学习笔记：`.gz` 和无后缀文件分别是什么？

### 先记住结论

`.gz` 是为了下载和存储而压缩的文件；解压后的无后缀文件是 **IDX 二进制数据文件**。

这些 IDX 文件的内容确实是灰度图像和对应标签，但它们不是 PNG、JPEG 这样能直接用图片查看器打开的图像文件。一个图像 IDX 文件会把整个数据集的许多张图连续存放在一起，而不是“一张图对应一个文件”。

```text
用于下载的压缩文件
train-images-idx3-ubyte.gz
        ↓ 解压
程序直接读取的 IDX 二进制文件
train-images-idx3-ubyte
        ↓ torchvision 解析
60,000 张可按索引访问的 `28 × 28` 灰度图
```

“没有后缀”不代表文件没有格式。`idx3-ubyte` 和 `idx1-ubyte` 已经在文件名中描述了数据结构和数值类型；MNIST 只是没有使用我们熟悉的 `.png` 或 `.jpg` 扩展名。

### 四个文件如何分工？

| 解压后的文件 | 内容 | 与另一个文件的关系 |
| --- | --- | --- |
| `train-images-idx3-ubyte` | 60,000 张训练图像 | 第 `n` 张图对应训练标签文件的第 `n` 个标签 |
| `train-labels-idx1-ubyte` | 60,000 个数字标签 | 每个标签是 `0～9` 中的一个整数 |
| `t10k-images-idx3-ubyte` | 10,000 张测试图像 | 第 `n` 张图对应测试标签文件的第 `n` 个标签 |
| `t10k-labels-idx1-ubyte` | 10,000 个数字标签 | 只在最终评估中与模型预测对照 |

图像文件和标签文件依靠**相同的顺序**建立关系，里面没有额外的图片文件名用来配对。例如，第 100 张训练图像的正确答案，就是训练标签文件中的第 100 个值。

### 图像 IDX 文件内部怎样存放灰度图？

图像文件可以简化理解为“文件头 + 连续的像素数据”：

```text
文件头
├── 格式标识
├── 图像数量
├── 每张图的行数：28
└── 每张图的列数：28
像素数据
├── 第 1 张图：784 个灰度值
├── 第 2 张图：784 个灰度值
└── ...
```

每张图有 `28 × 28 = 784` 个像素。每个像素在原始文件中是一个 `ubyte`（无符号 8 位整数，也就是 `uint8`），取值范围是 `0～255`：

- `0`：黑色背景；
- `255`：最亮的笔画；
- 中间数值：笔画边缘的灰度过渡。

绘图时有时会使用反转的灰度配色，把背景画成白色、笔画画成黑色。这只是显示方式改变，并不会改变原始像素数值。

标签 IDX 文件更简单：文件头记录标签数量，之后每个字节就是一张图的正确数字。

### torchvision 读取后发生了什么？

torchvision 帮我们解析 IDX 文件头，按索引取出某张图及其标签。使用 `ToTensor()` 后：

```text
IDX 中的单张图
`28 × 28` 个 uint8 像素，范围 0～255
        ↓ ToTensor()
PyTorch 单张图张量
shape = `[1, 28, 28]`，dtype = float32，范围 0～1
        ↓ DataLoader 组成 64 张的 batch
shape = `[64, 1, 28, 28]`
```

其中的 `1` 表示单通道灰度图；彩色 RGB 图像通常会有 3 个通道。标签不需要变成图像张量，64 张图对应的标签集合 shape 是 `[64]`。

### 为什么同时保留压缩和解压文件？

- `.gz` 体积较小，是下载到本地的原始分发形式，便于校验和重新解压。
- 无后缀 IDX 是解压后的可读取形式，torchvision 可以直接使用。
- 两者保存的是同一份数据，不代表数据集样本数翻倍；只是磁盘上同时有压缩版和解压版。

2026-09-02 使用 `torchvision 0.21.0+cpu` 以 `download=False` 直接读取本地文件，确认训练部分 60,000 张、测试部分 10,000 张。首个 64 样本 batch 的输入 shape 为 `[64, 1, 28, 28]`，标签 shape 为 `[64]`，输入是值域 0～1 的 `float32` 张量。

## 划分约定

- 从官方 60,000 张训练部分中，用固定随机种子 `42` 划分训练集与验证集。
- 已按 5:1 划分为 50,000 张训练、10,000 张验证：使用 PyTorch 独立随机生成器（种子 `42`）生成随机排列，前 50,000 个索引用于训练，其余用于验证。
- 索引保存在 `../outputs/tables/mnist_split_indices.json`，每类数量与检查结果保存在 `../outputs/tables/split_summary.json`。后续训练复用同一份索引；两部分无交集，共同覆盖全部 60,000 个样本。验证集各数字占比约为 8.75%～11.29%，没有明显失衡。
- 基于文件完整性和基础数据检查，当前无需额外清洗。训练图片与标签数量匹配，图像尺寸与类型符合预期，全部标签均在 `0～9`；像素零值不是缺失项。
- 官方 10,000 张测试部分不参与学习率、网络深度、batch size 或 epoch 的选择。
- 当前 E00 流程检查和 E01 基线训练使用同一份训练/验证索引，不为获得更好分数重新划分。
- 如需为 E00 使用小子集，必须单独保存索引与样本数，不将 E00 结果与正式实验比较。

## 输入处理约定

基线只将图像转为浮点张量，并将像素缩放到适合训练的数值范围。不做数据增强，不用测试部分计算任何归一化统计量。模型内部再将 batch 从 `[B, 1, 28, 28]` 展平为 `[B, 784]`。

本次数据探索已将以下内容记录到 `outputs/tables/dataset_overview.json`：

- 输入 shape、dtype、最小值和最大值；
- 标签 shape、dtype、最小值和最大值；
- 0～9 每类的样本数；
- 至少一组带真实标签的原始样例图。

类别统计和样例图只来自官方训练部分。官方测试部分在最终评估前只确认文件可读和总样本数，不查看图像、标签或类别分布。

## 仓库边界

原始数据、数据缓存和临时拆分文件不建议提交到 Git。仓库只保留数据说明、划分规则、必要的索引/元数据和不含敏感信息的小型图表。
