## 分类任务

输入一张主要包含一个物品的照片，输出它属于哪一类。先用现成的图片和标签完成分类，再用本地图片体验预测。摄像头是后续可选扩展。

迁移学习可以先理解为：借用一个已经从大量图片中学到视觉特征的模型，再训练它适应我们的几种类别。本案例固定预训练骨干参数和 BatchNorm 缓冲区，只训练最后负责分类的部分。

本案例先弄清三个问题：什么是预训练模型？怎样让它识别自己的类别？为什么换了背景以后可能识别错误？

## 数据从哪里来？

本案例使用 **TrashNet 的 3 类子集：纸张、纸板、金属**。运行时将完整六类图片准备在 `data/dataset-resized/`，三类样本路径与修正后标签放在 `data/selected_samples.json`，划分清单只引用原图，无需复制图片。来源、标签修正、数量与检查结果见 [数据说明](data/README.md)。

这里的类别按物品材料划分，例如“纸板”，不是按具体物品名称划分，例如“杯子”。如果更想做杯子、键盘等类别，后续可以更换数据集，整体学习流程仍然适用。

## 从数据加载到训练

`data.py` 返回一批图片和标签，模型将图片转成类别分数，训练再根据分数和标签更新参数。 ResNet18 的说明见 [概念笔记中的 ResNet18 小节](concepts.md#resnet18-是什么本案例具体用它做什么)。

| 步骤 | 要做什么 | 完成时应该看到什么 | 实现 |
| --- | --- | --- | --- |
| 1. 数据加载 | 读取固定清单，预处理图片并组成批次 | 图片 `[32, 3, 224, 224]`，标签 `[32]` | `src/data.py` |
| 2. 准备模型 | 加载 ResNet18 预训练参数，将最后的分类层改成三类，冻结前面的参数 | 只有新分类层的参数需要梯度 | `src/model.py` |
| 3. 单批前向传播 | 取训练集一批图片，调用 `logits = model(images)` | 有限的类别分数 `[32, 3]`，每行对应一张图片 | `src/model.py` |
| 4. 单批训练 | 用分数和标签计算损失，反向传播，再让优化器更新分类层 | 损失是有限数值，分类层参数发生变化，冻结部分保持固定 | `src/train_step.py` |
| 5. 按轮训练和验证 | 每轮遍历训练集更新参数，再遍历验证集检查效果 | 训练/验证损失与准确率记录，并保存验证表现较好的模型 | `src/train.py` |
| 6. 最终评估和预测 | 设置确定后评估测试集，再加载模型预测本地图片 | 测试指标、混淆矩阵、错误样本及单图预测 | `src/evaluate.py`、`src/predict.py` |

这里的 `32` 是完整批次的大小，最后一批可以更小。单批前向传播先用 `model.eval()` 配合 `torch.no_grad()` 检查输出；它只检查计算是否跑通，不会学习，新分类层此时预测不准很正常。标签不作为 `model(images)` 的输入，而是在计算损失时提供正确答案。

一次真正更新参数的训练步骤是：

```text
清空旧梯度：optimizer.zero_grad()
  ↓
图片 → 前向传播 model(images) → 类别分数 logits
                                  ↓ 与 labels 一起交给 CrossEntropyLoss
                                 loss
                                  ↓ loss.backward()
                                 梯度
                                  ↓ optimizer.step()
                             更新新分类层的参数
```

`CrossEntropyLoss` 直接接收原始分数和整数标签，前面不需要手动做 softmax。训练分类头时，不能把整个前向过程包进 `no_grad()`，否则分类头也无法记录梯度。

冻结 ResNet18 时还要注意：它包含 BatchNorm 层，即使参数不求梯度，在训练模式下仍可能更新运行统计量。实现让冻结的特征提取部分保持评估模式，分类头保持训练模式，优化器只接收分类头参数。具体区别见概念笔记第 11 节。

单批脚本检查求导和参数更新，`train.py` 完成按轮训练与验证，`evaluate.py` 单独评估测试集。未增强基线与增强版均已有三轮及测试记录，骨干微调没有实施。当前随机划分尚未经过近似图片分组检查，结果说明中保留这一限制。

本阶段选用 ResNet18 的 `IMAGENET1K_V1` 配套预处理，直接调用 `weights.transforms()`：短边缩放到 256，中心裁剪为 224×224，转为浮点张量，再按 RGB 各通道的均值和标准差标准化。标准化后数值可为负数或大于 1，这是正常的。中心裁剪可能舍去边缘内容。验证和测试使用上述确定性变换；训练集现在先做随机水平翻转和轻微亮度、对比度调整，再执行上述预处理。这个选择只建立预处理，不会下载模型权重，换模型时也要同步核对其输入要求。参见 [Torchvision 官方 ResNet18 文档](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)。

直接运行 `data.py` 只检查三个集合的首批格式并保存 `outputs/tables/dataloader_summary.json`，不计算测试集成绩。`train.py` 另建训练和验证加载器；已有测试成绩由 `evaluate.py` 单独生成。

## 准备 ResNet18 与单批前向传播

代码入口：[src/model.py](src/model.py)。建议依次阅读 `build_model()` 和 `main()`：

1. 创建原始 ResNet18 结构，完整加载官方 `IMAGENET1K_V1` 参数，与当前预处理对应。
2. 将旧参数设为 `requires_grad=False`。
3. 将 `fc` 替换为 `Linear(512, 3)`；新层默认可训练，包含 1,536 个权重和 3 个偏置。
4. 从训练加载器取一批真实图片，用 `eval()` 和 `no_grad()` 检查前向输出。

在本章目录运行：

```bash
python3 src/model.py
```

首次运行会从官方地址下载权重至 `outputs/pretrained/`，后续复用缓存；下载时校验文件名中的哈希前缀，加载失败会直接报错。缓存权重不提交 Git。原始预训练文件保留的是 1,000 类参数，新三分类头在每次构建模型时重新初始化，不是已经训练好的本案例模型。

`train_one_batch()` 每批调用 `set_head_training_mode(model)`，让冻结部分保持评估模式，避免 BatchNorm 运行统计量变化；分类头设置为训练模式。直接调用整个 `model.train()` 会把冻结部分也切到训练模式。现有优化器只接收分类头参数，训练前向保留求导图；损失、反向传播和更新由下面的 `loss.py`、`train_step.py` 实现，`train.py` 在整轮训练中复用它们。

实际检查通过：真实训练图片输入 `[32, 3, 224, 224]`，输出 `[32, 3]`，只有 `fc.weight` 和 `fc.bias` 共 1,539 个参数可训练。

## 损失函数：把分数与正确答案比较

已实现 [src/loss.py](src/loss.py)，`build_criterion()` 返回 `nn.CrossEntropyLoss(reduction="mean")`，供训练循环使用。核心只有两步：

```python
criterion = build_criterion()
loss = criterion(logits, labels)
```

`logits` 是模型输出的 `[B, 3]` 原始分数，`labels` 是 `[B]` 的 int64 正确类别编号。不要提前对分数做 softmax，也不要把标签转换为图片那样的浮点数。交叉熵会计算每张图片的损失，再取当前批次的平均值，得到一个标量张量（shape 为 `[]`）。正确类别对应的概率越高，该样本的交叉熵越小。

从 logits 到参数的具体数值见[分类头求导](head_gradients.md)：人为选定的 `h=[2,1]`、`z=[2,1,−1]` 与 `cardboard=1`，先计算交叉熵及三个分数梯度，再求 3×2 权重梯度和三个偏置梯度。实际批量均值及矩阵方向复用 [06 的反向链](../06_pytorch_networks/backpropagation.md)。

运行：

```bash
python3 src/loss.py
```

保存的未增强单批记录使用种子 42、新初始化分类头和训练集首批 32 张，平均损失约 **1.240659**；检查确认等于逐张损失的平均值，且保留了求导图。具体记录见 `outputs/tables/loss_summary.json`。当前脚本通过 `make_dataloaders()` 默认启用训练增强，重跑时输入和损失可能不同；这个单批数值不是准确率或完整训练成绩。

`loss.py` 的演示入口只计算损失，不执行 `loss.backward()` 或优化器更新。`train_step.py` 对原始 `loss` 张量求导；`loss.item()` 转成 Python 数字，只用于打印或保存。`train.py` 按实际批次样本数加权汇总整轮平均损失，避免不足 32 张的尾批占过大权重。

## 单批训练：反向传播与优化器更新

已实现 [src/train_step.py](src/train_step.py)。`train_one_batch()` 同时用于单批演示和 `train.py` 的整轮训练，每批执行以下步骤：

```python
set_head_training_mode(model)     # 前面保持 eval，分类头保持 train
optimizer.zero_grad(set_to_none=True)
logits = model(images)
loss = criterion(logits, labels)
loss.backward()                  # 计算梯度，写入参数的 .grad
optimizer.step()                 # 根据梯度修改参数
```

使用无动量、无权重衰减的 SGD，默认学习率 0.01，方便对照 `新参数 = 旧参数 - 学习率 × 梯度`。这只是起始设置，尚未通过验证集选择。优化器只管理 `fc.weight` 和 `fc.bias`。`zero_grad` 清掉旧梯度，避免下一批的梯度与上一批意外累加。

[二维手算示例](head_gradients.md#sgd-update)使用相同 SGD 规则，将损失从 `1.349012` 降至 `1.286911`；下面的 `1.240659 → 0.941231` 来自保存的真实图片单批记录。前者用于核对每个导数与更新，后者记录当时的数据、模型和训练配置，两组数字不应互相替代。

运行：

```bash
python3 src/train_step.py
```

保存的未增强单批记录使用种子 42、首批 32 张训练图片：更新前平均损失 **1.240659**，一次更新后同一批图片的平均损失 **0.941231**。当前脚本默认启用训练增强，重跑数值可能不同。`train_step.py` 检查分类头有有限梯度、更新符合 SGD 公式，并逐项验证特征提取参数及 BatchNorm 缓冲区不变。

`train_step.py` 的演示入口做两次前向传播：第一次计算用于反向传播的损失，第二次在 `no_grad()` 下观察更新后的同批损失；只有一次反向传播和一次优化器更新。这个演示不是完整 epoch，也不能据此判断验证集或新图片的效果；其他设置下单次更新也不保证损失下降。

单批结果保存到 `outputs/tables/train_step_summary.json`。该演示只更新一次参数，重新运行会从预训练骨干与随机初始化分类头开始；`train.py` 将相同更新过程放入整轮循环，再验证和保存权重。

## 按轮训练、验证与最佳模型保存

入口：[src/train.py](src/train.py)。模型、优化器和加载器在轮次循环外只创建一次，每轮通过已有的 `train_one_batch()` 遍历训练集，再在 `eval()` / `no_grad()` 下遍历验证集。训练每轮 31 批，验证 7 批；测试集不加载、不评估。

```bash
python3 src/train.py --no-augmentation
```

默认 3 轮、batch size 32、SGD 学习率 0.01、种子 42、CPU，默认启用训练增强；上面的 `--no-augmentation` 用于未增强基线。可使用 `--epochs`、`--batch-size`、`--learning-rate`、`--seed` 调整配置。默认每次创建独立的 `outputs/runs/<时间戳>/`，也可用 `--output-dir` 指定尚不存在的目录，避免覆盖旧实验。每次运行从预训练骨干和新分类头开始，不支持中途恢复训练。

每轮保存训练/验证损失及准确率。平均损失按样本数量加权，正确率按正确样本数除以总数计算。训练指标来自每批更新前的预测，因此对应一轮内不断变化的模型；验证指标来自该轮结束时的固定模型。

按**验证损失最低**选择最佳模型，相同时保留较早轮次：

- `history.json`：每轮指标、最佳轮次、配置、数据划分哈希及冻结状态检查结果。
- `best_model.pt`：最佳轮次的完整模型状态、类别映射、图片预处理配置和验证指标。它用于加载和推理，不是包含优化器与随机状态的断点续训文件。

每轮核对特征提取参数与 BatchNorm 缓冲区保持不变。最后重新构建模型、加载最佳权重，用相同验证输入检查输出一致。权重文件忽略 Git，保存在本地。仍需注意此前未完成近似图片分组检查，验证结果可能受此影响。

## 训练集随机增强

在 `src/data.py` 中阅读 `build_transform(training=True)`：先对读取到内存的 RGB 图片做随机水平翻转（概率 50%），再用 `ColorJitter` 调整亮度和对比度（两个因子分别在 0.9～1.1 内随机抽取），最后执行原有的 ResNet18 固定预处理。没有新增随机裁剪；原有中心裁剪仍可能舍去边缘内容。

每次取图重新抽取增强参数，不修改磁盘原图，不改变标签，也不增加每轮样本数。验证集、测试集和后续推理使用固定预处理。显式给 Dataset 传入自定义 `transform` 时，以自定义变换为准。

```bash
# 默认启用训练集增强；完整训练会创建新的实验目录
python3 src/train.py
# 关闭增强，便于与旧基线对比
python3 src/train.py --no-augmentation
```

实验配置中的 `preprocessing` 记录共用的固定预处理，`train_augmentation` 单独记录训练增强参数（关闭时为 null）。当前 `num_workers=0`，增强使用全局 PyTorch 随机状态，训练入口已调用 `torch.manual_seed(seed)`；DataLoader 的独立生成器用于取样顺序。相同种子、环境及调用顺序可以复现，不要每批或每轮重置种子，否则会重复随机序列。

未增强基线的验证准确率为 94.31%，增强版为 92.89%。单批演示启用增强后，图片输入与损失值也会改变。完整比较见[实验结果](results.md)。

## 自己拍的照片：单张推理

已实现 `src/predict.py`，默认加载增强版第 3 轮完整模型，不重新训练、不下载权重。在本章目录运行，将引号内的路径替换为自己的照片：

```bash
python3 src/predict.py "/绝对路径/我的照片.jpg"
```

支持 JPG、PNG 等 Pillow 可读取格式；HEIC 可先导出为 JPG。照片尽量以单个纸张、纸板或金属物品为主体，并置于画面中央（固定中心裁剪可能舍去边缘）。脚本修正手机 EXIF 方向，按模型记录缩放、中心裁剪、标准化，然后输出预测类别与三类 softmax 分数，不改变原图。

可通过 `--checkpoint` 指定其他完整模型文件。模型只在三类里选一个，没有“其他”类别；真实背景与训练图片不同可能误判，高分不代表一定正确。代码注释解释了模型加载、批次维度与推理模式。
