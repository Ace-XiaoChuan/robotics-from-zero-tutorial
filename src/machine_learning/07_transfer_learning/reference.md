## 本周要做什么？

输入一张主要包含一个物品的照片，输出它属于哪一类。先用现成的图片和标签完成分类，再用本地图片体验预测。摄像头是后续可选扩展。

迁移学习可以先理解为：借用一个已经从大量图片中学到视觉特征的模型，再训练它适应我们的几种类别。第一版可以先固定大部分模型参数，只训练最后负责分类的部分。

本周先弄清三个问题：什么是预训练模型？怎样让它识别自己的类别？为什么换了背景以后可能识别错误？

## 按什么顺序探索？

1. 看几张训练候选图片，理解标签，统计各类数量。
2. 检查重复或近似图片，再划分训练、验证和测试集。
3. 加载预训练模型，替换最后的分类部分，跑通一次小规模训练。
4. 尝试适度的数据增强：训练时随机改变图片外观，观察验证效果。
5. 确定设置后评估测试集，保存预测错误的图片并写下观察。
6. 加载保存的模型，对一张本地图片输出类别。

## 从数据加载到训练：接下来逐步做什么？

现在 `data.py` 已经能返回一批图片和标签。**下一步先让图片通过模型，得到类别分数，然后再接上学习过程。** ResNet18 的说明见 [概念笔记中的 ResNet18 小节](concepts.md#resnet18-是什么本周具体用它做什么)。

| 步骤 | 要做什么 | 完成时应该看到什么 | 当前状态 |
| --- | --- | --- | --- |
| 1. 数据加载 | 读取固定清单，预处理图片并组成批次 | 图片 `[32, 3, 224, 224]`，标签 `[32]` | 已完成：`src/data.py` |
| 2. 准备模型 | 加载 ResNet18 预训练参数，将最后的分类层改成三类，冻结前面的参数 | 只有新分类层的参数需要梯度 | 已完成：`src/model.py` |
| 3. 单批前向传播 | 取训练集一批图片，调用 `logits = model(images)` | 有限的类别分数 `[32, 3]`，每行对应一张图片 | 已完成：`src/model.py` |
| 4. 单批训练 | 用分数和标签计算损失，反向传播，再让优化器更新分类层 | 损失是有限数值，分类层参数发生变化，冻结部分保持固定 | 已完成：`src/train_step.py` |
| 5. 按轮训练和验证 | 每轮遍历训练集更新参数，再遍历验证集检查效果 | 训练/验证损失与准确率记录，并保存验证表现较好的模型 | 已完成：`src/train.py`，首次运行 3 轮 |
| 6. 最终评估和预测 | 设置确定后评估测试集，再加载模型预测本地图片 | 测试指标、混淆矩阵、错误样本及单图预测 | 测试评估已完成；单图预测待实现 |

这里的 `32` 是完整批次的大小，最后一批可以更小。单批前向传播先用 `model.eval()` 配合 `torch.no_grad()` 检查输出；它只检查计算是否跑通，不会学习，新分类层此时预测不准很正常。标签不作为 `model(images)` 的输入，而是在计算损失时提供正确答案。

一次真正更新参数的训练步骤是：

```text
清空旧梯度：optimizer.zero_grad()
  ↓
图片 → 前向传播 model(images) → 类别分数 logits
                                  ↓ 与 labels 一起交给 CrossEntropyLoss
                                 loss
                                  ↓ loss.backward()
                                 梯度
                                  ↓ optimizer.step()
                             更新新分类层的参数
```

`CrossEntropyLoss` 直接接收原始分数和整数标签，前面不需要手动做 softmax。训练分类头时，不能把整个前向过程包进 `no_grad()`，否则分类头也无法记录梯度。

冻结 ResNet18 时还要注意：它包含 BatchNorm 层，即使参数不求梯度，在训练模式下仍可能更新运行统计量。本周第一版计划让冻结的特征提取部分保持评估模式，分类头保持训练模式，优化器只接收分类头参数。具体区别见概念笔记第 11 节。

先通过单批检查，再运行少量训练轮次；观察验证结果后，才考虑训练集增强或微调。当前随机划分尚未经过近似图片分组检查，这个限制继续保留在评估记录中。

## 损失函数：把分数与正确答案比较

已实现 [src/loss.py](src/loss.py)，`build_criterion()` 返回 `nn.CrossEntropyLoss(reduction="mean")`，供后续训练复用。核心只有两步：

```python
criterion = build_criterion()
loss = criterion(logits, labels)
```

`logits` 是模型输出的 `[B, 3]` 原始分数，`labels` 是 `[B]` 的 int64 正确类别编号。不要提前对分数做 softmax，也不要把标签转换为图片那样的浮点数。交叉熵会计算每张图片的损失，再取当前批次的平均值，得到一个标量张量（shape 为 `[]`）。正确类别对应的概率越高，该样本的交叉熵越小。

运行：

```bash
/home/ace/mujoco-env/bin/python 07_transfer_learning/src/loss.py
```

实际使用种子 42、新初始化分类头和训练集首批 32 张，得到平均损失约 **1.240659**；检查确认等于逐张损失的平均值，且保留了反向传播所需的计算图。它不是准确率，也不是训练完成后的成绩。具体记录见 `outputs/tables/loss_summary.json`。

本脚本只计算损失，不执行 `loss.backward()` 或优化器更新。后续反向传播要使用原始 `loss` 张量；`loss.item()` 转成 Python 数字，只用于打印或保存。汇总整轮平均损失时，应按实际批次样本数加权，避免不足 32 张的尾批占过大权重。

## 单批训练：反向传播与优化器更新

已实现 [src/train_step.py](src/train_step.py)。先阅读 `train_one_batch()`，它就是接下来的训练循环中，每一批都要执行的步骤：

```python
set_head_training_mode(model)     # 前面保持 eval，分类头保持 train
optimizer.zero_grad(set_to_none=True)
logits = model(images)
loss = criterion(logits, labels)
loss.backward()                  # 计算梯度，写入参数的 .grad
optimizer.step()                 # 根据梯度修改参数
```

使用无动量、无权重衰减的 SGD，默认学习率 0.01，方便对照 `新参数 = 旧参数 - 学习率 × 梯度`。这只是起始设置，尚未通过验证集选择。优化器只管理 `fc.weight` 和 `fc.bias`。`zero_grad` 清掉旧梯度，避免下一批的梯度与上一批意外累加。

运行：

```bash
/home/ace/mujoco-env/bin/python 07_transfer_learning/src/train_step.py
```

种子 42、首批 32 张训练图片的实测结果：更新前平均损失 **1.240659**，一次更新后同一批图片的平均损失 **0.941231**。脚本检查分类头有有限梯度、更新符合 SGD 公式，并逐项验证特征提取参数及 BatchNorm 缓冲区不变。

整个脚本做两次前向传播：第一次计算用于反向传播的损失，第二次在 `no_grad()` 下观察更新后的同批损失；只有一次反向传播和一次优化器更新。这不是完整 epoch，也不能据此判断验证集或新图片的效果，其他设置下单次更新也不保证损失下降。

记录保存到 `outputs/tables/train_step_summary.json`。当前只做一步实验，不保存训练后的模型权重；重新运行会从官方预训练骨干和种子 42 初始化的新分类头开始。下一步将 `train_one_batch()` 放进遍历训练加载器的循环，再添加按轮验证与模型保存。

每轮保存训练/验证损失及准确率。平均损失按样本数量加权，正确率按正确样本数除以总数计算。训练指标来自每批更新前的预测，因此对应一轮内不断变化的模型；验证指标来自该轮结束时的固定模型。

按**验证损失最低**选择最佳模型，相同时保留较早轮次：

- `history.json`：每轮指标、最佳轮次、配置、数据划分哈希及冻结状态检查结果。
- `best_model.pt`：最佳轮次的完整模型状态、类别映射、图片预处理配置和验证指标。它用于加载和推理，不是包含优化器与随机状态的断点续训文件。

每轮核对特征提取参数与 BatchNorm 缓冲区保持不变。最后重新构建模型、加载最佳权重，用相同验证输入检查输出一致。权重文件忽略 Git，保存在本地。仍需注意此前未完成近似图片分组检查，验证结果可能受此影响。
