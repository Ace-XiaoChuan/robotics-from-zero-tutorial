# 数据集说明

本文行数：56行，预期阅读时长：3分钟

数据集与划分文件需要运行时准备。来源、类别与固定划分说明如下。

## TrashNet

[作者仓库与数据说明](https://github.com/garythung/trashnet)提供已经标注的生活废弃物图片，共 2,527 张、6 类，缩放版图片尺寸为 512 × 384：

| 标签 | 中文含义 | 图片数 |
| --- | --- | --- |
| glass | 玻璃 | 501 |
| paper | 纸张 | 594 |
| cardboard | 纸板 | 403 |
| plastic | 塑料 | 482 |
| metal | 金属 | 410 |
| trash | 其他垃圾 | 137 |

建议先选 `paper`、`cardboard`、`metal` 三类，共 **1,407 张**。规模较小，适合先体验完整流程；纸张与纸板之间的混淆也可以作为错误分析的素材。这是本项目的入门建议，并非作者规定的分类组合。

标签就是每张图片对应的正确类别。原始项目已提供分类数据，后续用代码读取类别即可，不需要重新逐张标注。下载入口见作者 README 的 Dataset 部分；项目可以只使用图片，用我们自己的 PyTorch 代码学习。

## 使用时理解两个局限

- 作者是在白色背景板上拍摄物品的，因此该数据上的成绩不能直接代表杂乱桌面或摄像头场景中的效果。
- 标签描述的是材料类别，不是当地垃圾投放规则；本案例任务是图片分类练习。

## 划分原则与当前实施

先检查重复和近似图片。如果能识别同一个物品或同一拍摄组，应把它们放在同一个集合里；不能只依靠随机打乱保证没有泄漏。

在这个前提下，尽量保持各类比例，按约 70% / 15% / 15% 划分训练、验证和测试集，并保存划分记录。训练集用于学习，验证集用于选择设置，测试集用于最终评估。数据增强只用于训练集，并在划分之后进行。

## 文件校验与标签问题

- 下载地址：[作者仓库 dataset-resized.zip](https://raw.githubusercontent.com/garythung/trashnet/master/data/dataset-resized.zip)。来源为 `master` 分支，以下 SHA-256 标识实验使用的数据包。
- 压缩包：`dataset-resized.zip`，42,834,870 字节（约 40.85 MiB）。
- SHA-256：`0bf472790f8b20e5c950d5b5012a9d38af0d3392efd65f8ce171334fc16b07c2`。
- 图片目录：`dataset-resized/<类别名>/*.jpg`，仅解压图片，跳过压缩包中的系统辅助文件。
- ZIP 内部 CRC 校验通过；全部 2,527 张图片均能完整解码，均为 RGB、宽 512 × 高 384。
- 下载时的三类数量为纸张 594、纸板 403、金属 410，共 1,407 张。运行时在本目录准备 `selected_samples.json`，保存原图相对路径和实际训练标签。

实验清单将 `dataset-resized/paper/paper201.jpg` 的标签改为 `metal`：用户已确认这张图是金属，原图路径保留，清单条目记录 `original_label` 和 `correction_reason`。修正后三类数量为纸张 **593**、纸板 **403**、金属 **411**，总数仍为 1,407；[图片检查结果](../outputs/tables/inspection_summary.json)和训练/验证/测试划分使用这组标签，不能只按原始目录名称重建标签。

完整六类数据中发现 3 组文件内容完全相同、但类别不同的图片：

| 图片一 | 图片二 |
| --- | --- |
| `glass/glass115.jpg` | `metal/metal91.jpg` |
| `glass/glass176.jpg` | `plastic/plastic152.jpg` |
| `glass/glass389.jpg` | `plastic/plastic332.jpg` |

本案例三类子集内部未发现文件内容完全相同的重复图片。`metal91.jpg` 在完整数据中存在跨类别标注冲突，后续清洗时需检查。哈希检查不能排除不同角度、裁剪或压缩后的近似图片，尚未做近似图片检查。

切分脚本将划分保存在 `splits/`：训练 984、验证 211、测试 212，种子 42。已验证路径互不重叠且完整覆盖清单。实验采用分层随机划分，尚未按近似图片或物品分组。
