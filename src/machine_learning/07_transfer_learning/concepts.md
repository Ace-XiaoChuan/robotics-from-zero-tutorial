## 1. 这次属于哪一种机器学习？

每张图片都有一个正确类别，我们用图片和答案训练模型，所以这是**监督学习中的图像分类任务**。模型选用卷积神经网络（CNN），训练方式采用迁移学习。

| 概念 | 回答的问题 | 本案例的例子 |
| --- | --- | --- |
| 任务 | 想让计算机做什么？ | 判断照片中的物品是纸张、纸板还是金属 |
| 模型 | 用什么结构处理输入？ | 卷积神经网络 CNN |
| 训练方式 | 怎样得到适合本任务的参数？ | 在已有预训练模型的基础上迁移学习 |
| 损失函数 | 怎样衡量预测与答案的差距？ | 多分类交叉熵 |
| 优化器 optimizer | 怎样根据梯度调整参数？ | 延续第六章对优化器的理解 |

迁移学习不是与 KNN、决策树、神经网络并列的第四种模型。它是一种利用已有学习成果的方法。

## 2. 分类、检测和分割有什么区别？

日常说的“物品识别”可能指不同任务：

| 任务 | 输出什么？ | 例子 |
| --- | --- | --- |
| 图像分类 | 整张图片的类别 | 这张图属于金属类 |
| 目标检测 | 物体类别和位置框 | 金属罐位于图片左上角 |
| 图像分割 | 每个像素属于什么区域 | 标出金属罐的完整轮廓 |

本案例先做分类：一张图片以一个物品为主，输出三个类别之一。模型不会自动给出物体的位置，也不能直接完成“找出桌上所有物品”。即使以后接入摄像头，逐帧分类仍然是分类任务。

## 3. 从灰度数字到彩色照片，输入变了什么？

第六章的 MNIST 是单通道灰度图，单张张量形状为 `[1, 28, 28]`。本案例的图片有红、绿、蓝三个颜色通道，也就是 RGB。

原始 TrashNet 图片宽 512、高 384。读成 PyTorch 常用的通道在前的布局后，单张形状是 `[3, 384, 512]`。注意文件尺寸常写“宽 × 高”，张量则常写“通道、高、宽”。

为了组成一批图片，并匹配选定模型的输入处理方式，通常会统一输入尺寸。本案例采用 `224 × 224`：

```text
单张图片：[3, 224, 224]
一批图片：[B, 3, 224, 224]
一批标签：[B]
模型输出：[B, 3]
```

这里 `B` 是 batch size。输入中的 `3` 是颜色通道数，输出中的 `3` 是类别数，两者只是恰好相同。`224` 是示例尺寸，不是所有 CNN 的强制要求。

## 4. 为什么这次用 CNN？

第六章的全连接网络先用 Flatten 把图片铺成一行。像素数值还在，但网络没有专门利用“附近像素组成局部形状”这一特点。物品稍微移动，同一形状就会落在不同的输入位置。

CNN 会用小窗口观察局部区域，并让同一组参数在图片不同位置重复使用。这样，检测某种边缘的规则可以用于图片左边，也可以用于右边。

KNN 和决策树也可以用于图片分类，但直接把大量原始像素交给它们，通常不容易处理位置、光照和背景变化。它们也可以接收 CNN 提取的特征，不过本案例先沿用神经网络训练流程，理解起来更连贯。

## 5. 卷积核、卷积和特征图

### 卷积是什么？

在 CNN 中，可以先把**卷积（convolution）**理解为一种“用同一组小窗口权重，逐块处理图片”的计算：**取出一个局部区域，将像素与对应位置的权重相乘，再把乘积相加；随后移动窗口，重复这个过程。** 在标准卷积层中，**同一个卷积核在一次前向计算中，无论滑动到图片的哪个位置，其内部的整组权重都保持不变，这就是权重共享**。卷积核内部不同位置的权重可以不同；权重对应的是窗口内的位置，而不是图片中某个固定的像素，所以同一个像素在不同窗口中可能乘以不同的权重。这里的“一次”指一次前向计算，并非整个训练轮次（epoch）；训练时，优化器会在更新参数时调整这些权重。

图片本身是一张数字表，因此这个过程最终会产生另一张数字表。它可以突出某些局部变化，例如相邻位置的亮度差异，为后续识别提供信息。卷积这一步本身不直接判断“这是纸张还是金属”。

### 卷积核是什么？

**卷积核（kernel/filter）**可以理解为一组可学习的小窗口权重。它在图片上移动，每到一个位置，就对覆盖范围内的数值加权求和；这一层也可能加入偏置。

也就是说，**卷积是计算操作，卷积核是这个操作使用的权重**。同一个卷积核在一次前向计算中移动到不同位置时，使用相同的权重；训练时，优化器才会根据梯度更新这些权重。

例如，单通道输入上的一个 `3 × 3` 卷积核，一次观察附近 9 个像素。处理 RGB 图片时，一个普通卷积核还会同时结合三个输入通道的信息，而不只是单独看某一种颜色。

### 手算一次卷积

为了看清过程，假设有一张 `3 × 3` 的单通道图片，使用一个 `2 × 2` 的卷积核。窗口每次移动一格，不在边缘补数，暂时不加偏置：

```text
输入图片          卷积核
1  2  3           1  0
4  5  6           0 -1
7  8  0
```

先把窗口放在左上角，覆盖 `[[1, 2], [4, 5]]`，对应位置相乘后求和：

```text
1×1 + 2×0 + 4×0 + 5×(-1) = -4
```

再向右移动一格，覆盖 `[[2, 3], [5, 6]]`：

```text
2×1 + 3×0 + 5×0 + 6×(-1) = -4
```

接着处理下一行的两个位置：

```text
左下：4×1 + 5×0 + 7×0 + 8×(-1) = -4
右下：5×1 + 6×0 + 8×0 + 0×(-1) =  5

按窗口的位置排列结果：
-4  -4
-4   5
```

这就是一张 `2 × 2` 的输出特征图。这个示例卷积核实际计算的是每个局部区域“左上值减右下值”，因此可以反映这两个位置的数值差异。负数是正常计算结果；是否接着用 ReLU 将负数变为零，是下一步激活函数的事情。

这里的权重是为了演示手工选择的。实际 CNN 中的权重通常通过训练学得，使用预训练模型时则从已学好的权重开始。

术语补充：严格数学定义中的卷积会先翻转卷积核；上面这种不翻转的计算叫“互相关”。深度学习里通常仍把这种层称为卷积层。本案例按上面的计算方式理解即可。

### 从卷积到特征图

```text
局部像素 + 卷积核权重
         ↓ 加权计算
这个位置的一个响应值
         ↓ 窗口移到其他位置，继续计算
一张特征图
```

**特征图（feature map）** 是某种计算在不同位置上的响应。它仍有空间布局，但其数值已经不再直接表示原图的红、绿、蓝亮度。

例如，沿用上面的手算结果，一个卷积核在四个窗口位置各算出一个数，按窗口的位置排起来，就得到一张特征图：

```text
窗口位置及计算结果                 特征图
左上窗口 → -4，右上窗口 → -4       -4  -4
左下窗口 → -4，右下窗口 →  5       -4   5
```

特征图右下角的 `5`，对应原图右下方的局部区域 `[[5, 6], [8, 0]]`，表示这个区域经过卷积核计算后的响应：`5×1 + 6×0 + 8×0 + 0×(-1) = 5`。它不是原图某个像素的亮度，也不是分类概率；这里表示该区域左上值比右下值大 `5`。**特征图中的每一个数，都对应卷积核在一个窗口位置的计算结果。**

一层通常有多个卷积核，产生多个输出通道。可以先把它们理解为不同的特征观察方式。训练时，卷积核权重是通过损失、反向传播和优化器学出来的，不需要我们手工规定“这个核专门识别纸板”。

常见直觉是：较浅的层关注边缘、颜色或纹理，较深的层组合更复杂的信息。但实际特征通常由多个通道共同表示，不一定能给每个通道起一个明确的人类名称。

## 6. 步幅、填充、激活和池化

阅读 CNN 结构时，经常遇到以下词语。先掌握作用即可，不必立即计算每一层尺寸。

| 概念 | 直觉理解 | 主要作用 |
| --- | --- | --- |
| 步幅 stride | 窗口每次移动几格 | 步幅增大通常会缩小输出的空间尺寸 |
| 填充 padding | 在输入边缘补一些数值 | 控制边缘处理和输出尺寸；常见的是补零 |
| 激活函数，如 ReLU | 对计算结果进行非线性变换 | 让多层网络表达更复杂的关系 |
| 池化 pooling | 将局部区域汇总成一个数 | 压缩空间尺寸、汇总信息 |
| 全局平均池化 | 每个通道的所有位置取平均 | 把空间特征汇总成一组数 |

### 池化是什么？先手算一张特征图

**池化（pooling）就是按指定规则，把一个区域里的多个数汇总成一个数。** 在 CNN 中，它通常作用于卷积之后的特征图。常见的最大池化取区域内最大值，平均池化取区域内平均值。

假设有下面这张 `4 × 4` 特征图，使用 `2 × 2` 的池化窗口，每次移动两格（`stride=2`），不填充。竖线和横线只是帮助看清四个窗口：

```text
输入特征图
1  3 | 2  0
2  4 | 6  2
-----+-----
5  1 | 8  4
3  7 | 2  6
```

**最大池化（max pooling）**在每个窗口取最大值：

```text
左上：max(1, 3, 2, 4) = 4     右上：max(2, 0, 6, 2) = 6
左下：max(5, 1, 3, 7) = 7     右下：max(8, 4, 2, 6) = 8

输出特征图：
4  6
7  8
```

原来的 `4 × 4` 变成 `2 × 2`。每个输出值表示对应区域内的最强响应，但其他数值以及最大值在窗口内的具体位置不再直接保留。

**平均池化（average pooling）**使用同样的窗口，改为取平均：

```text
左上：(1+3+2+4)/4 = 2.5     右上：(2+0+6+2)/4 = 2.5
左下：(5+1+3+7)/4 = 4       右下：(8+4+2+6)/4 = 5

输出特征图：
2.5  2.5
4    5
```

它概括的是区域内的平均响应。两种池化都会丢失部分细节；缩小特征图可以降低后续计算量，但也可能损失识别小物体所需的信息。这里尺寸减半是因为选择了 `2 × 2` 窗口、步幅 2、不填充，不能认为所有池化都一定减半。

### 池化会把不同通道混在一起吗？

常见二维最大池化和平均池化对**每张图片的每个通道分别处理**，不会把 RGB 三个通道或不同图片混在一起。例如上述设置作用于 32 张、每张有 64 个通道的特征图：

```text
[32, 64, 4, 4] → 池化 → [32, 64, 2, 2]
 图片数、通道数不变；高度、宽度缩小。
```

### 全局平均池化：一整个通道汇总成一个数

**全局平均池化（global average pooling）**把每个通道的所有空间位置取平均。以上面原始 `4 × 4` 特征图为例，16 个数总和为 `56`，输出就是 `56 / 16 = 3.5`。

本案例 ResNet18 最后有 512 个通道，每个通道的特征图为 `7 × 7`，因此会得到 512 个平均值：

```text
[B, 512, 7, 7] → 全局平均池化 → [B, 512, 1, 1]
                                      ↓ Flatten
                                  [B, 512]
```

这里池化负责计算平均值，Flatten 负责把剩下的维度展开，得到分类头要用的特征向量。第七节会用两张小特征图继续演示这个过程。

### 池化、卷积、Flatten 有什么不同？

| 操作 | 怎样处理数字 | 是否有需要学习的权重和偏置 |
| --- | --- | --- |
| 卷积 | 将窗口内数值乘以卷积核权重，再求和，可加偏置 | 有 |
| 常见最大/平均池化 | 按预设规则取最大值或平均值 | 没有 |
| Flatten | 按顺序展开数字，不计算区域汇总值 | 没有 |

池化的窗口大小和步幅是我们选择的设置，不是训练出来的权重。**没有可训练参数不代表阻断反向传播**：最大池化把梯度传给取得最大值的输入位置（并列时由实现选择），平均池化将梯度分配到参与平均的输入位置，所以前面的卷积层仍然能够学习。

### 池化与感受野

经过多层卷积，每个较深位置能受到更大范围输入的影响，这个范围称为**感受野**。模型因此可以逐渐结合更广的上下文。

池化和卷积有助于处理一定程度的位置变化，但不能保证物体无论怎样移动、旋转或遮挡都能被识别。

## 7. 特征提取部分和分类头

**一张图片进入分类网络后，先被算成一组数字，再用这组数字计算“纸张、纸板、金属”的分数。** 我们把前面负责处理图片的部分叫“特征提取部分”，把最后负责给类别打分的部分叫“分类头”。它们是同一个网络里前后连接的两部分。

```text
一张图片 → 特征提取部分 → 一组数字 → 分类头 → 三个类别分数
```

下面只跟着一张图片走一遍。所有数字都是为了方便手算而假设的，不是真实模型的运行结果。

### 1. 前半部分：把图片算成一组数字

前面已经学过：**一个卷积核滑过图片，会算出一张特征图；多个卷积核可以算出多张特征图。** 网络后面的卷积层会接着处理前面的特征图，中间也可以有 ReLU、池化等操作。

假设这张图片经过前面的多层处理，最后得到两张特征图：

```text
特征图 A          特征图 B
1  3              0  2
2  2              0  2
```

接着使用刚学过的全局平均池化，每张图取一个平均值：

```text
A 的平均值 = (1+3+2+2)/4 = 2
B 的平均值 = (0+2+0+2)/4 = 1

按 A、B 的顺序放在一起：[2, 1]
```

**这就是“提取特征”在这个例子里做的事：把图片经过一连串计算，变成 `[2, 1]`。** 这一串数字叫“特征向量”。这里的“向量”先理解为一排数字就可以。

`2` 是 A 这张特征图的平均响应，`1` 是 B 的平均响应。它们不是“有两张纸、一块金属”，也不是“纸张得 2 分、纸板得 1 分”。此时还没有按类别打分。

这里还有一个容易混淆的地方：**`[2, 1]` 是这张图片算出来的结果，不是卷积核的权重。** 换一张图片，即使用同样的卷积核权重，通常也会算出不同的特征数字。至于 A、B 各自能不能叫“边缘”“纹理”，不必强行给它们起名字。

完成前面这些计算的网络部分，就是**特征提取部分（backbone）**。

### 2. 后半部分：用这组数字给三个类别打分

现在图片已经变成 `[2, 1]`，接下来需要回答：根据这两个数字，三个类别各得多少分？

这由**分类头（classifier/head）** 完成。“头”是习惯名称，在这里指网络末尾负责输出类别分数的部分。本案例使用的分类头就是第六章解释的 **Linear 全连接层**。

每个类别都有自己的打分公式，形式仍然是“乘权重、求和、加偏置”。假设分类头的参数如下：

| 类别 | 第一个数字乘什么权重 | 第二个数字乘什么权重 | 最后加的偏置 |
| --- | --- | --- | --- |
| 纸张 | 1 | 0 | 0 |
| 纸板 | 0 | 1 | 0 |
| 金属 | -1 | 1 | 0 |

三个类别使用的是**同一组输入 `[2, 1]`**，但各有一组权重：

```text
纸张分数 = 2×1    + 1×0 + 0 = 2
纸板分数 = 2×0    + 1×1 + 0 = 1
金属分数 = 2×(-1) + 1×1 + 0 = -1

按纸张、纸板、金属的顺序，输出：[2, 1, -1]
```

纸张的分数最高，因此这一次预测为“纸张”。这是模型的预测，不代表一定正确；要和真实标签比较，才知道有没有判断对。这些分数叫 logits，可以为负数，不是概率。

表中的权重是演示用的。真正训练时，优化器会调整分类头的权重和偏置，让正确类别更容易得到较高分。

### 3. 把两部分连起来看

```text
同一张图片
  ↓ 前半部分：多层卷积、激活等处理
两张特征图 A、B
  ↓ 每张图取平均
[2, 1]             ← 这张图片的特征数字，还没有类别含义
  ↓ 后半部分：三个类别分别加权求和、加偏置
[2, 1, -1]         ← 纸张分数、纸板分数、金属分数
  ↓ 选最高分
预测为纸张
```

前半部分的卷积核有自己的权重，后半部分的全连接层也有自己的权重。**它们不是同一组权重：前者用于计算特征，后者用于根据特征打分。**

这也解释了本案例为什么能“保留前面、换掉最后”：我们希望借用预训练模型已经学好的图片处理能力，再训练一个适合纸张、纸板、金属的新分类头。先冻结前面时，它仍然照常计算特征，只是参数暂时不更新。

### 4. 再对应到本案例代码中的形状

上面为了手算，只让一张图片得到 2 个特征数字。本案例的 ResNet18 会让每张图片得到 **512 个特征数字**，再交给一个输出 3 个分数的 Linear 层：

```text
一张图片：512 个特征数字 → 3 个类别分数
32 张图片：[32, 512]    → [32, 3]
```

这里每一行都属于一张图片。`512` 表示每张图片有多少个特征数字，`3` 表示我们要区分多少个类别。前面概念中写的 `D` 就是特征数字的个数，在本案例 ResNet18 中 `D = 512`。第八节会继续解释预训练模型和 ResNet18。

## 8. 预训练模型到底提供了什么？

**预训练模型，就是一个已经在其他数据上训练过、保存了训练所得参数的模型。** 使用它时，我们把这些参数读进网络，作为新任务的起点。

### 它给我们的，具体是什么？

你前面已经知道，卷积层会学习卷积核的权重和偏置。假设某个单通道 `2 × 2` 卷积核在训练前后的参数如下（数字仅用于示意，并非真实模型参数）：

```text
随机初始化时：             在原数据集上训练后：
权重                      权重
 0.02  -0.01               0.7  -0.6
 0.03   0.01               0.8  -0.7
偏置：0                   偏置：0.1
```

右边这组权重会把窗口左侧像素乘以正数、右侧像素乘以负数，因此能对“左侧亮、右侧暗”的变化产生较大的正响应。**加载预训练参数，就是直接使用右边这类已经学过的数值开始计算。** 实际模型会保存许多层的参数，其中的特征也比这个小例子复杂得多。

模型的**结构**规定有多少层、卷积核多大、各层如何连接；模型的**参数**则是计算时使用的具体数值。同一种结构，可以配随机初始化的参数，也可以加载预训练参数。两者开始训练时的能力不同。

### 原来学的任务不同，为什么还能用？

假设一个模型原先训练的是猫、狗、汽车等图片分类。为了做好这个任务，它学到的一部分计算可以提取边缘、纹理、形状等信息。我们的纸张、纸板、金属图片中，也有这些视觉信息，所以其中一些计算仍然有用。

但原来的分类头输出的是原任务的类别分数。它不能直接当作我们的三个类别分数使用。因此，本案例这样处理：

```text
原来的模型：
图片 → 已训练的特征提取部分 → 原分类头 → 原任务的类别分数

用于本案例任务：
图片 → 保留的特征提取部分 → 新分类头 → 纸张、纸板、金属的分数
       加载预训练参数        初始化后需要训练
```

沿用第七节的例子，特征提取部分把一张图片变成 `[2, 1]`。**新分类头仍然需要学习：这组特征出现时，应该给纸张、纸板、金属各打多少分。** `[2, 1]` 本身并没有写着“这是纸张”。

### 和从零训练相比，少学了什么？

| 方式 | 特征提取部分的起点 | 新分类头的起点 | 本案例任务中更新什么 |
| --- | --- | --- | --- |
| 从零训练 | 随机初始化，尚未学到有用的视觉特征 | 尚未学会三个类别 | 特征提取部分和分类头一起训练 |
| 加载预训练参数，冻结特征提取部分 | 已从原任务学到一些视觉特征 | 尚未学会三个类别 | 只训练新分类头 |
| 加载预训练参数，再微调 | 已从原任务学到一些视觉特征 | 尚未学会三个类别，或已单独训练过 | 训练分类头，并调整部分或全部特征提取参数 |

### ResNet18 是什么？本案例具体用它做什么？

**ResNet18 是一种已经设计好的卷积神经网络结构。** 它规定图片依次经过哪些卷积、激活、池化等操作。我们直接使用 Torchvision 的实现，不需要自己逐层搭建；再加载 `IMAGENET1K_V1` 权重，就得到曾在 ImageNet 的 1,000 类图片任务上训练过的模型。**ResNet18 是结构名称，预训练权重是装进这个结构里的参数数值。** `data.py` 调用这套权重配套的预处理；`model.py` 负责加载参数、替换三分类头和前向检查，`train.py` 负责训练。历史记录已包含三轮分类头训练，模型构建本身不等于训练。[官方模型说明](https://docs.pytorch.org/vision/0.21/models/generated/torchvision.models.resnet18.html)

#### 名字里的 ResNet 和 18 分别是什么意思？

ResNet 是 Residual Network，即“残差网络”。它仍属于 CNN，特点是在部分计算中加入一条跳跃连接，让输入可以绕过几层计算，再与计算结果相加。

`18` 按通常的命名口径，指主路径上的 17 个卷积层加最后 1 个全连接层。它不是 18 个卷积核，也不是 18 个类别；激活、池化、BatchNorm，以及部分捷径中的投影卷积，不按这个命名口径额外计数。[原论文](https://arxiv.org/abs/1512.03385)

#### 残差连接：把原来的信息加回来

先看输入、输出形状相同的一个残差块。令输入特征为 `x`，经过块内卷积等操作得到 `F(x)`：

```text
输入 x ──→ 卷积等操作，得到 F(x) ──→ 相加 ──→ ReLU ──→ 输出
   └──────── 原样传递 x ────────────↑
```

这里的相加是对应位置相加。用两个数字模拟特征张量中的两个位置（仅为演示，不是真实模型输出）：

```text
输入 x：             [2.0, 1.0]
卷积分支输出 F(x)：   [0.3, -0.2]
相加 x + F(x)：      [2.3, 0.8]
经过 ReLU：         [2.3, 0.8]
```

可以把 `F(x)` 理解为网络学到的一份调整量：在传来的特征基础上增加或减少一些响应。它不是“预测标签减真实标签”的误差，也不是损失函数。跳跃连接为信息和梯度提供了更直接的路径，有助于较深网络的优化；并不是跳过训练或保证不会出错。[原论文对残差学习的解释](https://arxiv.org/abs/1512.03385)

实际 ResNet18 的一个基本残差块含两层主分支卷积。若输入输出的空间尺寸或通道数不同，捷径会先做变换来对齐形状，再相加；不能把不同形状的特征图直接相加。[与本地版本对应的 Torchvision 实现](https://github.com/pytorch/vision/blob/v0.21.0/torchvision/models/resnet.py)

#### 对本案例的一批图片，它会输出什么？

沿用第七节“特征图 → 特征向量 → 类别分数”的过程，本案例标准 `224 × 224` 输入经过 ResNet18 时可以这样看：

```text
图片 [B, 3, 224, 224]
  ↓ 初始卷积、池化和四组残差块
最后的特征图 [B, 512, 7, 7]
  ↓ 全局平均池化：每张 7×7 特征图取平均
[B, 512, 1, 1]
  ↓ 展平：每张图片得到 512 个特征数字
[B, 512]
  ↓ 最后的全连接层 fc
原模型：[B, 1000]      本案例替换后：[B, 3]
```

`512` 是这里的特征向量长度，不是类别数。原来的 `fc` 用这 512 个数计算 1,000 类分数；[model.py](src/model.py) 已将它替换为 `nn.Linear(512, 3)`，计算纸张、纸板、金属三个分数。这是本实现的结构对应关系。[Torchvision 源码](https://github.com/pytorch/vision/blob/v0.21.0/torchvision/models/resnet.py)

新分类层有 `512 × 3 = 1,536` 个权重和 `3` 个偏置，共 **1,539 个可训练参数**。先冻结前面的特征提取部分，只学习这 1,539 个参数。这里的“冻结”是保持参数固定，图片仍然要经过前面的网络才能变成 512 个特征数字。

对应的前向传播检查是：**把 `[32, 3, 224, 224]` 送入改好的模型，确认得到 `[32, 3]`。** 新分类层从初始化参数开始，输出格式正确不表示已经学会分类；还要接着计算损失、反向传播并更新参数。

## 9. 从零训练、冻结训练和微调

| 方式 | 从哪里开始？ | 哪些参数会更新？ |
| --- | --- | --- |
| 从零训练 | 通常从随机参数开始 | 训练整个网络 |
| 冻结特征提取部分 | 使用预训练参数，建立新分类头 | 先只更新分类头 |
| 微调 fine-tuning | 在预训练参数基础上继续学习 | 更新部分或全部特征提取参数，以及分类头 |

**冻结**表示让指定参数保持固定。前面的网络仍然执行计算，为图片提取特征；不是跳过前面这些层，也不是把它们的输出变成零。

本案例先采用“冻结特征提取部分，只训练分类头”。这能缩小需要学习的参数范围，让我们先看清完整流程。它仍需要运行 CNN 的前向计算，因此并不等于没有计算成本。

后续如果想探索微调，可以解冻靠后的部分层，用较小的学习率尝试调整。较小的步幅有助于避免已有参数变化过大，但最终是否更好要看验证结果。解冻以后，也要确保优化器包含这些新加入训练的参数。

## 10. 优化器在这次训练中做什么？

第六章的训练逻辑仍然成立：

```text
取出图片和标签
  ↓
清空之前的梯度
  ↓
前向传播，得到三个类别分数
  ↓
计算交叉熵损失
  ↓
反向传播，计算需要训练的参数的梯度
  ↓
优化器依据梯度更新这些参数
```

当特征提取部分被冻结时，优化器主要调整分类头。可以把它理解成：前面已经把图片整理成一组特征，我们学习怎样根据这些特征给三个类别打分。

**模型负责计算预测，损失函数衡量差距，反向传播计算梯度，优化器真正更新参数。**它们的职责与第六章相同。

### SGD 是什么？怎样根据梯度更新参数？

**SGD 是 Stochastic Gradient Descent 的缩写，中文叫“随机梯度下降”。它是一种优化器，负责根据梯度修改参数。** 当前 `train_step.py` 使用的是最基础的 SGD，没有加入动量或权重衰减。

先把两个步骤分清楚：

```python
loss.backward()   # 反向传播：算出梯度，放在参数的 .grad 中
optimizer.step()  # SGD：读取梯度，真正修改参数
```

本案例这个基础版本的更新公式是：

```text
新参数 = 旧参数 - 学习率 × 梯度
```

例如，分类头中某个权重当前为 `0.5`，梯度为 `2`，学习率为 `0.01`：

```text
新权重 = 0.5 - 0.01 × 2 = 0.48
```

梯度为正，表示在当前点附近、其他参数不变时，增大这个权重会使损失倾向于增大，所以沿相反方向减小它。如果同一个权重的梯度是 `-2`，则更新为：

```text
新权重 = 0.5 - 0.01 × (-2) = 0.52
```

学习率控制每次调整的幅度。梯度只反映当前点附近的变化趋势，步子过大可能越过合适的位置，因此不能认为每次更新都一定降低损失。

公式对每个可训练参数分别应用：每个权重、偏置都有自己的梯度。本案例只更新分类头的 `fc.weight` 和 `fc.bias`，前面的特征提取参数没有交给优化器更新。

例如第七节的特征 `[2,1]` 与分数 `[2,1,−1]`，若正确标签是纸板 `cardboard=1`，分数梯度约为 `[0.705385,−0.740504,0.035119]`。纸板行第一个权重的梯度为 `−0.740504×2≈−1.481007`；学习率 `0.01` 将这个权重从 0 改为 `0.014810`。完整 3×2 梯度、偏置更新和更新后损失见[分类头求导](head_gradients.md)，这些示意值不替代下面的真实图片单批记录。

### “随机”是随机修改权重吗？

不是。**随机性来自训练样本的抽取或打乱，而参数的更新由算出的梯度决定。**

| 每次用多少数据计算梯度 | 常见名称 |
| --- | --- |
| 全部训练样本 | 批量梯度下降 |
| 一个训练样本 | 随机梯度下降，狭义的 SGD |
| 一小批训练样本 | 小批量随机梯度下降，mini-batch SGD |

你的代码每次用最多 **32 张图片**，根据这批图片的平均交叉熵计算梯度，再更新一次参数，所以属于小批量 SGD。PyTorch 中仍使用 `SGD` 这个优化器名称，实际批次大小由 DataLoader 决定。

```text
第一批 32 张 → 平均损失 → 梯度 → 更新一次参数
第二批 32 张 → 用更新后的模型计算新损失 → 新梯度 → 再更新一次
……
最后一批 24 张 → 平均损失 → 梯度 → 更新一次
```

训练集共 984 张，全部遍历一轮是 31 批；每批更新一次，就是 31 次参数更新。`train_step.py` 的演示入口只执行首批的一次更新；`train.py` 已将同一更新函数放入整轮循环，三轮共 93 次更新，结果见[实验记录](results.md)。固定随机种子 42 有助于复现取样顺序，不会把小批量梯度变成全量梯度。

### 对应到当前代码

```python
parameters = [p for p in model.parameters() if p.requires_grad]
optimizer = torch.optim.SGD(parameters, lr=0.01)
```

第一行选出需要学习的参数；第二行建立管理这些参数的优化器。创建优化器并不会立刻改变权重，真正更新发生在 `optimizer.step()`。

每批反向传播前还要调用 `optimizer.zero_grad(set_to_none=True)`，清除上一批留下的梯度，因为 PyTorch 默认会累加梯度。当前基础 SGD 的更新只使用这一次算出的梯度。

保存的未增强单批实验中，更新前平均损失约为 `1.240659`，更新后同一批图片的损失约为 `0.941231`。当前 `train_step.py` 默认启用训练增强，重跑数值可能不同。单次更新改善同批损失不能说明其他图片效果；完整训练的验证与测试成绩见[实验记录](results.md)。

## 11. 冻结参数、train/eval 和 no_grad 是三件事

(其实上个 week 说过这些事了，这里只是结合例子讲一下。)

先解释 `model.py` 中这句话：“冻结部分保持评估模式，分类头设为训练模式。”

**我们想让前面的 ResNet18 按已经学好的规则处理图片，只让最后的新分类头学习。** 但是，模型里除了权重和偏置，还有一些会在前向计算时自动变化的统计记录。所以需要分别设置“哪些参数要学习”和“某些层按什么规则运行”。

### 1. 冻结参数：不再为这些权重和偏置计算梯度

例如，一个卷积核已经学到了某组权重。我们希望后续训练纸张、纸板、金属分类时保留它，就设置：

```python
parameter.requires_grad_(False)
```

在本案例代码里，先对原模型所有参数这样设置，再创建新的 `model.fc(指模型中的全连接层，fc 是 fully connected 的缩写，它是模型的一个属性。)`。新分类头的参数默认需要梯度，所以最后只剩分类头可以学习。

冻结之后，卷积仍然执行乘法和求和，继续产生特征图。**固定的是计算使用的参数，不是输出特征；换一张图片，特征通常仍会变化。** 后续优化器只接收需要训练的分类头参数。

### 2. 为什么冻结参数之后，还要设置 eval？

**冻结可学习参数还不能保证整个模型状态保持不变。** ResNet18 中的 **BatchNorm（批归一化）** 在训练模式下，用当前 batch 的统计量归一化中间特征，再做可学习的缩放和平移。更换批次会改变统计量和输出，但不会因此自动改变已经冻结的缩放、平移或卷积权重；需要另外关注下面的运行统计记录。

BatchNorm 不只是保存可学习的参数，还保存类似下面的统计记录：

```text
running_mean：根据过去批次逐步积累的均值估计
running_var：根据过去批次逐步积累的方差估计
```

这些统计记录属于模型状态，但不是优化器通过梯度学习的权重。**在本案例 ResNet18 的 BatchNorm 默认设置下，它们可以在前向传播时自动更新，不需要 loss.backward() 或 optimizer.step()。**

两种模式的区别是：

| BatchNorm 的模式 | 这次前向计算使用什么统计量 | 是否更新保存的统计量 |
| --- | --- | --- |
| `train()` 训练模式 | 当前批次的均值和方差 | 是 |
| `eval()` 评估模式 | 已经保存的均值和方差 | 否 |

这里统计的是中间特征。对二维特征图，BatchNorm 按通道统计，结合这个批次中的图片及其空间位置，并不是把类别标签拿来求平均。

举一个只看均值更新的例子：假设保存的均值是 `10`，新批次均值是 `20`，更新比例为 `0.1`。训练模式下，保存的均值会变成：

```text
新记录 = 旧记录×0.9 + 当前批次均值×0.1
       = 10×0.9 + 20×0.1
       = 11
```

**即使所有权重都冻结了，这条记录仍可能从 10 变成 11。** 而在评估模式下，这次前向会使用保存的统计量，记录仍保持为 10。

因此，*只冻结参数还不能保证整个特征提取部分保持固定。*本案例同时让它处于 `eval()`，保留预训练时保存的 BatchNorm 统计量。

### 3. “评估模式”不是“拿测试集来评估”

`eval` 是 evaluation 的缩写，但这里是一个**层的运行模式开关**。调用 `eval()` 本身不会读取验证集或测试集，不会计算准确率，也不会停止前向传播。

例如，下面完全可以输入训练集图片：

```text
训练集图片
  ↓
冻结的特征提取部分：处于 eval，照常算出特征
  ↓
新分类头：根据特征给三个类别打分
  ↓
与训练标签比较，反向传播并更新分类头
```

整个任务正在训练分类头，同时前面的特征提取部分采用评估模式，这两件事并不矛盾。

### 4. 对照 model.py 的两行代码

```python
model.eval()
model.fc.train()
```

第一行把整个模型及其子层都切到评估模式；第二行只把 `fc` 分类头切回训练模式。所以最终状态是：

| 部分 | 参数是否需要梯度 | 运行模式 | 在本案例训练中做什么 |
| --- | --- | --- | --- |
| 前面的特征提取部分 | 否，已在 build_model 中冻结 | eval | 使用固定参数和统计量计算特征 |
| 新分类头 fc | 是 | train | 计算分数，随后根据梯度更新权重和偏置 |

**这两行模式设置本身不负责冻结或解冻参数。** 冻结是前面 `requires_grad_(False)` 做的，分类头可训练是因为它是后来新建的层。

还有一个细节：本案例 `fc` 是普通 `Linear` 层，它在 train 和 eval 模式下的前向公式相同。让它能够学习的关键是参数需要梯度、计算被记录，以及优化器执行更新；并不是 `.train()` 一调用，它就自动开始学习。显式写 `model.fc.train()` 是为了清楚表达只训练分类头的安排。

`train_one_batch()` 每批调用 `set_head_training_mode(model)`，让骨干保持 eval，分类头保持 train。如果之后又调用整个 `model.train()`，会把前面的 BatchNorm 也切回训练模式，需要重新设置。

### 5. no_grad 又管什么？

**`torch.no_grad()` 控制这一段计算是否记录反向传播所需的信息。** 它不会自动改变 train/eval 模式，也不修改参数的 `requires_grad` 设置。

当前 `model.py` 只检查一次前向传播，所以使用：

```python
model.eval()
with torch.no_grad():
    logits = model(images)
```

这时连分类头的计算也不记录梯度，因为只是检查输出形状，并不训练。

现有 `train_one_batch()` 训练分类头时遵循下面的流程（optimizer 只管理分类头参数）：

```python
set_head_training_mode(model)
optimizer.zero_grad()
logits = model(images)       # 这里不把整个前向放进 no_grad
loss = criterion(logits, labels)
loss.backward()
optimizer.step()
```

即使特征提取部分不学习，分类头仍然需要记录自己的计算，才能得到梯度。只对冻结部分单独使用 `no_grad()` 可以作为另一种实现方式，但不能把需要训练的分类头一起包进去。

当前骨干参数与输入图片都不要求梯度，因此骨干特征作为固定输入参与分类头求导；骨干的 `.grad=None` 不表示其数学导数必然为零。若拆分骨干并使用 `no_grad()`，分类头应在该上下文外执行。实际形状及求导条件见[分类头求导的最后两节](head_gradients.md#real-head)。

### 6. 再用三个问题区分它们

| 操作 | 回答的问题 | 不会自动做什么 |
| --- | --- | --- |
| `requires_grad_(False)` | 这个参数要不要计算梯度？ | 不会阻止训练模式下 BatchNorm 统计量更新 |
| `train()` / `eval()` | 某些层采用哪种前向行为？ | 不会开启/关闭梯度，也不会更新权重 |
| `no_grad()` | 这一段计算要不要记录梯度信息？ | 不会切换层的运行模式 |

另一个受模式影响的常见层是 Dropout：训练时随机将部分输入置零，评估时不再随机丢弃。本案例标准 ResNet18 加 Linear 分类头没有 Dropout，重点关注 BatchNorm 即可。

本案例选择固定预训练统计量，是为了先只训练分类头；这不是所有迁移学习都必须遵守的规则。以后微调时可以重新选择哪些参数及统计量需要适应新数据。

参考：[PyTorch 对梯度开关与评估模式的说明](https://docs.pytorch.org/docs/2.6/notes/autograd.html)。

## 12. 图片预处理：缩放、裁剪与标准化

预处理是把磁盘上的图片转换成模型所需输入。

| 操作 | 做了什么？ | 需要理解什么？ |
| --- | --- | --- |
| 转为 RGB | 统一为三个颜色通道 | 避免灰度或透明通道导致输入不一致 |
| 缩放 resize | 改变图片尺寸 | 直接改成正方形可能拉伸物品 |
| 裁剪 crop | 保留图片中的一部分 | 裁剪过多可能丢失目标 |
| 转成浮点张量 | 将图片表示为可计算的数组 | 常先把 0～255 转为 0～1 |
| 标准化 normalize | 按通道减均值，再除以标准差 | 数值可以变成负数，也可以大于 1 |

标准化可写成：`新数值 = (原数值 - 均值) / 标准差`。它与简单除以 255 是不同步骤，不应混为一谈。

使用预训练权重时，应遵循这些权重对应的输入尺寸处理、均值和标准差等要求。它们来自预训练约定，不是用本案例测试集估计出来的。若要自己估计数据统计量，则只能使用训练集。

验证、测试和实际推理应采用一致、确定的输入处理规则。训练阶段在此基础上可以加入随机增强。

## 13. 数据增强：给同一张训练图换一种外观

**数据增强（augmentation）** 是在取训练样本时，对图片施加适度的随机变化，例如翻转、裁剪或亮度变化，让模型接触更多外观情况。

例如，纸板照片稍微变暗后，正确标签通常仍是纸板。这可以帮助模型减少对某一种亮度的依赖。增强通常在读取时进行，不需要覆盖原图，也不一定生成新的磁盘文件。

增强必须尽量保持标签含义。裁剪到只剩白背景，或者把颜色改得过于失真，就可能让输入不再支持原来的答案。

**先划分数据，再只对训练集做随机增强。** 不能先生成同一张图的多个变体，再随机分到训练和测试中，否则测试可能变成对训练图片变体的识别。

增强不能凭空补足所有真实场景。对白背景图片做简单翻转，不等于模型已经见过杂乱桌面。

## 14. 标签与类别映射为什么要保存？

程序通常使用整数表示类别。举例：

```text
0 → cardboard（纸板）
1 → metal（金属）
2 → paper（纸张）
```

这些编号只是约定，没有大小关系。标签 `2` 不代表纸张比金属“更大”。实际映射必须以数据加载代码为准，不能凭文件夹出现的顺序猜测。

模型输出的第几个分数对应哪一类，完全依赖这个映射。如果训练时 `0` 是纸板，推理时却解释成纸张，即使权重正确，也会显示错误答案。

因此应把类别映射与模型一起保存；三类标签也要对应三个输出位置，不能直接沿用六类数据中的不连续编号。

## 15. Logits、概率与置信度

模型先输出三个原始分数，也就是 logits。假设映射采用上一节的例子：

```text
输出：[1.2, 3.1, -0.4]
最大分数在位置 1 → 预测金属
```

训练时将 logits 和整数标签直接交给交叉熵，不提前对 logits 做 softmax。需要展示结果时，再用 softmax 将它们转换为总和为 1 的概率形式。取最大类别时，softmax 不会改变分数的大小顺序。

界面上常把最大概率称为“置信度”。但显示 95% 并不保证这次预测有 95% 的现实正确率，尤其是面对与训练数据不同的图片。

如果输入一张猫的照片，只有三个输出类别的模型仍会从三者中选一个，甚至给出很高的分数。低置信度阈值可以帮助拒绝部分不确定预测，但不能自动赋予模型可靠的“识别未知物体”能力。

## 16. 数据划分、重复图片与标签问题

训练集用于更新参数，验证集用于选择训练设置，测试集在设置确定后用于最终评估。即使使用预训练模型，这些职责也不改变。

视觉数据要特别注意：同一物品的连续照片可能非常相似。若分散到不同集合，分数可能主要反映模型记住了物品或场景，而不是学会识别新物品。能确认属于同一物品或拍摄组的图片，应尽量按组划分。

**标签噪声**指答案可能有误或不一致。本次下载检查发现完整六类数据中有跨类别完全重复图片，其中一组涉及金属类。具体记录见[数据说明](data/README.md)。这提醒我们：现成数据省去了采集与标注工作，但仍需要检查质量。

文件哈希能发现文件内容完全相同的图片，不能保证发现换角度、重新压缩等近似样本。后续需要把检查范围和未解决的问题写清楚。

## 17. 怎样判断模型有没有学好？

| 观察内容 | 回答什么问题？ |
| --- | --- |
| 训练与验证 loss | 学习是否稳定，是否出现过拟合迹象？ |
| 准确率 accuracy | 整体有多少图片分类正确？ |
| 每类召回率 recall | 某类真实图片中，有多少被认出来？ |
| 混淆矩阵 | 哪些类别经常被相互认错？ |
| 错误样本图片 | 分数背后的具体问题是什么？ |

例如，纸张和纸板经常混淆时，可以看模型是否主要依靠颜色，或者照片本身是否缺少厚度、折痕等可区分信息。仅凭一张错图通常不能证明原因，需要观察多个样本，再做有针对性的验证。

训练表现越来越好而验证表现变差，可能表示过拟合。看到测试错误后可以记录发现，但若据此继续改模型，后续结果就应说明测试集已影响开发，不能再把它当作完全独立的最终考试。

## 18. 为什么换到真实桌面可能失效？

训练数据与实际输入的条件不同，常称为**分布变化（distribution shift）**。本案例图片主要在白色背景板上拍摄，而真实照片可能包含杂乱背景、强反光、遮挡或多个物品。

模型还可能学到与任务偶然相关的线索，例如背景、拍摄习惯，而不是我们期望的材料特征。这类现象常被称为“走捷径”。

所以，数据集上的准确率回答的是“在这份测试数据上表现怎样”，不能直接等同于“在任何环境中都能识别”。本地图片演示可以帮助直观看到这种差异。

## 19. 保存与推理：怎样把训练结果真正用起来？

推理是用已训练好的模型对新输入作预测，不需要正确标签，也不执行反向传播或优化器更新。

为了恢复同一个预测过程，需要保留：

- 模型结构信息：使用什么网络，分类头如何定义。
- 模型状态：学习后的权重及相关状态，通常保存为 `state_dict`。
- 类别映射：每个输出位置对应什么类别。
- 输入处理规则：尺寸、颜色通道、标准化方式等。

```text
本地图片
  ↓ 与评估一致的预处理
单图张量 [3, H, W]
  ↓ 增加 batch 维
[1, 3, H, W]
  ↓ 重建模型、加载状态、使用评估模式并关闭梯度记录
三个类别分数 [1, 3]
  ↓ 按保存的映射解释输出
类别名称 + 用于展示的置信度
```

保存后应重新建立模型并加载，用同一输入检查预测是否一致。这能发现结构、权重或预处理没有正确恢复的问题。

## 20. 快速复习卡

| 词语 | 一句话复习 |
| --- | --- |
| CNN | 利用局部连接和共享卷积权重处理图片的神经网络 |

| 池化 | 对局部或整体空间信息进行汇总 |

| 冻结 | 保持指定参数固定，同时仍可执行前向计算 |

| 推理 | 用已训练模型为新输入给出预测 |

回看时可以先回答：图片的 shape 是什么？哪部分参数在更新？输出编号代表什么？测试图片有没有参与选设置？换个背景后模型还可靠吗？需要实现细节时，再通过[本章入口](README.md)查阅源码。
