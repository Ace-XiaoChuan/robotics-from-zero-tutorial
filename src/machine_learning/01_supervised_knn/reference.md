本项目使用鸢尾花的测量数据，训练一个模型来判断一朵花属于哪个品种。

## 核心概念

| 概念 | 在鸢尾花项目中的含义 |
| --- | --- |
| 样本 | 一朵花 |
| 特征 | 花萼和花瓣的长度、宽度 |
| 标签 | 花的品种 |
| 分类 | 从几个品种中选择一个 |
| 回归 | 预测连续数值，例如房价 |
| 模型 | 从已有样本中学到的判断规则 |
| 训练 | 用已知答案的数据寻找规则 |
| 预测 | 用学到的规则判断新数据 |

计算机并不知道“花长什么样”，它只能根据几个数字寻找品种之间的规律。

## 什么是监督学习和分类？

**监督学习**是指：我们提供一批已经知道正确答案的数据，让模型从中学习输入和答案之间的关系。在本项目中，输入是每朵鸢尾花的四个测量数值，正确答案是它的品种；这些已知品种就是对模型的“监督”。

**分类**是监督学习的一种任务。它的目标不是预测一个连续数值，而是在有限个类别中做选择。鸢尾花项目需要从三个品种中选择最可能的一个，因此它是一个分类问题；预测房价这类连续数值的问题则属于回归。


训练过程：

```text
鸢尾花数据
  → 按品种比例划分训练集（80%）和测试集（20%）
  → 在训练集上标准化特征(几乎所有机器学习项目都需要检查特征尺度，但并非所有模型都需要标准化。)
  → 仅在训练集内用 5 折交叉验证比较不同 K 值
  → 用选出的最佳 K 重新训练模型
  → 在未参与选型的测试集上进行最终评估
```

### 训练集、验证集与测试集

机器学习中通常将原始数据分成三种用途不同的集合：

| 数据集 | 用途 | 能否用于调整模型？ |
| --- | --- | --- |
| **训练集（training set）** | 让模型学习规律，例如 KNN 保存训练样本并学习标准化规则。 | 可以 |
| **验证集（validation set）** | 比较不同模型、不同超参数（例如不同的邻居数 `k`），帮助选择方案。 | 可以，但不能把它当作最终成绩 |
| **测试集（test set）** | 模拟模型第一次面对从未见过的数据，用于最终评估泛化能力。 | 不可以 |

测试集的意义是当一张“最终考试卷”。如果反复根据测试集成绩修改 `k`、换模型或调整预处理，模型就会间接适应这张考卷，得到的分数会过于乐观，无法真实反映它面对新数据时的表现。

本项目没有单独固定一份验证集，而是采用 **5 折交叉验证**：

```text
原始 150 个样本
  → 训练集：120 个样本
  → 测试集：30 个样本（先保留，不参与选 K）

120 个训练样本
  → 分成 5 折，轮流作为临时验证集
  → 比较不同 k 的平均验证准确率
  → 选定 k 后，用全部 120 个训练样本训练最终模型
  → 最后仅在 30 个测试样本上评估一次
```

因此，训练集负责“学习”，交叉验证中的临时验证集负责“选择”，测试集负责“最后验收”。

### 什么是 X 折交叉验证？

**X 折交叉验证**中的 `X` 表示把训练数据分成几份。例如，5 折交叉验证就是把训练数据分成 5 份；10 折交叉验证就是分成 10 份。

每一轮都选其中一份作为临时验证集，其余 `X - 1` 份全部用于训练；轮流进行 X 次后，计算 X 次验证结果的平均值。这样，每个训练样本都会恰好验证一次，并参与 `X - 1` 次训练。

以 5 折交叉验证为例，把 120 个训练样本分成 A、B、C、D、E 五份：

| 轮次 | 临时验证集 | 本轮训练集 |
| --- | --- | --- |
| 第 1 轮 | A | B + C + D + E |
| 第 2 轮 | B | A + C + D + E |
| 第 3 轮 | C | A + B + D + E |
| 第 4 轮 | D | A + B + C + E |
| 第 5 轮 | E | A + B + C + D |

例如，第三份 C 会在第 3 轮验证，但在第 1、2、4、5 轮都参与训练。需要注意：这里的 5 是“折数”；KNN 中的 `k=3` 则表示预测时参考 3 个最近邻样本，两者不是同一个概念。

### 交叉验证结束后会发生什么？

5 折交叉验证确实是在训练集内部估计模型面对未知数据时的泛化能力。对于某一个候选 `k`，它会产生 5 个**临时模型**：每个临时模型都用 4 折数据训练、用剩余 1 折验证。

这 5 个模型不是完全不相干的，因为它们的训练数据大部分重叠；它们的作用也不是让我们从中挑选“最好的一个模型”，而是得到同一个 `k` 的 5 次验证成绩并计算平均值。

```text
以 k=3 为例：

第 1 轮：A 验证，B+C+D+E 训练 → 临时模型 1 → 得分
第 2 轮：B 验证，A+C+D+E 训练 → 临时模型 2 → 得分
……
第 5 轮：E 验证，A+B+C+D 训练 → 临时模型 5 → 得分

→ 计算 5 次得分的平均值
→ 得到 k=3 的交叉验证成绩
```

当前项目会分别尝试 `k=1、3、5、7……15`。每个候选 `k` 都进行 5 折交叉验证，因此共有 `8 × 5 = 40` 个临时训练过程。比较每个 `k` 的平均验证准确率后，选出表现最好的超参数，例如 `k=3`。

最后，不保留上述临时模型，而是使用选出的超参数和**全部 120 个原始训练样本**重新训练一个最终模型。交叉验证中临时充当验证集的那一折数据会回到训练集中；只有最初保留的 30 个测试样本始终没有参与训练、交叉验证或选超参数。最终模型只在测试集上评估一次。

### 使用了什么数据预处理？

这里使用 `Pipeline(StandardScaler → KNeighborsClassifier)`，其中 `StandardScaler` 是本项目的预处理步骤。

它会针对每一个特征，使用训练集计算均值 `μ` 和标准差 `σ`，并转换为：

```text
标准化后的值 = (原始值 - μ) / σ
```

标准化后，各特征都以 0 为中心、尺度相近。KNN 依赖样本之间的距离；如果某一列数值范围明显更大，它会在距离计算中占据更大影响，因此需要标准化。

鸢尾花数据集没有缺失值，且四个特征本来都是数值，所以本项目**不需要**缺失值填补或类别编码。`Pipeline` 会确保标准化规则只从训练数据中学习，再将同一规则应用到验证折和测试集，避免测试集信息泄漏。

### 如何理解混淆矩阵？

混淆矩阵把“真实类别”和“模型预测类别”逐格统计。在本项目生成的图中：

- **行**表示真实品种；
- **列**表示模型预测的品种；
- 从左上到右下的**对角线**表示预测正确的样本；
- 非对角线位置表示模型把一种花误判成另一种花的次数。

本次使用 `random_state=42` 的运行结果可概括为：

| 真实品种 | 预测为 setosa | 预测为 versicolor | 预测为 virginica |
| --- | ---: | ---: | ---: |
| setosa | 10 | 0 | 0 |
| versicolor | 0 | 10 | 0 |
| virginica | 0 | 2 | 8 |

因此，30 个测试样本中有 28 个位于对角线，测试集准确率为 `28 / 30 = 93.3%`。错误集中在：有 2 朵真实的 `virginica` 被预测成 `versicolor`。这说明在这次划分中，模型最容易混淆这两个品种；`setosa` 则完全被正确识别。
