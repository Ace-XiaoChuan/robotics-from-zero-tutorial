# 13 序列模型与编码器—解码器

本文行数：154行，预期阅读时长：9分钟

<a id="developer-overview"></a>

## 开发者理解：需要历史和顺序的预测功能

**序列模型处理有顺序的一组输入，利用前后关系预测结果。** 一张图片或一个位置有时不足以说明情况；想要具体了解运动方向、过去发生了什么、一句话里谁在谁前面，就需要顺序信息，而这个顺序信息，就是我们说的序列模型。

**例子（教学场景）：** 两个物体当前在同一位置，但一个刚从左边移来，另一个刚从右边移来。若短时间内继续沿原方向移动，它们下一刻的位置会不同。只提供当前位置无法区分这两种历史，提供最近几次位置与时间才有相应信息；简单运动估计也可以利用它，不一定需要神经网络。

序列功能可以有几种输入输出形式：

| 功能 | 输入 | 输出 |
| --- | --- | --- |
| 历史判断 | 一段传感记录 | 一个类别或当前状态估计 |
| 运动预测 | 过去的位置、时间等信息 | 一个未来位置或一段未来序列 |
| 序列转换 | 一句有顺序的文字 | 另一条序列，如译文 |

**时间窗口**是直接提供最近一段历史；**隐藏状态**是模型内部保存并逐步更新的历史摘要。窗口外的信息默认不可见，内部摘要也不保证保留了所有过去细节。RNN（循环神经网络）使用这种递推摘要；GRU 让保留旧信息和写入新信息的程度也可学习。

**编码器—解码器**描述两个角色：编码器把输入形成表示，解码器依据这些表示产生目标输出。输入与输出长度可以不同，例如英文与中文句子不必包含同样多的单位。这种结构不只用于某一种网络，也不是“编码器输出接上任意模块都能工作”。

**时间和可见历史属于功能含义。** 预测下一秒与预测下一帧不同，缺帧也会改变相邻观测的时间间隔。机器人位置需要统一坐标系与单位；新轨迹开始时，上一段保留的状态是否清除，也会影响输入究竟包含什么。

连续预测还可能逐步累积误差：训练时参考正确历史，实际生成时却参考自己前面生成的结果。每步重读传感器与一直沿用预测，是不同的使用方式。

**需要深入时：** [历史为何重要](#1-同样在-02-m下一步可能向不同方向) · [窗口与状态](#2-时间窗口与隐藏状态) · [编码器—解码器](#5-编码器解码器输入与输出各有一条序列) · [训练与自由生成](#6-训练与生成历史-token-从哪里来)。

单张图像分类处理一个输入，运动预测和语言生成还需要处理顺序。本章从带时间的位置序列讲起，再解释 RNN、GRU 与编码器—解码器；为 [14 注意力](../14_attention_transformer/README.md)和 [16 VLM](../16_vision_language/README.md)提供回查入口。

## 速记要点

- 序列是有顺序的输入；机器人序列还需写清采样时间、单位、坐标系和缺帧情况。
- 时间窗口把最近几个观测一起给模型；隐藏状态把历史压成可更新的向量，它通常没有直接物理单位。
- RNN 每步复用相同参数，状态依赖当前输入和上一状态；训练需沿时间展开计算图。
- GRU 用门控制旧状态保留与新信息写入；门是网络计算的数值，不是离散程序判断。
- 编码器形成输入表示，解码器依据该表示产生目标输出；输出长度可以不同，架构不限于 RNN。
- 教师强制使用正确历史 token 训练；自由生成使用自己生成的历史，误差可能逐步影响后续输出。

## 1. 同样在 0.2 m，下一步可能向不同方向

**输入（教学运动）：** 物体沿 `base` 坐标系 x 轴运动，采样间隔 Δt=0.1 s，当前时刻 t=0。暂时假设局部速度恒定，预测 t=0.1 s 的位置。

| 历史 | t=−0.2 s | t=−0.1 s | t=0 | 最近差分速度 | 下一位置预测 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A | 0.0 m | 0.1 m | 0.2 m | +1 m/s | 0.3 m |
| B | 0.4 m | 0.3 m | 0.2 m | −1 m/s | 0.1 m |

**结果（静态计算）：** 当前位置相同，但最近两个位置给出不同速度。只把当前位置输入一个确定性模型，无法唯一分辨本例的两种历史；使用窗口或有效隐藏状态，才有机会保留方向信息。这不是说必须用神经网络：差分与简单状态估计已经能说明信息来源。

若时间不等间隔，速度必须使用实际时间差；把缺帧序列当成固定 Δt 会改变含义。物体加速或观测有噪声时，恒速外推也可能失败，[09](../09_probability_uncertainty/README.md)的不确定性不能省略。

## 2. 时间窗口与隐藏状态

对于 d 维观测、长度 T 的序列，一种张量排列为 `[B,T,d]`，B 为批次。若把过去三步位置拼成向量，输入是 `[B,3]`；若每步包含三维位置，则是 `[B,3,3]`，展平后为 `[B,9]`。最后一个数字不再代表时间步。

窗口模型可以使用 MLP、卷积或后续注意力；窗口之外的历史默认不可见。RNN（Recurrent Neural Network，循环神经网络）用递推状态：

\[
h_t=\tanh(W_x x_t+W_hh_{t-1}+b),\qquad
\hat y_t=W_yh_t+c.
\]

若输入维度 d、状态维度 k、输出维度 m，列向量约定下 `W_x∈Rᵏˣᵈ`、`W_h∈Rᵏˣᵏ`、`W_y∈Rᵐˣᵏ`。所有时间步共享这些权重，序列变长不增加一套新权重。输出若为位置，最后一层与反归一化需使其回到指定坐标和 m 单位。

**可手算的线性递推演示：** 先去掉 tanh，使用归一化后的输入 `[0,1,2]`，`h_t=0.5h_(t−1)+x_t`，h₀=0，输出依次为 `[0,1,2.5]`。它是历史的衰减加权和，不是上节恒速预测器，也没有经过训练。

同一输入换成 `[2,1,0]`，状态为 `[2,2,1]`，最后状态不同，说明顺序会改变结果。实际 RNN 通过目标损失学习应该保留什么，不能把每个隐藏维度直接命名为“速度”或“物体类别”。

## 3. 沿时间反向传播，困难在哪里

RNN 训练时把每个时间步的计算连接起来，形成展开图；从输出损失反向求各步的贡献，称为 BPTT（Backpropagation Through Time，随时间反向传播）。共享参数的总梯度是所有相关时间步贡献之和。

对上面的线性递推，三步输入记为 x₁、x₂、x₃，h₃=`a²x₁+ax₂+x₃`。在 x=`[0,1,2]`、a=0.5 时，h₃=2.5。若目标为 3、损失为 `½(h₃−3)²=0.125`：

\[
\frac{\partial L}{\partial a}
=(h_3-3)(2ax_1+x_2)=-0.5.
\]

**结果（解析与数值差分一致）：** a 对两个历史路径都起作用，要累计贡献。输入 x₁ 到最终状态的导数为 a²；长序列中出现 a 的高次乘积，与 [11 的梯度消失/爆炸](../11_training_optimization/README.md)相同机制。非线性 RNN 还包含各步激活导数。

截断 BPTT 在指定时间长度后停止向更早状态回传梯度，可以控制计算与内存；状态值仍可传到后面，但优化信号的历史范围变短。跨 episode 的状态通常应重置，不能让上一段运动或上一句无意影响下一段。

## 4. GRU：让保留与更新变得可学习

GRU（Gated Recurrent Unit，门控循环单元）通过更新门 z、重置门 r 和候选状态控制信息。本章采用“z 越大，旧状态保留越多”的约定：

\[
z_t=\sigma(W_zx_t+U_zh_{t-1}+b_z),\quad
r_t=\sigma(W_rx_t+U_rh_{t-1}+b_r),
\]

\[
\tilde h_t=\tanh(W_hx_t+U_h(r_t\odot h_{t-1})+b_h),\quad
h_t=z_t\odot h_{t-1}+(1-z_t)\odot\tilde h_t.
\]

σ 是 sigmoid，门的每个分量在 0～1，`⊙` 表示逐元素乘。更新门决定保留多少旧状态；重置门控制计算候选时使用多少旧状态。本章公式是常见写法之一；某些实现把重置放到矩阵乘之后，或用互补的更新门定义，不能直接混用权重。

**输入（指定门值，未训练）：** 标量旧状态 h=0.8、候选为 0.2。z=0.9 时新状态为 0.74，z=0.1 时为 0.26；z=1 时完全保留旧状态，z=0 时使用候选。

**结果与原因：** 直接保留路径有助于记住较早信息，但不保证所有长度上的梯度都稳定；门本身也依赖输入与状态。[GRU 与 RNN 编码器—解码器原论文](https://arxiv.org/abs/1406.1078)用于建立这一机制的来源，正文数值为本文构造。

## 5. 编码器—解码器：输入与输出各有一条序列

编码器（encoder）把输入形成表示，解码器（decoder）根据表示和已有输出产生目标。序列到序列（seq2seq）允许输入和输出长度不同，例如三项英文词到四项中文 token。token 是按规则切分的序列单位，本章为手算而使用词和短词；真实 tokenizer 未必如此切分。

**教学翻译，非模型实测：**

~~~text
输入：The | cat | sleeps
编码器：依次处理输入 → 上下文表示 c
解码器：给定 c 与“开始” → 猫
        给定 c 与“猫”   → 在
        给定 c 与“在”   → 睡觉
        给定 c 与“睡觉” → 结束
~~~

其中还保留解码器自己的状态，因此不是每步只看一个词。原始固定向量方案用最终状态 c 压缩整段输入，长序列可能难以保留全部细节；注意力方案可以保留各输入位置的表示，并让解码器按当前需要读取，见 [14](../14_attention_transformer/README.md)。

“编码器—解码器”描述结构角色，不专指一种网络：RNN 可以承担它，Transformer 也可以；自编码器的重建任务也使用这两个角色，见 [15](../15_representation_learning/README.md)。它不等于“先做文本编码，再随意接任何生成器”。

## 6. 训练与生成：历史 token 从哪里来

给目标中文句子加开始/结束标记，训练输入与监督目标错开一位：

~~~text
解码器输入：[开始, 猫, 在, 睡觉]
监督目标：  [猫,   在, 睡觉, 结束]
~~~

教师强制（teacher forcing）用真实前缀作为条件，目标是提高各正确下一个 token 的概率。若本次概率为 `[0.8,0.6,0.5,0.9]`，平均负对数似然为：

\[
L=-\frac14\ln(0.8\times0.6\times0.5\times0.9)
\approx0.383119.
\]

**结果（静态计算）：** 四个位置都计入 loss，包括结束标记；序列条件概率为 0.216。生成时不知道真实答案，第一步若选了“狗”，后面会依据这个错误前缀继续；训练时正确前缀条件下的 loss 不能直接代表自由生成成功率。

可变长度的批次通常补 padding，并记录实际长度：padding 位置不应作为普通目标计入平均 loss，也不能无意影响最终状态。对于 Transformer，还要区分忽略 padding 的 mask 与限制未来信息的因果 mask，下一章具体展开。

对运动也会发生类似差异：训练时每步看到真实位置，推理时连续使用自己的预测作为下一输入，误差可能累积。是否每步重新读传感器、预测多长时间、多久更新一次，决定实际任务接口。

## 7. 当前机器人主线如何使用这些概念

窗口适合描述“过去多久”；状态适合描述“历史怎样保留”；编码器—解码器适合解释“观察历史 → 未来序列”。选择模型之前，先定义观测时间和预测时间，并按轨迹或场景划分数据，防止相邻帧泄漏。

本章运动外推、递推、门值和 token 概率均为教学计算，没有训练 RNN/GRU、翻译模型或动作策略。没有理由仅因序列模型文件存在，就标记机器人未来轨迹已可用。数值见[核对记录](../examples/README.md#multimodal)。
