# VLM 05：怎样接入机器人，为什么还要区分 VLA

本文行数：146行，预期阅读时长：9分钟

**VLM 可以将语言任务与视觉对象联系起来；机器人执行还需要带单位、坐标和时间的目标，以及可验证的规划与控制。** VLA 则把动作预测纳入模型任务，不等同于普通看图问答。

## 速记要点

- “抓左边红杯”同时包含语义选择、几何定位、抓取方式和执行问题，不能只靠一段文字完成。
- 普通生成式 VLM 不一定有定位能力；grounding 表示把语言对象对应到图像区域，仍需具体模型或感知工具。
- 像素位置只有二维图像信息；米制三维位置还需深度、几何先验或多视图及相机参数。
- VLM 结合独立检测、位姿估计、规划与控制，是一种可解释的系统方案。
- VLA（Vision-Language-Action）根据视觉、语言等条件预测机器人动作，必须明确动作定义、尺度、时间和适用机器人。
- 预习可以现在阅读；机器人策略开发仍按 S8 数据契约和 S9 闭环评估推进。

## 1. 把“抓左边的红杯”拆开

沿用宽 640、高 480 像素的桌面图。下面是建议系统结构，没有实现或运行抓取。

~~~mermaid
flowchart TD
    A["图像与用户指令"] --> B["语义理解：确定要找什么"]
    B --> C["语言定位模型或独立检测：目标区域"]
    C --> D["深度与几何估计：相机系目标"]
    D --> E["标定与 TF：基座系目标"]
    E --> F["抓取候选与运动规划"]
    F --> G["轨迹执行与状态反馈"]
    G --> H["重新观测与任务判断"]
~~~

| 环节 | 输入 → 输出 | 不能省略的定义 |
| --- | --- | --- |
| 语义理解 | 指令 + 图像 → 目标描述 | “左边”依据图像还是机器人方向；多个红杯时如何选 |
| 语言定位 grounding | 目标描述 + 图像 → 框 / 掩码 / 对象 ID | 图像尺寸、框格式、候选是否唯一 |
| 几何估计 | 区域 + 深度/先验 + 相机参数 → 位置/位姿 | 单位、相机坐标轴、遮挡与测量有效性 |
| 坐标变换 | 相机系量 + 外参/TF → 基座系量 | 变换方向及采集时刻 |
| 规划 | 目标、机器人状态、碰撞场景 → 轨迹 | 关节顺序、限位、末端姿态、碰撞条件 |
| 执行与复核 | 带时间轨迹 → 实际状态与任务结果 | 跟踪误差、抓取状态、超时和失败处理 |

这里“左边”首先指图像横坐标较小。它不自动等于机器人基座的 +Y 或 -Y 方向；换相机视角后关系可能改变。

**结果与解释：** VLM 可以帮助第一项，有定位能力的视觉语言模型也可承担第二项；其余项要由明确的几何和机器人模块完成。将这些模块组合起来，并不需要先把全部控制过程训练成神经网络。

## 2. 例子：一个框能说明多少

假设具备定位能力的模块返回教学框 [u_min,v_min,u_max,v_max]=[120,140,220,300]，坐标以原始图左上角为原点，u 向右、v 向下，单位为像素。框的几何中心为：

$$u_c=(120+220)/2=170,\qquad v_c=(140+300)/2=220.$$

**结果（静态推导，已核对）：** 中心在图像 (170,220) 像素。若原图框定义采用连续坐标，这个几何中心没有端点是否包含的离散计数问题；读具体接口时仍要核对框与裁剪规则。

它只能说明一个图像区域的位置。杯子可以在 0.5 米处，也可以更远；没有尺度信息，单一像素点对应相机前的一条射线，不是唯一三维点。

如果模型在缩放、裁剪或补边后的图上输出框，还须映射回原图；不能把 224×224 图上的坐标直接套到 640×480 原图。归一化到 [0,1] 或其他范围的输出也要按接口恢复，不能从数字形式猜单位。

## 3. 再加入深度与内参，才得到三维例子

追加以下教学假设：图像已去畸变、与深度对齐；该中心点的深度 Z=0.60 米，表示沿相机光轴的距离，而非到相机原点的欧氏距离。相机内参 fx=fy=600 像素，cx=320 像素，cy=240 像素；相机坐标采用 X 向右、Y 向下、Z 向前。

针孔反投影：

$$X=(u_c-c_x)Z/f_x,\qquad Y=(v_c-c_y)Z/f_y.$$

代入后：

~~~text
X = (170-320)×0.60/600 = -0.15 米
Y = (220-240)×0.60/600 = -0.02 米
Z = 0.60 米
相机系点 p_C = [-0.15, -0.02, 0.60] 米
~~~

**结果（静态推导，已核对）：** 负 X 表示在相机主点左侧，负 Y 表示上侧。它不表示机器人应该向某个关节发负指令。

这个点是所选像素的表面测量，不一定是杯子物体中心或合适抓取点；框中心可能落在空背景上。仅有一点位置也无法确定杯子姿态、抓取方向或夹爪间隙。

把点变到机器人基座坐标系 B：

$$p_B=R_{BC}p_C+t_{BC}.$$

这里 R_BC 将 C 系向量旋转到 B 系，t_BC 是相机原点在 B 系的位置，单位米。此例未给外参，因此**不编造基座系数值**。眼在手上的相机需要采集时刻的机器人姿态参与坐标链，不能用回答生成完毕时的最新 TF 替代原图时间。

完整相机与坐标原理复用 [S6 相机标定](../../perception/01_camera_calibration/README.md)、[位姿与坐标变换](../../perception/02_pose_transforms/README.md)及[时间对齐](../../perception/06_time_alignment/README.md)，不在本专题再复制一套推导。

## 4. 语义推测与测量结果怎样分别保存

一个建议接口可以分别保存目标描述、原图坐标区域、图像时间戳、来源模型、定位分数、几何估计及其坐标系、测量有效性。分数必须注明来自匹配、检测还是生成，不能把不同意义的分数混为一个“置信度”。

例如“红杯可能用于喝水”是语义推测；“中心像素测得 Z=0.60 米”是带前提的几何测量。杯内是否有液体、是否适合夹持，都不能由类别标签自动确认。

目标不唯一时请求明确对象，深度无效时重观测，规划失败时反馈具体原因。这些是建议系统行为，尚未实现；关键是避免让一条看起来合理的语言回答直接变成无条件动作。

一张照片只能支持该时刻的判断。VLM 推理期间杯子可能被移动，执行前后的观察要按系统时间要求检查；“模型回答抓取成功”也不能代替物体是否实际离桌、夹爪是否保持等任务证据。

## 5. VLM 与 VLA 的输出差别

| 系统 | 输入示意 | 输出示意 | 要验证什么 |
| --- | --- | --- | --- |
| 图文匹配 VLM | 图片 + 候选文字 | 相似度向量 | 候选检索是否正确 |
| 生成式 VLM | 图片 + 问题 | 文字回答 | 事实、关系、对象选择 |
| VLM + 传统机器人栈 | 图片 + 指令 + 感知与机器人状态 | 语义目标，经模块变成轨迹 | 各模块接口与闭环任务结果 |
| VLA | 图像 + 指令，可能还有状态/历史 | 机器人动作或动作序列 | 动作契约、机器人适配与闭环表现 |

[OpenVLA 原项目](https://openvla.github.io/)是 VLA 的代表例子，把视觉语言预训练与机器人示教动作学习联系起来。本页仅借它说明任务类型，不下载模型、不移植到本仓库，也不假定任意机器人可直接使用。

一种**人为设计、未实现**的动作向量可写为：

~~~text
a_t = [Δx_B, Δy_B, Δz_B, g]
例： [0.01, 0.00, 0.00, 1]
~~~

这里前三项为机器人基座 B 系下、相对当前末端位置的平移增量，单位米；假设每 0.1 秒更新一次目标，姿态固定；g 是本例规定的夹爪目标状态，1=闭合、0=张开。这不是 OpenVLA 的具体动作格式，也不是直接执行代码。

**结果与解释：** 第一项 0.01 表示把下一步末端位置目标沿基座 X 方向增加 1 厘米，不是 0.01 弧度、0.01 米/秒或电机力矩。实现时还需解 IK、生成运动、处理限幅等，单独四个数并不能证明轨迹可行。

真实动作也可能是绝对关节角、关节增量、速度、末端位姿、力矩，或一个未来动作块；模型可能输出离散 action token 再解码为连续量。必须核对状态归一化、动作反归一化、旋转表示、夹爪约定、控制周期、动作块执行方式和关节顺序。

VLA 描述模型的输入输出与能力，不自动指定训练方式；基于示教训练可以属于模仿学习/监督学习，并不因输出动作就变成强化学习。真正的策略评估见 [S9](../../../doc/learning-roadmap.md#s9)。

## 6. 对当前仓库的定位

本专题先帮助理解：模型怎样把图像与文字关联，怎样生成回答，以及为何回答不能直接替代几何和控制。以后若有明确需求，可先接“语言选目标 → 现有感知 → 规划与控制”，再根据数据和任务决定是否需要 VLA。

阅读预习材料不依赖机器人策略训练；开发 VLA 或其他策略则应先明确观测、动作、同步、独立评估场景和闭环成功定义。现有图像分类案例与本次小型算术核对都不能作为策略有效的证据。

## 7. 换图、换指令与定位失败，怎样分别计分

**教学对照，未运行真实 VLM：** 两幅图分别是 A“左红右蓝”、B“左蓝右红”，每图问左侧颜色和右侧颜色；四个真值为 `[红,蓝,蓝,红]`。人为设定系统 X 总答“红”，系统 Y 四项都答对。

| 教学输出方案 | 普通答案正确数 | 同一问题在 A/B 两图都正确的成对数 |
| --- | ---: | ---: |
| X：`[红,红,红,红]` | 2/4=50% | 0/2=0% |
| Y：`[红,蓝,蓝,红]` | 4/4=100% | 2/2=100% |

**结果（静态计数）：** 普通准确率可能掩盖偏向一个常见答案；成对检查要求同一指令下随图像变化正确响应。该小表只能说明评价定义，不是系统 Y 已真正使用视觉证据的证明；还应扩展物体、指令、遮挡与独立场景，并检查实际图像输入。

即使答对颜色，也可能框错对象。指定指令“找左边红杯”，真实框为 `[120,140,220,300]`，输出文字“红色”但框为右侧 `[380,140,480,300]`，颜色文本通过，目标区域 IoU=0。若用这个错误区域读深度，后续几何可能在数值上合法却指向错误物体；不能让文字正确率覆盖定位失败。

框、掩码与区域评估回查 [12](../12_detection_segmentation/README.md)，目标时效和执行条件回查 [08](../08_robot_integration/README.md)。图像、指令、模型输出、定位来源和采集时间应能关联起来；新图或新指令改变条件后，旧回答和 [14 的 KV cache](../14_attention_transformer/README.md)不能未经核对地复用。

本节完成的是计分与接口解释，没有实际换图推理、定位模型或抓取运行。动作标签与闭环偏移见[18 模仿学习](../18_imitation_learning/README.md)，多解动作与扩散机制见 [17](../17_generative_models/README.md)，实际泛化评价见 [20](../20_generalization_sim2real/README.md)。
