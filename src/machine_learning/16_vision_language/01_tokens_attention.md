# VLM 01：token、语言模型与注意力

本文行数：234行，预期阅读时长：14分钟

**生成式 VLM 要先把图像和文字变成模型能计算的表示，再根据这些表示预测回答。** 先理解语言一侧，后面就容易看懂“接入图像”改变了什么。

## 先认识“序列”：按顺序排列的一串元素

**序列（sequence）就是按先后位置排列的一串元素。** 你可以先把它理解为一个有顺序的列表：有哪些元素、每个元素排在哪里，都属于序列的信息；元素也可以重复出现。

例如，为了说明顺序的作用，我们人为把两句话按词拆开：

| 原句 | 拆开后得到的序列 | 长度与含义 |
| --- | --- | --- |
| 我喜欢你 | [“我”, “喜欢”, “你”] | 3 个元素，表达我喜欢你 |
| 你喜欢我 | [“你”, “喜欢”, “我”] | 3 个元素，表达你喜欢我 |

**结果与解释（教学示意）：** 两行包含相同的词，但排列顺序不同，句子的意思也不同。第一行的第 1 个元素是“我”，第 2 个是“喜欢”，第 3 个是“你”；“序列长度为 3”就是一共有 3 个元素。这里的位置从 1 开始描述，代码中也常从 0 开始编号。

模型处理文字时，会先把文字拆成供它处理的小单位，叫作 **token**；这些单位按原文中的顺序排列，就构成 **token 序列**。上表只是人为按词切分，真实模型怎样拆分由配套的 tokenizer（文本切分与编码工具）决定，后面再具体解释。

因此，后文说“同一个序列的不同位置”，可以先理解为“同一句话拆开后，第 1、第 2、第 3……个小单位所在的位置”。序列也可以由数字或图像块的表示组成；顺序不一定是采集时间，也可以是约定的空间排列顺序，图像的例子在第 03 篇展开。

另一个会用到的词是 **上下文（context）**：这里指模型做当前预测时能够利用的已有信息，例如用户的问题和已经生成的文字；VLM 还可以利用图像信息。当模型生成了一个新 token，这个 token 就能加入后续预测的上下文。

## 速记要点

- token 是模型处理文字时使用的小单位，按输入中的位置排列起来就构成 token 序列；真实文本 token 可能是字、子词、字节片段或特殊标记，不固定等于一个汉字或单词。
- token ID 是词表索引；embedding 是通过索引取得的向量。ID 大小不表示语义距离。
- 语言模型在给定上下文后预测下一个 token 的分布，多次预测组成回答。
- 注意力根据内容计算不同位置之间的权重，再汇总向量信息；它不等于人类注视，也不直接证明模型理解正确。
- Transformer 还包含前馈网络、残差连接、归一化和位置信息，不能只把它理解成一次相似度计算。

## 1. 从一句话到一组向量

人为定义玩具词表：红=0，蓝=1，杯=2，<结束>=3。这里每个汉字作为一个 token，仅为解释；真实模型必须使用与权重配套的 tokenizer，不能拿这个词表代替。

**embedding 表（嵌入表）是一张存放 token 数值向量的表，在模型里通常表示为一个矩阵。** 每个 token ID 对应其中一行，这一行的数就是该 token 的初始向量表示。“查表”就是按 ID 取出对应行，供后续网络计算。

下面是配合本例的人为示意表，数字不是实际模型参数：

| token ID（行索引） | 对应 token | 该行存放的向量 |
| --- | --- | --- |
| 0 | 红 | [1.0,0.0] |
| 1 | 蓝 | [0.0,1.0] |
| 2 | 杯 | [0.5,0.5] |
| 3 | 结束标记 | [-0.5,0.0] |

这张表有 4 行、每行 2 个数，因此形状为 [4,2]。读取 ID 0 和 2，就得到“红”“杯”的两行向量；真实表的行数对应词表大小，每行的数目对应 embedding 维度。表中的数值属于模型参数，通常通过训练学习，使用预训练模型时随权重加载。

~~~text
文字“红杯” → token [“红”, “杯”] → ID [0, 2]
                                  ↓ 查 embedding 表
                                  [[1.0, 0.0],
                                   [0.5, 0.5]]
~~~

上面两行向量分别表示“红”和“杯”，所以张量形状为 [L, D]=[2, 2]；L 是序列长度，这里有“红”“杯”两个 token，所以 L=2；D 是每个 token 的特征维度，这里每行有两个数，所以 D=2。L 数的是有几个 token，D 数的是每个 token 用几个数表示，二者碰巧相等但含义不同。批量处理时常写为 [B, L, D]，B 是样本数。向量值无物理单位，不能把第二维当作米或角度。

**结果与解释（人为示意）：** ID [0,2] 通过查表得到两组数，供网络后续计算。ID 2 不比 ID 0“多两倍语义”；embedding 的单个分量也未必能命名为颜色、材质。训练可以改变 embedding 表，使其适合预测任务。

同一个“杯”最初可以查到相同向量；经过结合上下文的网络后，“红杯”和“奖杯”里的表示可以不同。初始 embedding 与后续隐藏状态要分开理解。

## 2. “预测下一个 token”怎样变成回答

假设问题和图像信息已进入模型，目前需要生成第一个回答 token。模型对上述四项玩具词表输出分数 z=[2,1,0,-1]，称为 logits，形状为 [4]。

将 logits 经过 softmax：

$$p_i=\frac{\exp(z_i)}{\sum_j\exp(z_j)}.$$

| 候选 token | logit | 概率，四舍五入 |
| --- | ---: | ---: |
| 红 | 2 | 0.6439 |
| 蓝 | 1 | 0.2369 |
| 杯 | 0 | 0.0871 |
| 结束标记 | -1 | 0.0321 |

**结果（静态计算，已由小程序核对）：** 若取概率最大的项，输出“红”。下一步把“红”加入上下文，重新计算分布；假设这次“杯”最大，再输出“杯”；第三步若结束标记最大，就结束。后两步是过程示意，没有给出或实测模型权重。

每次预测都依赖此前的上下文，称为**自回归（autoregressive）生成**。词表固定不意味着答案句子固定，模型可以组合 token 成不同序列，但仍受词表、上下文长度和学到的规律约束。

用温度 T 调整生成分布时，常将 softmax 的输入改为 z/T（T>0）。同一组 logits，T 较小时分布更集中，T 较大时更平；采样依据该分布随机选择，而贪心解码直接选最大项。部分框架用 temperature=0 表示贪心策略，但不能把 0 直接代入除法。

**解释：** 0.6439 是这个 token 在当前上下文和解码设置下的概率，不是“图里有红杯的事实可靠度为 64.39%”。降低温度也不会补回图中不可见的信息。

## 3. 为什么要注意力：把相关信息带到当前位置

读“红杯在蓝杯左边”，判断“左边的是谁”需要联系多个位置。若每个 token 只独立计算，就很难表达这些关系；注意力提供了按当前内容汇总其他位置信息的机制。

对每个位置的隐藏向量，网络用学到的线性变换生成三个表示：

| 名称 | 符号 | 入门理解 |
| --- | --- | --- |
| Query | q | 当前要从哪些内容取信息 |
| Key | k | 各位置提供怎样的匹配线索 |
| Value | v | 匹配后实际汇总的内容向量 |

这是帮助理解的比喻；Q、K、V 本质上是计算出的向量，不是人写的查询、物品标签或数据库记录。通常由 Q=XW_Q，K=XW_K，V=XW_V 得到，矩阵 W 是训练参数。

<a id="qkv-from-input"></a>

### Q、K、V 的数字从哪里来：从“红杯”一步步算

**不是把 Query、Key、Value 这三个英文词转换成数字，而是把每个 token 已有的数值向量，通过三组不同的权重，算出三种数值表示。** 小写 q、k、v 表示一个位置的向量；大写 Q、K、V 表示把多个位置的向量按行排在一起的矩阵。

沿用第 1 节的教学输入：

~~~text
“红” → ID 0 → 查 embedding 表 → x_红 = [1.0, 0.0]
“杯” → ID 2 → 查 embedding 表 → x_杯 = [0.5, 0.5]
~~~

这里 ID 只负责选中 embedding 表的一行。表里的数字才参与下面的计算，不能拿 ID 0 或 2 直接当作 q、k、v。

选取三组教学权重，采用“输入向量按行放置、右乘权重矩阵”的约定，并忽略偏置：

$$W_Q=\begin{bmatrix}1\\1\end{bmatrix},\qquad W_K=\begin{bmatrix}1\\-1\end{bmatrix},\qquad W_V=\begin{bmatrix}2&0\\-2&4\end{bmatrix}.$$

W_Q、W_K 的形状为 [2,1]，将两个输入数转换成一个输出数；W_V 的形状为 [2,2]，将两个输入数转换成两个输出数。**输入向量和权重数字都是人为选择的教学值，不是实际模型测得的参数。**

暂时不熟悉矩阵乘法也可以按下面的规则计算：对于输入 x=[a,b]，每个输出数都是“输入数乘对应权重，再相加”。

~~~text
q = x W_Q = [a×1 + b×1]       = [a+b]
k = x W_K = [a×1 + b×(-1)]    = [a-b]
v = x W_V = [a×2 + b×(-2), a×0 + b×4]
          = [2a-2b, 4b]
~~~

同一个输入 x 经过不同的权重，得到的 q、k、v 就可以不同。对两个 token 使用同一套三组权重，分别代入：

| token 与输入 | q 的计算 | k 的计算 | v 的计算 |
| --- | --- | --- | --- |
| 红：[1,0] | [1+0]=[1] | [1-0]=[1] | [2×1-2×0,4×0]=[2,0] |
| 杯：[0.5,0.5] | [0.5+0.5]=[1] | [0.5-0.5]=[0] | [2×0.5-2×0.5,4×0.5]=[0,2] |

**结果（静态计算，已由核对程序验证）：** 按“红、杯”的位置顺序排列，就得到 Q=[[1],[1]]，K=[[1],[0]]，V=[[2,0],[0,2]]。这两行分别属于两个 token；不是给整个句子只算一组 q、k、v。

在“杯”这个位置汇总信息时，取它的 q_杯=[1]，与两个位置的 k_红=[1]、k_杯=[0] 计算匹配，再用权重汇总 v_红=[2,0]、v_杯=[0,2]。这正是下面“两项手算例子”的数字来源。输入向量 → 三组权重变换 → Q/K/V → 匹配权重 → 信息汇总，是连续的计算过程。

### 输入向量和三组权重本身又从哪里来

真实模型中，embedding 表与 W_Q、W_K、W_V 都是模型参数。从头训练时按初始化方案赋值，随后根据训练损失和梯度不断调整；使用预训练模型时，通常直接加载已经训练好的参数。推理时给定这些参数和输入，Q、K、V 就由计算得到，通常不会再更新权重。

例如，训练目标要求下一 token 是“杯”，模型却给它很低的概率，训练会计算误差并沿网络传回梯度，调整相关参数。这些调整会影响后续算出的 q、k、v；我们不需要逐个规定“某个词的 q 应该是多少”。这里说明训练机制，没有实际训练或演示某一步参数更新。

本例为单头、无偏置的简化计算，直接用 embedding 当作输入，省略位置处理、归一化等步骤。真实多层网络中，某层的 X 是送入该层注意力的隐藏表示，未必仍是最初的 embedding；不同层或头有各自的参数，但同一头对不同 token 位置共享对应权重。

Q、K、V 的区别在于后续怎样使用：Q 与 K 比较形成权重，V 被这些权重加权汇总。它们的每个分量通常没有预先命名的语义，本例也不能把 q=1 解读成“正在寻找红色”。

对一个 query，缩放点积注意力为：

$$a_j=\operatorname{softmax}_j\left(\frac{q\cdot k_j}{\sqrt{d_k}}\right),\qquad o=\sum_j a_jv_j.$$

d_k 是 q、k 的维度；除以其平方根有助于控制点积分数的尺度。多个 query 合起来写为 softmax(QKᵀ/√d_k)V，softmax 分别沿每个 query 对应的 key 维度计算。公式来自 [Transformer 原论文 §3.2](https://arxiv.org/html/1706.03762v7#S3.SS2)，下例是本仓库选定的教学数值。

### 两项手算例子

接着上面的计算，选“杯”位置的 q=[1]；“红”“杯”两个位置分别提供 k₁=[1]、k₂=[0]，所以 d_k=1；两个 value 为 v₁=[2,0]，v₂=[0,2]。key 维度为 1，value 维度为 2，允许不同。这是在“杯”位置汇总当前和此前的信息，没有读取未来 token。

~~~text
匹配分数：[1, 0]
注意力权重：softmax([1, 0]) = [0.731059, 0.268941]
输出：0.731059×[2,0] + 0.268941×[0,2]
    = [1.462117, 0.537883]
~~~

**结果与解释（静态计算，已核对）：** 第一个 value 占比较大，但第二个仍有贡献。输出是两个信息向量的加权和，不是“已锁定第一个物体”的离散决定；权重也没有米、像素等单位。真实网络还会通过后续层组合和变换这些信息。

## 4. self-attention、cross-attention 和因果遮罩

| 机制 | Q、K、V 来自哪里 | 起什么作用 |
| --- | --- | --- |
| 自注意力 self-attention | 同一个序列的不同位置 | 将序列中的上下文信息联系起来 |
| 交叉注意力 cross-attention | Q 来自一个序列，K/V 来自另一个 | 例如让文本状态读取视觉特征 |
| 因果遮罩 causal mask | 在分数上遮住未来位置 | 生成文字时不能借用尚未生成的答案 |

若视觉表示和文字表示拼在同一序列里，自注意力也能跨图文位置传递信息。因此“图文交互”不一定需要一个独立命名的 cross-attention 层，取决于架构。

**例子：把英文 `The cat sleeps` 翻译成中文“猫在睡觉”。** 这里假设使用**编码器—解码器（encoder–decoder）模型**，即由“处理输入”和“生成输出”两部分配合工作的神经网络：

- **编码器（encoder）**读取完整英文，把每个输入 token 转换成结合句子上下文的特征向量，供生成译文时使用。
- **解码器（decoder）**利用编码器输出的这些向量和已经生成的中文，预测下一个中文 token 的概率分布；选出新 token 后继续，直到输出结束标记。这就是第 2 节逐 token 生成回答的过程，只是这里还会读取编码器提供的信息。

为方便说明，人为把英文拆成 `[The, cat, sleeps]`，中文拆成 `[猫, 在, 睡觉]`；这些切分和下面的信息联系都是教学示意，不是实际模型测得的结果。

| 在这个例子里 | 信息怎样流动 | Q、K、V 的来源 |
| --- | --- | --- |
| 编码器的 self-attention | `cat` 位置可以汇总 `The`、`cat`、`sleeps` 的信息，让“猫”的表示带上句子上下文 | Q、K、V 都来自英文序列的隐藏表示；这里允许读取完整英文 |
| 解码器的 self-attention | 已生成“猫”，准备预测“在”时，当前中文位置可以汇总开始标记和“猫”的信息 | Q、K、V 都来自中文侧的隐藏表示；可见位置受因果遮罩限制 |
| 解码器的 cross-attention | 同样在预测“在”时，中文侧还可以读取完整英文的编码结果，利用原句表达的含义 | Q 来自中文侧当前状态，K/V 来自英文编码器的输出 |

**因果遮罩规定中文侧“能看哪些位置”。** 训练时可把完整目标句放入计算，但解码器输入与预测目标要错开一位：

~~~text
解码器输入：[开始, 猫, 在, 睡觉]
预测目标：  [猫,   在, 睡觉, 结束]
~~~

| 当前输入位置 | 中文 self-attention 允许读取 | 该位置要预测的下一个 token |
| --- | --- | --- |
| 开始 | 开始 | 猫 |
| 猫 | 开始、猫 | 在 |
| 在 | 开始、猫、在 | 睡觉 |
| 睡觉 | 开始、猫、在、睡觉 | 结束 |

**结果与解释（教学示意）：** 在输入“猫”的位置预测“在”时，模型能读取当前的“猫”，但不能读取右侧输入位置上的“在”或“睡觉”，否则就提前看到了答案。遮罩在 softmax 之前将这些未来位置的匹配分数设为负无穷，使对应权重为 0。完整英文是事先给定的条件，因此本例的 cross-attention 可以读取全部英文位置。

两种注意力的区别在于信息来源；因果遮罩限制的是信息的可见范围。换成 VLM 时，也可以让中文侧的 Q 读取图像编码器提供的 K/V；是否采用这样的 cross-attention 结构取决于模型设计。

训练可以同时计算多个位置的预测并用遮罩限制信息流；生成时后一个未知 token 要等前一步选择之后才能继续。两者并不矛盾。

## 5. Transformer 还有什么

多头注意力使用不同的投影并行计算，再组合结果，增加表示能力；不能保证某个头固定负责“颜色”、另一个固定负责“位置”。前馈网络进一步变换各位置向量；残差连接和归一化帮助信息传播与训练。

序列还需要位置信息，才能区分 token 的顺序或图像 patch 的位置。否则单看一组内容向量，很难区分“红杯在蓝杯左边”与“蓝杯在红杯左边”。位置编码方案因模型而异，不必先背完整实现才能理解 VLM。

原始 Transformer 是编码器—解码器结构；不少自回归语言模型采用 decoder-only 结构。这里介绍共通机制，不把原论文的每层结构当作所有 LLM 的固定配置。
