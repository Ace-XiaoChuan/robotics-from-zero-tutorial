# VLM 04：训练学什么，推理怎样评估

本文行数：140行，预期阅读时长：9分钟

**VLM 训练让图文表示更有用，或让生成的回答更接近目标答案；推理使用已有参数。** 看懂这个区别，才不会把改提示、冻结模型和微调混成同一件事。

## 速记要点

- 预训练学习广泛规律，图文对齐建立跨模态联系，指令微调学习按问题组织回答；真实模型可能组合或合并这些阶段。
- 对比学习比较图文配对；生成训练预测目标回答 token，两种 loss 不能混用。
- 监督微调使用图像、问题、目标回答；训练时答案用于计算 loss，推理时不能要求提供正确答案。
- 冻结是不更新参数，不是跳过该模块。LoRA 用少量可训练参数表示权重增量。
- 改提示通常不改权重；减少随机采样通常不提升模型的视觉证据。
- 评估要针对具体任务、独立数据和失败行为；平均 benchmark 分数不能代替本机器人场景的效果。

## 1. 先分清训练阶段与参数来源

例如构建一个教学 VLM：已有视觉编码器，已有语言模型，一个新连接器。连接器随机初始化时，虽然它能输出正确维度，LLM 还未必能利用视觉特征。

| 阶段 | 数据形式 | 希望学会什么 |
| --- | --- | --- |
| 视觉 / 语言预训练 | 图像任务数据或文本序列等 | 分别建立视觉表示和语言预测能力 |
| 跨模态适配 / 对齐 | 图文配对，或转换成描述任务的数据 | 建立视觉表示与语言侧的联系 |
| 视觉指令微调 SFT | 图片 + 问题 / 指令 + 目标回答 | 根据图像回答用户实际提出的问题 |
| 任务或领域微调 | 例如机器人相机中的目标数据 | 适配视角、物体、输出语义与特定领域 |

SFT 是 Supervised Fine-Tuning（监督微调），使用目标回答作为学习信号。“自监督”则常从原始数据构造预测目标，例如文本后续 token；不等于没有 loss 或无需任何数据处理。图文数据可能来自自然配对、人工标注或生成，需要检查质量。

阶段名称并不决定 loss：图文对齐可以用对比损失，也可以训练图像描述的 token 预测。**不能把 CLIP 的对比预训练和所有 VLM 的对齐阶段当作同一算法。**

[原始 LLaVA 论文 §4.2](https://arxiv.org/html/2304.08485v2#S4.SS2)的阶段一冻结视觉编码器和 LLM、训练投影层；阶段二继续冻结视觉编码器，更新投影层与 LLM。这个例子展示了参数范围随阶段变化，不能推广为所有 VLM 的固定冻结方案。

## 2. 生成式训练的一个完整小例子

假设图片 I 与问题 Q 的目标答案只有两个教学 token：“红”“杯”。真实答案可能切成更多 token，本页忽略结束标记，仅对这两个目标位置计 loss。

~~~text
第 1 个位置：给定 I、Q，预测“红”
第 2 个位置：给定 I、Q、正确的“红”，预测“杯”
~~~

训练时给后续位置提供正确历史 token，称为 teacher forcing（教师强制）。虽然整个目标序列可一起输入计算，因果遮罩和目标错位让预测位置不能偷看自己的目标或未来目标。

采用回答位置平均交叉熵：

$$L=-\frac1N\sum_{t=1}^{N}\ln p_\theta(y_t\mid I,Q,y_{<t}).$$

θ 是需要训练的参数集合；N 是参与 loss 的回答 token 数，本例为 2；ln 为自然对数，所以这里的损失按 nats 计，不是准确率或物理误差。

| 目标位置 | 正确 token 的预测概率（示意） | 对 loss 的贡献 |
| --- | ---: | ---: |
| 红 | 0.8 | -ln0.8 ≈ 0.223144 |
| 杯 | 0.5 | -ln0.5 ≈ 0.693147 |

**结果（静态计算，已核对）：** 平均 loss 为 (0.223144+0.693147)/2≈0.458145。训练提高目标 token 的概率，通常会降低该损失；这里没有执行梯度更新，也没有训练真实 VLM。

回答 token、用户问题、系统提示、图像占位与 padding 的 loss 处理要区分。常见 SFT 配置只监督 assistant 的回答位置，将其余位置标为忽略；某些训练方案也监督其他位置，实际以数据与代码为准。loss mask 决定哪些位置计误差，attention mask 决定哪些位置可读信息，二者功能不同。

推理时第二步用的是模型自己输出的历史 token，而不是教师答案。如果第一步错误输出“蓝”，后续可能继续生成“蓝杯”。训练 loss 低不保证自由生成正确，也不保证模型事实依据充分。

## 3. 冻结、全量微调与 LoRA

| 方式 | 更新哪些量 | 适合建立的印象 |
| --- | --- | --- |
| 冻结骨干、只训连接器或任务头 | 新模块参数 | 借用已有表示，学新接口 |
| 全量微调 | 所选模型部分的全部权重 | 适配能力强，但训练资源和数据需求较高 |
| LoRA | 选定层上的低秩增量参数 | 减少可训练参数，而不是省掉基础模型计算 |
| 只改提示 | 通常无参数更新 | 改变推理条件和任务表达 |

冻结视觉编码器后，图片仍必须通过它计算特征。冻结 LLM 后，若要训练其前面的连接器，仍可能需要梯度通过 LLM 的计算传回连接器；把整个 LLM 前向放进禁止梯度的上下文，会切断这条路径。“不更新某模块权重”与“不构建任何梯度路径”不是同义词。

LoRA 将权重增量写成两个较小矩阵相乘：

$$W'=W+\Delta W,\qquad \Delta W=\frac{\alpha}{r}BA.$$

若 W 形状为 [m,n]，则 A 为 [r,n]，B 为 [m,r]；r 是低秩维度，α 是缩放参数。常见设置冻结 W，训练 A、B；是否还训练其他层由方案决定。结构可对照 [LoRA 原论文](https://arxiv.org/abs/2106.09685)。

**参数量示例（静态推导，已核对）：** m=n=4096，r=8。原矩阵有 4096²=16,777,216 个参数，A、B 合计 8×4096+4096×8=65,536 个，约为 0.390625%。只比较这一层，不代表整个 VLM 都缩小到这个比例；基础权重仍须加载，激活和优化器等也占资源。

量化降低权重等数值的存储精度，与 LoRA 减少可训练参数解决不同问题；两者可以组合，但量化不自动消除推理的激活内存、视觉 token 成本或输出误差。

### 冻结权重以后，梯度怎样传回连接器

**冻结模块的梯度小例子：** 输入 x=2，可训练连接器 `z=wx`，w=0.5；固定的下游模块 `y=3z+1`，目标为 7、loss=`½(y−7)²`。前向得到 z=1、y=4、loss=4.5，链式梯度 `∂L/∂w=(4−7)×3×2=−18`。学习率 0.01 后 w=0.68、y=5.08、loss=1.8432；固定系数 3 和偏置 1 不更新。

**结果（解析与数值差分一致）：** 下游权重固定，但其计算仍传回梯度。若在 z 后停止梯度，则这个数据损失不能训练前面的 w。例子不是实际 LLM，只把冻结与求导的关系缩为可看清的线性链；回查 [06](../06_pytorch_networks/README.md)的计算图与 [11](../11_training_optimization/README.md)的模式、梯度和优化器区别。

LoRA 也不能简单等同于停止梯度。对冻结基础 W，输入仍通过 `Wx+(α/r)BAx` 计算；A/B 的更新改变函数。训练检查应看可训练参数、梯度路径和实际参数变化，而非只看模块是否命名为“冻结”。

## 4. 提示能改进什么

对桌面图，可以写清：“仅依据图像，回答左边杯子的颜色；若被遮挡或无法判断，请说明。”这让任务对象、回答范围和不确定处理更明确，属于**建议提示，未实测**。

提示可以改变模型行为，不能让不存在的定位头自动出现，也不能可靠地强制所有未知情况都拒答。要求返回 JSON 只是结构约束；JSON 内的事实和坐标仍需验证。

多轮对话中，旧问题、旧回答和新图片如何组织也会影响条件。机器人图像更新后，应标明时间并防止把旧回答误当新图事实；一次截图无法单独证明当前还可抓取。

## 5. 怎样判断模型确实利用了图像

下面是建议评估设计，没有运行真实模型。保持问题“左边杯子什么颜色？”不变：

| 对照输入 | 期望事实答案 | 能检查什么 |
| --- | --- | --- |
| 左红右蓝 | 红色 | 基础识别与关系 |
| 左蓝右红 | 蓝色 | 是否随位置交换而改变回答 |
| 左侧被遮挡且颜色不可见 | 无法确定 | 是否把猜测当成观察 |
| 相同问题，换成没有杯子的图 | 图中无杯子或无法定位 | 是否依据问题编造物体 |
| 同图改问右侧杯子 | 蓝色（在首图条件下） | 是否响应指定对象 |

**结果与解释：** “换图后回答不变”是值得排查的现象，但不能单独证明某个内部故障；需要再核对图片是否加载、模板、预处理和任务难度。多组对照比一条看似正确的回答更能说明适用范围。

图像缺失的对照只能在接口支持时使用；不应把接口报错当作“模型已拒答”。遮挡、空场景和目标不唯一也应作为独立失败类别记录。

物体幻觉是指生成图像中不存在或缺乏支持的物体描述。[POPE 论文](https://arxiv.org/abs/2305.10355)提出用物体相关问题评估这一现象。本专题借此强调事实检查，不把“有无某物体”的测试当作位置、数量、材质与机器人任务的完整评估。

## 6. 指标怎样选

| 任务 | 可用的评价方式 | 局限 |
| --- | --- | --- |
| 图文检索 | Recall@K：正确候选是否在前 K 个 | 要固定候选池与正确匹配定义 |
| 颜色、数量等封闭问答 | 答案准确率，必要时先规范等价表达 | 文本完全相等会误罚“红”“红色”等等价答案 |
| 描述 | 按对象、属性、关系逐项核对；记录无依据内容 | 文字流畅度不等于事实正确 |
| 定位 | 框/掩码指标，如 IoU | 不代表三维位置或抓取成功 |
| 机器人系统 | 独立场景的闭环成功率、延迟、失败类别 | 需把感知、规划、控制各环节分开记录 |

IoU 是预测区域与真值区域的交集面积除以并集面积，无单位。语言模型自己给答案打分可作为辅助，但应核对评价者偏差，不能直接当作客观真值。

训练、验证、测试按独立场景或 episode 划分，防止同一视频的相邻帧散到不同集合。预训练是否包含测试数据往往也需说明；无法确认时，不声称完全无污染。

需要实现时，保留模型与处理器版本、数据来源与划分、提示/模板、输入分辨率、解码配置、输出解析规则以及原始失败例子。普通推理耗时要区分预处理、模型计算和后处理，不能只报告某一段而宣称机器人反应周期。

## 7. 资源需求先怎样理解

如果有 30 亿参数，每个参数按 2 字节存储，仅权重约为 6×10⁹ 字节，即 6 GB（十进制）或约 5.59 GiB。还没算视觉模块是否已包含在参数总数里、激活、KV cache、工作空间等；训练还有梯度与优化器状态。这是存储估算，**不是显存实测或运行最低配置**。

KV cache 是生成时缓存已有位置的 key/value 以复用计算，不是持久知识库；上下文变长通常会增加其资源开销。部署要根据具体模型、精度、图片数量与上下文长度测量，本次不安装环境或下载模型。
