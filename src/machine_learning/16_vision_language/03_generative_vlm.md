# VLM 03：图片怎样进入语言模型，变成回答

本文行数：140行，预期阅读时长：9分钟

**生成式 VLM 的关键是让视觉表示成为语言生成的条件。** 图片先经过视觉网络，文字经过 tokenizer 和 embedding，模型结合两者逐 token 生成答案。

## 速记要点

- 视觉编码器把像素变成特征；连接器把视觉特征转换到语言模型能使用的形式；语言模型生成回答。
- 视觉 token 一般是连续特征向量，不是 tokenizer 给每块图片分配一个汉字 ID。
- 原始 LLaVA 用投影连接视觉编码器和 LLM；BLIP-2 用 Q-Former 获取视觉信息，结构并不完全相同。
- 仅让向量维度相等，无法保证 LLM 看懂图像；连接方式和训练同样关键。
- processor 负责准备图片、文字及模板。图片文件路径只是读取入口，真正的视觉内容必须被加载和编码。
- 能生成描述不保证能做像素定位，更不保证三维几何、时间推理或机器人动作正确。

## 1. 先看完整数据流

这是便于理解的“视觉编码器 + 投影连接器 + 自回归 LLM”结构。尺寸是教学配置，不对应某个实际 checkpoint。

~~~mermaid
flowchart TD
    A["RGB 图片"] --> B["预处理：缩放与归一化"]
    B --> C["视觉编码器：像素变特征"]
    C --> D["连接器：转换特征维度或组织方式"]
    E["问题文字"] --> F["Tokenizer 与文本 embedding"]
    D --> G["语言模型结合视觉与文字"]
    F --> G
    G --> H["下一 token 的 logits"]
    H --> I["解码，加入已生成文字，再继续"]
    I --> J["最终回答"]
~~~

| 环节 | 教学输入 → 输出形状 | 在做什么 |
| --- | --- | --- |
| 原始照片 | [480,640,3] | 高、宽、RGB 通道；像素值尚未归一化 |
| 示例预处理 | [480,640,3] → [1,3,224,224] | 改成批次、通道、高、宽顺序并缩放；B=1 |
| 切 patch 并编码 | [1,3,224,224] → [1,196,768] | 每个 16×16 patch 编成 768 维，再由视觉网络联系各位置 |
| 连接器 | [1,196,768] → [1,196,4096] | 将每个视觉 token 转换成语言侧能接收的维度 |
| 文本 embedding | [1,L] 个 token ID → [1,L,4096] | 将问题 token 转成向量 |
| 拼接后的输入示意 | [1,196+L,4096] | 此例只拼视觉 token 和文本；真实系统还有特殊标记等 |
| 预测下一个 token | 当前隐藏状态 → [1,V] | V 为语言词表大小，输出 V 个 logits |

**结果与解释：** 视觉编码器输出的是 196 组特征，不是 196 个物体。4096 是向量维度，不是图片宽度。真实模型的分辨率、patch 大小、维度、特殊 token 和视觉 token 数量都要看对应配置。

不少架构会保留额外的全局 token，或使用多裁剪、动态分辨率、token 合并；本表忽略这些变化，只说明一个连续的数据流。无需把表中数字背成 VLM 统一规格。

## 2. patch 是什么，为什么图片也会形成序列

patch 是图片中的一个小块。224×224 图片，每块 16×16、不重叠且没有补边时，一边有 14 块，共 14×14=196 块。

每块原来有 16×16×3=768 个 RGB 数值。可以先展平成向量，再用学到的映射生成 patch embedding。这里选择 embedding 维度也为 768，仅是教学配置；像素数与特征维度不必相同。

~~~text
2×2 分块的缩小示意：
[左上块] [右上块]        → 按约定顺序：[左上、右上、左下、右下]
[左下块] [右下块]          + 位置信息 → 视觉网络
~~~

**结果与解释：** 不同块的内容和位置经过网络共同处理，才形成后续视觉特征。切块不是物体检测；一只杯子可能跨多个 patch，一个 patch 也可能包含杯子与背景。

增加输入分辨率可能保留小字或远处物体的细节，但会增加视觉 token 或裁剪数量、内存和计算成本；生成回答的上下文预算也可能受到影响。不是“越大一定越准确”。

把宽高比 4:3 的图直接缩成正方形会改变外观比例；中心裁剪可能去掉画面边缘的红杯。此处直接缩放只是展示形状变化，实际处理应与模型训练时一致，不能沿用第 07 章的预处理后默认兼容。

## 3. 连接器究竟学什么

假设单个视觉 token 是 h=[2,1]，为了接入三维语言表示，用教学矩阵：

$$W=\begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix},\qquad b=\begin{bmatrix}0\\0\\0\end{bmatrix},\qquad z=Wh+b=\begin{bmatrix}2\\1\\3\end{bmatrix}.$$

这里按列向量约定：h 是 [2,1] 形状，W 是 [3,2]，z 是 [3,1]；所有数都无量纲。上文批次形状按行存储 token，实现时相当于右乘 Wᵀ。

**结果（静态推导，已核对）：** 两个特征变成三个。它解决了维度接口，但随机选定这组 W 并没有让模型学会认红杯。训练还要让转换后的表示有助于正确回答，不能把“矩阵乘法成功”当作语义对齐成功。

连接器可以是单线性层、多层感知机（MLP），或更复杂的查询/重采样模块。它有时也减少 token 数量，不只是扩展每个向量的维度。

## 4. 用两个代表结构建立印象

[原始 LLaVA（Visual Instruction Tuning，2023）](https://arxiv.org/html/2304.08485v2#S4)把视觉编码器的特征通过投影层接入 LLM，使回答受图像和指令共同影响。本页的投影数据流借此解释接口，但数值不是论文配置。后续 LLaVA 版本有不同连接器、分辨率和训练方案，应按具体版本查证。

[BLIP-2（2023）](https://arxiv.org/abs/2301.12597)在冻结的图像编码器和大语言模型之间训练 Q-Former。它用可学习查询读取视觉特征，再桥接语言侧；这说明跨模态连接还可以通过查询机制完成，不必把所有视觉 patch 原样拼进 LLM。

| 方法 | 用来建立的印象 | 输出类型 |
| --- | --- | --- |
| CLIP | 两个编码器把图文映射到可比较的空间 | 特征或匹配分数 |
| 原始 LLaVA | 用视觉表示给语言生成增加条件 | 回答 token 序列 |
| BLIP-2 | 用查询模块从视觉表示提取连接信息 | 支持图像条件的语言任务 |

CLIP 的文本编码器负责产生匹配用的文本表示，生成式 VLM 中的 LLM 负责生成语言。视觉骨干使用了 CLIP 预训练知识，并不等于整套系统只是在运行 CLIP 的文本匹配接口。

## 5. 例子：问“左边的杯子是什么颜色”

输入还是专题首页的照片，问题为“左边的杯子是什么颜色？”。答案示意为“红色”，没有运行真实模型。

1. 图像预处理保留两个杯子，视觉网络生成带空间信息的表示。
2. tokenizer 编码问题，语言模型获得“左边”“杯子”“颜色”等问题信息。
3. 视觉与语言表示在模型中交互，为回答提供条件。
4. 语言模型生成“红色”对应的 token 序列并结束。

**结果与解释：** 这表示架构提供了使用图像回答的路径，但不能据此确定某层一定找到红杯、某个注意力头一定判断左右。真正的事实准确率要通过换图、遮挡、互换位置等对照检查。

若模型在“左红右蓝”和“左蓝右红”两张图上都回答红色，它可能没有正确利用图像关系；也可能预处理裁掉了目标或问题模板有误。单条正确回答不足以定位它学到了什么。

## 6. 源码里常见的三个对象

| 名称 | 作用 | 与其他对象的区别 |
| --- | --- | --- |
| tokenizer | 文字与 token ID 之间的转换 | 不能代替图片解码与预处理 |
| processor | 组织文本处理、图像预处理和模型所需输入 | 具体包含哪些处理器取决于模型 |
| model | 用输入张量执行前向计算或生成 | 权重必须与配置、处理器兼容 |

多模态消息通常同时包含图像内容项与文字内容项，聊天模板再加入角色和控制标记。官方 [Transformers 多模态模板文档](https://huggingface.co/docs/transformers/main/en/chat_templating_multimodal)展示了 processor 生成文本 ID、像素张量及可能的网格字段。本文只解释职责，不把文档中的 main 分支 API 当作已在本仓库验证的运行入口。

给普通文本模型发一句“请看 /tmp/cup.jpg”，不会自动让它读取图片。支持路径输入的上层接口会负责读取文件；最终仍要把视觉数据交给支持该模态的模型。

## 常见误解

| 现象或说法 | 应核对什么 |
| --- | --- |
| 回答里有图像细节，说明图片传成功 | 它也可能根据提示猜测；检查真实输入和换图响应 |
| 视觉 token 就是识别出的物体标签 | 通常是连续特征，不是类别清单 |
| 使用相同维度，任何编码器都能接任意 LLM | 还缺兼容的连接结构和训练 |
| 没有单独 cross-attention 就无法看图 | 拼接序列的 self-attention 也可以交换图文信息 |
| 给框坐标格式，模型就能检测 | 输出格式约束不等于定位能力，需匹配训练与评估 |

## 7. 视觉 token 数与查询压缩

同样采用 16×16 patch、无额外 token，224×224 图有 196 个视觉 token，448×448 图有 784 个，增加为 4 倍。仅看视觉序列的标准全注意力分数矩阵，元素数增加为 16 倍；若还加入文字、分块或特殊 token，要按实际总长度重新算，不能把这一比例当成显存实测。

连接器也可以改变 token 数量。**一个查询汇总演示，非完整 Q-Former：** 四个视觉 token 为 `H=[[1,0],[0,1],[1,1],[0,0]]`，两个查询为 `Q=[[1,0],[0,1]]`，令 K=V=H，d_k=2，执行一次 cross-attention。

**结果（静态计算）：** 输出约为 `[[0.669762,0.5],[0.5,0.669762]]`，形状从四个视觉位置的信息变成两个查询输出，每项仍为二维。查询是模型表示，不是“红杯”和“蓝杯”的固定对象标签；此处数值由 [14 的注意力公式](../14_attention_transformer/README.md)计算。

查询模块可以再把 `[B,M,d_visual]` 投影为 `[B,M,d_language]`，M 是查询数量。减少 token 能压缩接口，但可能丢失小字、细小物体或空间关系；不能由维度正确与查询数较少推出信息仍完整。[BLIP-2 原论文](https://arxiv.org/abs/2301.12597)的 Q-Former还包含其具体层、可学习查询和训练任务，本例只演示读取与长度改变。

把视觉 token 放到 decoder-only 的文字前缀时，后续文字能读取哪些图像/文本位置取决于整个 attention mask。把多个视觉位置统一用下三角遮罩也可能让早期视觉位置读不到后面的图像块；实际模型可能给视觉前缀不同可见范围。需要检查模型设计，不能仅从“decoder”这个名称推断所有模态的 mask。[13](../13_sequence_models/README.md)与 [14](../14_attention_transformer/README.md)提供结构回查。
