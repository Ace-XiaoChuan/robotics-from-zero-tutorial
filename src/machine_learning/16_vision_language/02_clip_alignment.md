# VLM 02：CLIP 怎样把图片和文字联系起来

本文行数：156行，预期阅读时长：8分钟

<a id="developer-overview"></a>

## 开发者理解：用文字候选匹配图片

**CLIP 是图文匹配模型：把图片与文字分别形成表示，再比较它们的相关程度。** 可以用图片找相关描述，也可以用文字从图库找相关图片；核心输出是特征与匹配分数，不是自动生成一段回答。

**例子（沿用教学候选）：** 给一张红杯图片和“红杯、蓝杯、猫”三项描述，输出各项分数和排名。若红杯排名第一，表示它在这些候选中最匹配；若只给“蓝杯、猫”，简单的最大分数规则仍会选一个候选，不能据此认定图片就是蓝杯。本页向量和排名是人为教学构造，未运行真实 CLIP。

| 功能 | 输入 | 输出含义 |
| --- | --- | --- |
| 图片选描述 | 图片与一组文字候选 | 候选之间的匹配排名 |
| 文字找图片 | 查询文字与候选图库 | 相关图片的排名 |
| 特征复用 | 图片或文字 | 可用于后续检索等任务的表示 |

**图文对齐**是通过学习让相关图片和文字可以在表示中比较，不是把文字变成实际物体坐标。特征相近表示语义相关，不说明两个物体在空间上靠近。

相比训练一个固定类别的分类头，推理时可以改文字候选来表达新任务。**零样本**通常表示没有为这个下游任务使用带标签数据重新拟合；模型本身已经预训练，不代表它从未见过类似内容，也不保证新场景都能识别。

候选的数量、描述方式和分数处理会影响排名或相对分布。分数变高不等于图像事实更确定，未知对象也不会自动被拒绝。整图匹配还可能缺少细粒度位置与左右关系，若要定位某个物体，需要相应区域信息或定位能力。

**需要深入时：** [与分类头的区别](#1-与第-07-章的三分类头相比) · [匹配计算](#2-一个能手算的图文匹配) · [零样本与适配](#4-零样本少样本和上下文例子) · [候选变化](#candidate-changes)。

**图文匹配模型把图片与文字各自编码为向量，学习让匹配的一对更相似。** 先看这条路线，就能理解 VLM 不一定要生成句子。

## 速记要点

- CLIP（Contrastive Language-Image Pre-training,对比式语言图像预训练）是代表性的双编码器方法：图像编码器和文本编码器分别处理各自输入。
- 对齐后的向量可用于图文检索，或把候选类别写成文字进行匹配。
- 推理时改候选文字，不等于重新训练分类头；“零样本”指对这个下游任务没有使用训练样本拟合，模型本身仍经过预训练。
- 相似度回答“与这些候选相比更像哪一个”，不能自动判定图像真相或候选是否完整。
- 图文语义对齐不是外参标定，特征距离也不是三维空间距离。

## 1. 与第 07 章的三分类头相比

此前 ResNet18 案例把一张图映射到三个固定类别：纸张、纸板、金属。新分类头用这些标签训练，输出维度固定为 3。

图文匹配换了输出组织方式：

~~~text
图片 I ──图像编码器及投影──→ 图像向量 u ─┐
                                         ├─ 相似度 → 候选排名
文字 T ──文本编码器及投影──→ 文本向量 v ─┘
~~~

两边最终向量维度必须一致，才能做点积。中间骨干网络可以不同；“同维度”本身不保证有共同语义，跨模态训练才提供这种联系。[CLIP 原论文](https://proceedings.mlr.press/v139/radford21a.html)用图文配对学习可迁移的视觉表示，并以自然语言指定下游概念。

**结果与解释：** 增加“一个玻璃杯”的候选时，可以编码新文字与图片比较，而不必把原三分类头改成四分类再训练。但在目标领域能否正确识别，仍取决于预训练知识、图像质量和评估，不能由接口灵活性推出。

## 2. 一个能手算的图文匹配

为便于计算，假设图像编码结果是 u=[3,4]，三个文本候选向量为：

| 候选描述 | 向量 v | 向量长度 |
| --- | --- | ---: |
| “红杯” | [3,4] | 5 |
| “蓝杯” | [4,3] | 5 |
| “猫” | [-3,-4] | 5 |

这些向量是人为选择，**不是实际 CLIP 特征**；两维只是降低计算量，不能把第一维解释为颜色、第二维解释为形状。

余弦相似度消除向量长度的影响：

$$s(u,v)=\frac{u\cdot v}{\|u\|\|v\|}.$$

| 候选 | 点积 | 余弦相似度 |
| --- | ---: | ---: |
| 红杯 | 25 | 1.00 |
| 蓝杯 | 24 | 0.96 |
| 猫 | -25 | -1.00 |

**结果（静态计算，已核对）：** 红杯排名第一，蓝杯也很接近。“接近”发生在特征空间，不表示两个杯子的物理位置接近。分数本身没有米、像素等单位。

若只给“蓝杯”和“猫”，模型仍会选蓝杯；正确候选未提供，就无法通过简单最大值规则选出红杯。所以检索接口若需要“都不匹配”，还得设计拒绝规则并在目标数据上验证。

### 为什么分数经过 softmax 也不能当作事实概率

为显示排名分布，取本页人为设定的温度 τ=0.1，将相似度除以 τ 后做 softmax：

~~~text
logits = [10, 9.6, -10]
softmax ≈ [0.598688, 0.401312, 0.000000001234]
~~~

这只是在**三个候选和当前温度**下的相对分布。改候选或温度，数值会变；不能解释成红杯“有 59.87% 的真实概率”。原始 CLIP 的缩放系数通过训练学习，本页固定温度仅用于算术示例。

特征匹配的温度与上一页生成采样的温度都用于缩放分数，但使用位置和目的不同，不要把它们当作同一个运行参数。

## 3. 训练时怎样知道什么应该靠近

设一个批次只有两对数据：(红杯图, 红杯描述)、(蓝杯图, 蓝杯描述)。先把图文向量归一化，假设两对分别得到正交单位向量 [1,0] 和 [0,1]，得到相似度矩阵：

~~~text
                 文本：红杯   文本：蓝杯
图像：红杯           1            0
图像：蓝杯           0            1
~~~

矩阵形状为 [B,B]=[2,2]，不是二维空间中的物体位置。对角线是本批次的配对，非对角线作为不配对候选。

教学温度 τ=0.5，则第一行 logits 为 [2,0]，正确配对概率为：

$$p=\frac{e^2}{e^2+e^0}\approx0.880797,\qquad -\ln p\approx0.126928.$$

对每张图，把正确文字当作候选分类标签，计算交叉熵；再交换方向，对每段文字选择正确图片。两个方向的平均就是本页的对称对比损失。一般写为：

$$L=\frac12\left[\frac1B\sum_i-\ln\operatorname{softmax}_j(S_{ij}/\tau)_i+\frac1B\sum_j-\ln\operatorname{softmax}_i(S_{ij}/\tau)_j\right].$$

S 为 [B,B] 的余弦相似度矩阵，i 索引图像，j 索引文字；每对图文对应同一个索引。这里假设每个样本只有一个正确配对。对称交叉熵的结构可对照 [CLIP 论文 Figure 3](https://proceedings.mlr.press/v139/radford21a/radford21a.pdf)；上述正交向量是本仓库的简化示例。

**结果（静态计算，已核对）：** 本例行列对称，两方向平均 loss 都为 0.126928。若所有相似度都为 0，每行正确概率只有 1/2，loss 为 ln2≈0.693147；正确配对更突出，loss 更低。

模型通过梯度更新编码器等参数，让真实配对更易区分。它学的是跨模态关联，不是简单把原图和句子保存成一张查找表。真实训练涉及更多批次、更高维表示及数据质量问题。

如果批次里两张图都能被“杯子”正确描述，非对角项也可能语义匹配；“配对标签不同”不保证“语义完全相反”。这是对比数据中可能出现的假负例，不应把矩阵构造规则当作世界事实。

## 4. 零样本、少样本和上下文例子

| 名称 | 在目标任务上做什么 | 是否必然改权重 |
| --- | --- | --- |
| 零样本 zero-shot | 用已有模型和任务描述直接预测 | 否 |
| 少样本 few-shot 微调 | 用少量目标样本训练或适配 | 是，具体更新范围依方法 |
| 上下文学习 in-context learning | 在提示里给例子，再要求回答 | 通常不改权重，且需模型支持 |

“few-shot”也有人用于提示里放少量例子，阅读资料时要看它具体指哪一种。预训练数据中是否已有类似物体，和下游是否使用标签重新训练，是不同问题；零样本不等于模型从来没见过类似概念。

写“a photo of a red cup”与只写“red cup”可能产生不同特征。候选描述、语言和措辞属于评估配置，应固定记录；改提示后提高分数不等于已提高独立测试准确率。

## 5. CLIP 能做什么，哪些问题需要别的方法

它适合用共享特征进行图文检索、候选匹配，或作为后续系统的视觉表示来源。原始 CLIP 接口并不逐 token 写出解释，也不直接输出检测框或米制位姿。

开放词汇检测可以结合视觉语言表示与定位训练，返回文字指定对象的区域；这与只有整图匹配的双编码器不同。若要回答“左边的杯子是什么颜色”，还需要适合关系理解与回答生成的模型，并评估它是否利用了对应图像区域。

## 6. 候选变化与局部关系：排名正确还缺什么

沿用 u 与相似度 `[1,0.96,−1]`，τ=0.1，固定视觉特征，只改候选集合。

| 候选配置（教学） | 第一个“红杯”候选的 softmax | 改变了什么 |
| --- | ---: | --- |
| 红杯、蓝杯、猫 | 约 0.598688 | 原三候选分布 |
| 红杯、猫 | 约 0.999999998 | 删除最相似的竞争候选 |
| 红杯、另一个红杯描述、蓝杯、猫；两条红杯描述向量相同 | 约 0.374487 | 相同语义由两个候选分享概率 |

**结果（静态计算）：** 图像完全未变，单个候选概率已明显变化；数值变高不能直接解释为视觉识别变得更准确。重复描述的设定只为演示分母效应，真实同义句未必得到相同向量。若汇总同类别候选，还需定义候选组织与归一化方式，并独立评估。

匹配训练里的负例组织、温度和表示质量回查 [15](../15_representation_learning/README.md)，概率校准回查 [09](../09_probability_uncertainty/README.md)。增加“没有杯子”文字候选提供了可选标签，但本身不会保证未知对象被可靠拒绝。

整图表示若重点保留“红杯与蓝杯都存在”，可能没有充分保留左右关系；单看整图相似度无法证明“左边红杯”被定位。可以按任务读取区域特征或采用有定位训练的模型，再按 [12](../12_detection_segmentation/README.md)评价框/掩码。裁剪区域后再匹配也需要知道裁剪位置，并检查杯子有没有被截断；原始 CLIP 的整图接口不会自动产生这些区域。
