## 原有详细笔记

本项目使用泰坦尼克号乘客数据预测乘客是否生存（`Survived`）。重点不是追求最高准确率，而是把缺失值处理、类别编码、数值标准化和模型训练封装进一个可复现、无数据泄漏的 `Pipeline`。

## 为什么本项目使用逻辑回归，而不是线性回归？

`Survived` 的原始取值只有 `0`（未生存）和 `1`（生存），因此这是一个**二分类**问题。我们关心的并不是一个任意连续数值，而是某位乘客生存的条件概率：

```text
P(Survived = 1 | Pclass, Sex, Age, SibSp, Parch, Fare, Embarked)
```

| 模型 | 适用任务 | 直接输出 | 这个项目是否适合 |
| --- | --- | --- | --- |
| 线性回归 `LinearRegression` | 预测连续数值，例如房价 | 任意实数 | 不适合当作第一版分类模型 |
| 逻辑回归 `LogisticRegression` | 预测类别及其概率 | 0 到 1 之间的类别概率 | 适合 |

线性回归直接计算特征的加权和：

```text
ŷ = b + w₁x₁ + w₂x₂ + … + wₚxₚ
```

这个结果没有上下界。若把它解释为生存概率，可能会得到 `-0.18` 或 `1.27`，两者都不是合法概率。直接用线性回归拟合 0/1 标签有时被称为“线性概率模型”，但它会出现概率越界，而且其均方误差目标并不最适合二分类事件。

逻辑回归也会先计算一个线性分数：

```text
z = b + w₁x₁ + w₂x₂ + … + wₚxₚ
```

但它再通过 sigmoid 函数转成概率：

```text
P(Survived = 1) = 1 / (1 + e^(-z))
```

无论 `z` 多大或多小，输出总在 `(0, 1)` 内：

| 线性分数 `z` | 生存概率 |
| ---: | ---: |
| -3 | 约 0.05 |
| 0 | 0.50 |
| 3 | 约 0.95 |

这个把任意实数压缩到 0 和 1 之间的函数叫 **sigmoid 函数**，记为 `σ`：

```text
σ(z) = 1 / (1 + e^(-z))
```

它的直觉是：线性分数很小时，概率逐渐接近 0；`z = 0` 时概率为 0.5；线性分数很大时，概率逐渐接近 1。两端会逐渐变平，因此不会产生 `-0.18` 或 `1.27` 这样的非法概率。

训练完成后，可用阈值将概率变成类别。例如阈值为 `0.5` 时，预测概率不低于 `0.5` 就预测“生存”，否则预测“未生存”。阈值并非不可改变：如果更重视尽量找出生存者，可以降低阈值，但需要同时观察精确率、召回率和 F1 的变化。

线性回归和逻辑回归的关系可以概括为：

```text
线性回归：特征 → 线性分数 z → 直接作为连续预测值
逻辑回归：特征 → 线性分数 z → sigmoid → 类别概率
```

因此，逻辑回归不是线性回归的“高级版本”。两者恰好共享“特征加权求和”这一步，但分别为不同的问题设计：

| 内容 | 线性回归 | 逻辑回归 |
| --- | --- | --- |
| 预测目标 | 连续数值，例如房价 | 0/1 事件的概率，例如生存概率 |
| 最终输出 | 任意实数 | 0 到 1 之间的概率 |
| 训练时关注 | 预测数值与真实值的平方误差 | 预测概率与实际 0/1 结果是否匹配 |
| 合适场景 | “房价是多少？” | “乘客会不会生存？” |

线性回归并不低级；它预测房价这类连续目标时很合适。逻辑回归多出的 sigmoid 步骤和适合概率的训练目标，使它更适合本项目的二分类任务。“逻辑回归”中的“回归”指它会学习特征与**对数几率**之间的线性关系，不代表它是和房价预测相同的连续数值回归。本周会使用 `LogisticRegression` 作为第一个真正利用七个特征的模型，并与均值基线、KNN、决策树比较。

### 逻辑回归在本项目中做什么？

逻辑回归会为每个预处理后的特征学习一个权重。例如，独热编码后的 `Sex_female`、`Pclass_1`、`Embarked_S` 都会成为单独的 0/1 特征；`Age`、`Fare` 等数值特征则会先标准化。模型将这些特征乘以各自权重、相加，再转换成生存概率。

权重的正负可以帮助理解模型倾向：某个特征的权重为正，表示在其他输入不变时，该特征出现或增大通常会提高预测生存概率；为负则相反。但权重的大小会受标准化方式、特征之间相关性和类别参考列影响，不能孤立地把它当成因果结论。

逻辑回归的优点是速度快、结果相对容易解释，并且天然输出概率；局限是它主要表达特征的线性加和效果。例如，“女性且一等舱”这种特征组合若有额外影响，第一版逻辑回归不会自动专门学习这一交互关系，除非我们显式增加交互特征。

### 决策树在本项目中做什么？

决策树不是计算所有特征的加权和，而是不断提出“如果……那么……”的问题，把乘客分到更相似的小组。例如一棵简化的树可能是：

```text
Sex 是 female 吗？
├── 是：Fare 是否大于某个阈值？
│   ├── 是：预测生存概率较高
│   └── 否：预测生存概率中等
└── 否：Pclass 是否为 1？
    ├── 是：预测生存概率中等
    └── 否：预测生存概率较低
```

真实模型会根据训练数据自动选择提问的特征与阈值，而不是使用上面的固定规则。每一个叶节点会根据落入该节点的训练样本中生存者的比例，给出类别或生存概率。

| 特点 | 逻辑回归 | 决策树 |
| --- | --- | --- |
| 学习方式 | 特征加权求和，再转为概率 | 连续的条件分支与切分 |
| 能否自然表达非线性／特征组合 | 较弱，通常需手工加入特征 | 较强，可自动学习条件组合 |
| 是否需要数值标准化 | 通常需要，尤其与 KNN 同用 Pipeline 时 | 通常不需要；阈值切分不受尺度影响 |
| 主要风险 | 欠拟合复杂关系 | 树过深时容易记住训练数据，即过拟合 |

在 scikit-learn 中，决策树仍不能直接读取 `Sex`、`Embarked` 这类文本，所以类别特征依然要先填补 `Missing` 并独热编码。为使三个候选模型使用同样的数据规则，本项目的决策树也沿用“数值中位数填补 → 标准化”和“类别填补 → 独热编码”的 Pipeline；标准化对树通常没有必要，但不会改变树按数值大小切分的能力。

当前决策树使用默认配置，允许树持续切分直到停止条件满足，因此更需要通过交叉验证检查它是否过拟合。后续可只改变一个参数进行实验，例如限制 `max_depth`（树最大深度）或增大 `min_samples_leaf`（叶节点最少样本数），并与当前基线比较。

## 第一版：均值（先验概率）基线

先运行固定的分层切分和均值基线：

```bash
# 如需运行，先激活自行准备的 Python 环境
cd 03_preprocessing_pipeline
python src/split_titanic.py --random-state 42 --test-size 0.2
python src/train_mean_baseline.py
python src/train_models.py --cv-folds 5
python src/evaluate_model.py
```

二元标签 `Survived` 只有 0 和 1。因此训练集标签的平均值就是训练集中“生存”的比例：

```text
平均生存率 = (训练集中 Survived 的总和) / 训练集样本数
```

这个基线为每名乘客输出同一个生存概率，即训练集平均生存率；它不从 `Pclass`、`Sex`、`Age`、`SibSp`、`Parch`、`Fare`、`Embarked` 中学习任何规律。若要输出类别，则选择训练集中较多的那一类。本次划分中平均生存率为 0.383，小于 0.5，所以基线会将所有乘客预测为“未生存”。

脚本仍将七个特征经过同一条 Pipeline：数值列使用训练集的中位数填补并标准化，类别列使用 `Missing` 填补并独热编码。这样可验证后续模型所需的无泄漏预处理流程；但 `DummyClassifier(strategy="prior")` 会忽略转换后的特征，所以这些处理不会改变均值基线的预测。

本次基线在测试集的准确率为 0.615，却从未预测任何生存者，因此生存类别的精确率、召回率和 F1 都为 0。这说明仅看准确率会产生误导；后续逻辑回归、KNN 和决策树至少应在生存者的召回率和 F1 上有实质改善。

## 如何理解分类指标与交叉验证标准差？

本项目将 `Survived=1`（生存者）视为**正类**。比较模型时会出现四种结果：

| 名称 | 含义 |
| --- | --- |
| 真正例（TP） | 实际生存，模型也预测生存。 |
| 假正例（FP） | 实际未生存，模型误预测为生存。 |
| 假负例（FN） | 实际生存，模型误预测为未生存。 |
| 真负例（TN） | 实际未生存，模型也预测未生存。 |

分类模型的评估不只包括准确率、精确率、召回率和 F1；还常见混淆矩阵、ROC-AUC、PR-AUC、对数损失等。对本周这个入门二分类项目，前四项指标加上混淆矩阵已经构成足够的核心组合。并不存在对所有任务都最重要的单一指标：应根据哪一种错误的代价更高来选择重点指标。例如，若漏掉真实生存者的代价更高，应更重视召回率；若错误地预测“会生存”会引发昂贵或危险的行动，应更重视精确率；当希望同时兼顾两者时，可重点比较 F1。

### 准确率、精确率、召回率与 F1

**准确率（accuracy）**是所有预测中正确的比例：

```text
accuracy = (TP + TN) / (TP + TN + FP + FN)
```

它回答“整体上猜对了多少”。但泰坦尼克号中未生存者更多；如果模型把每个人都预测为未生存，仍能有约 61.5% 的准确率，却一个生存者也没有找出。因此不能只看准确率。

**精确率（precision，也常被称为精准率）**关注“预测为生存”的结果是否可信：

```text
precision = TP / (TP + FP)
```

例如精确率为 0.80，表示模型说“会生存”的 100 人中，约 80 人确实生存。精确率低意味着假正例多。

**召回率（recall）**关注实际生存者被找回了多少：

```text
recall = TP / (TP + FN)
```

例如召回率为 0.70，表示全部实际生存者中，模型正确识别出约 70%；剩余约 30% 被错判为未生存。召回率低意味着假负例多。

**F1 分数**将精确率和召回率合并为一个数：

```text
F1 = 2 × precision × recall / (precision + recall)
```

它是两者的调和平均数：只要精确率或召回率有一个很低，F1 就会被明显拉低。均值基线从未预测生存者，精确率、召回率和 F1 都为 0；这正说明它的 0.615 准确率并不能代表它适合任务。本项目以生存类 F1 作为挑选候选模型的主要依据，同时也检查召回率与准确率。

### `平均值 ± 标准差` 表示什么？

交叉验证会产生 5 次独立的临时验证分数。例如逻辑回归的 F1 写为：

```text
0.730 ± 0.024
```

前面的 `0.730` 是五折 F1 的平均值；后面的 `0.024` 是这五个 F1 分数的**样本标准差**。标准差衡量五次分数围绕平均值的波动大小，并不是“模型必然会错 2.4%”，也不是最高分与最低分的差。

- 标准差较小：不同训练／验证划分下成绩接近，模型表现较稳定。
- 标准差较大：成绩会随数据划分明显波动；可能是样本较少、模型对数据敏感，或某些样本影响很大。

因此，比较模型时先看平均 F1 是否更高，再结合标准差判断这项优势是否稳定。当前逻辑回归的 F1 为 `0.730 ± 0.024`，KNN 为 `0.718 ± 0.018`：逻辑回归平均表现较好，而两者的波动都不大。

## 在训练集内部比较模型

`src/train_models.py` 会在 712 条训练数据上使用 5 折分层交叉验证。每一轮中，填补器、标准化器、独热编码器和分类器都只从该轮的训练部分学习；临时验证部分只用于评分。因此，不会把 179 条测试集用于选模型，也不会让验证折的数据泄漏进预处理规则。

三条候选 Pipeline 唯一变化的是最后的分类器：

- `LogisticRegression(max_iter=1000)`；
- `KNeighborsClassifier(n_neighbors=5)`；
- `DecisionTreeClassifier(random_state=42)`。

脚本输出每个模型的交叉验证平均准确率、精确率、召回率、F1 及标准差，保存为：

- `outputs/tables/cross_validation_results.csv`；
- `outputs/tables/model_selection.json`；
- `outputs/figures/cross_validation_comparison.png`；
- `outputs/models/best_cross_validated_pipeline.joblib`。

选择规则为：先比较生存者（`Survived=1`）的平均 F1；若相同，再比较召回率、准确率。不要根据测试集分数来反复更改模型；确定方案后才对测试集进行一次最终评估。
