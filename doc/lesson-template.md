# 学习笔记样板：快速复习优先

本文行数：81行，预期阅读时长：3分钟

**默认采用“速记要点 → 具体例子 → 结果与解释 → 按需查阅”。** 读者不用执行代码，也能找回知识印象。只有静态例子难以说明的动态现象才增加可选实验。

简短样例见 [S0 单元 01](../src/foundations/engineering/01_shell_paths/README.md)、[单元 02](../src/foundations/engineering/02_git/README.md)；机器人专题可参考 [Lesson 1](../src/lesson1/ros2_interfaces_notes.md)。目录归属见 [案例索引](../src/README.md)，先修关系见 [学习路线](learning-roadmap.md)。

## 1. 内容深度

- 工具基础：保留几条结论、一两个例子和排错速查，语法与常规实现可由 AI 协助。
- 机器人核心知识：按需要解释坐标系、单位、公式与约束，但每个知识点都应给出可直接理解的例子。
- 运行命令、环境与验证记录：作为实现参考，按需阅读；agent 的验证工作不变成读者的必做练习。

## 2. 可复制的正文样板

下面 `<...>` 为待替换内容，按主题删减，不要求填满所有章节。

````markdown
# <主题名称>

本文行数：<实际行数>行，预期阅读时长：<估算分钟数>分钟

**一句话回忆：<最重要的结论或它解决的问题>。**

## 速记

- <关键概念或规则>
- <容易混淆的区别>

## 例子：<一个具体场景>

**条件 / 输入：** <必要背景、数值或少量代码；机器人量写明单位和坐标系。>

**结果：** <直接给出输出、现象或示意图，不能只让读者自己运行查看。>

**解释：** <指出输入如何得到结果，以及为什么容易误解。>

结果依据：<说明是教学示意、源码推导，还是已实际验证。>

## 遇到问题时查

| 现象 | 原因或检查方向 |
| --- | --- |
| <问题> | <解释或定位入口> |

## 需要深入时

<原理笔记、对应代码、具体版本的官方资料链接。>
````

## 3. 什么时候才需要实验

当读者的疑问依赖实际变化，例子难以充分表达时，再补实验，例如控制器在不同增益下的振荡、线程调度导致的延迟、噪声与滤波的权衡。

可选实验应说明：要观察的疑问、运行前提、最少操作、预期现象和解释。已有真实曲线或日志时优先直接展示；尚未运行的预期不能写成实测结果。

不要把安装环境、运行所有脚本、填写记录表或完成自查题作为阅读笔记的前提。

## 4. 文件如何组织

- `README.md`：速记与例子，默认阅读入口。
- `notes.md` 或专题笔记：必要原理、排错与资料，内容较多时才拆分。
- 代码、配置和验证记录：供需要实现或复现时查阅，不要求读者逐个执行。

一个知识点保留一份主要解释，通过相对链接复用。已有个人困惑和失败结论可保留，不替用户编造学习经历。

## 5. 写完后检查

- 标题下方是否包含行数和预期阅读时长，并在修改后刷新？
- 不运行代码，是否也能看懂例子的结果和原因？
- 工具细节是否可以移到按需速查？
- 数值是否注明单位、维度、坐标系与成立条件？
- 示例、推导、实测与未验证内容是否分清？
- 链接是否有效，代码和解释是否对应？

实际修改代码时，仍由 agent 完成与改动相称的验证。是否需要验证实现，与读者是否需要做实验是两件事。

行数按 Markdown 文件的实际行数统计，包含空行、代码和说明行本身。阅读时长按中文字符每分钟 400 字、英文及数字词每分钟 200 词粗估，向上取整且至少 1 分钟；忽略链接地址，不包含动手实践时间，也不代表深入掌握所需时间。

从仓库根目录运行 `python3 scripts/update_doc_metadata.py`，自动刷新根目录、`doc/` 和 `src/` 下的文档（跳过隐藏目录和构建产物）。使用 `python3 scripts/update_doc_metadata.py --check` 可检查统计是否过期。脚本见 [文档统计工具](../scripts/update_doc_metadata.py)。
